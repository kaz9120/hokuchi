# 登壇資料を、理解される順に組み立てる

このスキルは、登壇資料を対話から実装まで一続きで作るためのものです。完成の姿は、話者と合意した `talks/<YYYY_MM_DD_タグ_演題>/storyboard.md` (絵コンテ) と、`check` を通したシーンの実装 (`talk.tsx` と `scenes/`) です。書き手は Claude で、話すのも決めるのも話者です。

土台は Nancy Duarte『slide:ology』です。ページ番号はすべて同書のものです。その上に、聞きに来たくなる・人に勧めたくなるための型 (`references/story.md`) を重ねます。

## 段ごとに、その段のファイルだけを開く

手順は段ごとのファイルに分けてあります。いまの段のファイルだけを開き、ほかの段のファイルは開きません。1 つの段で読む規則を少なくするほど、出てくるものの質が上がります。とくにスライドの段は、規則を読むほど画面が規則の挿絵になります (原則 5)。

| 段 | Phase | ファイル | 成果物 | 関門 |
|---|---|---|---|---|
| 伝えること | 0〜2 前提と素材・聴衆・中核メッセージ | `steps/core.md` | | 承認 |
| 構成 | 3 メッセージマップ | `steps/outline.md` | | 承認 |
| 絵コンテ | 4〜6 完全版を書き、聴衆役に読ませ、持ち時間に合わせて削る | `steps/storyboard.md` | storyboard.md | 承認 |
| スライド | 7 画面を作り、撮って目で見て直す | `steps/slides.md` | talk.tsx・scenes/ | 話者が見た目を認める |
| 直し | 8 話者のフィードバックで直す。認めた見た目を守る | `steps/fix.md` | | |
| 発表後 | 公開・収穫 | `steps/after.md` | | |

話者が構成そのものに触れるフィードバックを返したら、構成の段に戻って合意し直してから書き換えます。シーンの実装は手間がかかるので、構成と言葉は絵コンテの段の削った版まで、絵コンテの上で固めます。

studio (`apps/studio`) の中では、studio が段とファイルを渡します。渡された段のファイルに従います。

## 5 つの原則

1. 理解が先です。芯にするのは、聴衆に理解してほしいこと (中核メッセージ) です。締めは、話全体を総括するまとめにします。本は成功を「新たな見識を得た・行動を起こそうと思った・態度を改めようと思った」のどれかとしていて (p.269)、感動は疑問が解けて腑に落ちた瞬間に生まれると書いています (p.277)。行動は、理解した聴衆が自分で選ぶものです。画面で押しつけません
2. 完全版から削ります。持ち時間は絵コンテの段の最後 (Phase 6) で扱います。時間から先にシーンの数を決めると、削る元がないまま薄い中身を埋めることになります。本の Reduce も、全文から段階を踏んで削ります (p.241, p.243)
3. 文脈を持たない目で読みます。Claude も話者も、題材の文脈を持ちすぎています。「自分の頭では明快でも、他人には分かりにくい」(p.54) ので、話者に見せる前に、文脈を渡さない読み手に読ませて直します
4. 素材と判断は話者から受け取ります。共有される技術トークの強い部分は、どれも話者しか持っていない実物 (再現した対話、日付つきの事例、自分の失敗、選んだ理由) でした。AI っぽさは、判断と素材を AI に任せたときに出ます。実物と、話者がそれを選んだ理由が手元に無いシーンは、画面の言葉を書く前に話者に聞きます
5. 画面は、規則ではなく目で作ります。座標・見出しの位置・文字の大きさ・強調色の数を型で決めると、どの画面も「左上の見出しと下の図」の資料になり、話者は「えも言えぬダサさ」と評しました。2026-11 の将棋の発表で、同じ構成と言葉のまま、型を当てずに「かっこよく作り、撮って自分で見て直す」とだけ頼んだ版は、話者が「100 人いたら 100 人こっちがいいと言う」と評しました。絵コンテには画面の作り方を書かず、スライドの段で、撮っては見て直します。テーマが決めること (MOSH のテンプレート) は、この自由の外です
