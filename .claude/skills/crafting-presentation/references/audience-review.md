# 聴衆役に読ませる

Phase 5 で開きます。本は「自分の頭の中では単純明快なアイデアでも、他人にとっては複雑で分かりにくいことはよくあります」と書いています。そのうえで、1〜2 人の同僚に見せて「ポイントを押さえたものかどうか、評価してもらう」よう勧めています (p.54-55)。Claude と話者は、題材の文脈を持ちすぎています。そこで、文脈を持たないサブエージェントに聴衆役を任せます。

## 渡すものと、渡さないもの

渡すのは次の 2 つだけです。

- 聴衆のプロフィール (絵コンテ冒頭の `聴衆:` などと、Phase 1 で描いた人物像)
- 絵コンテの画面と話すこと。シーンと状態の順に、状態の 1 行目 (画面) と `> ` の行 (話すこと) だけを並べたもの。写真は、絵コンテに書いた仕様で代える

渡さないものは次のとおりです。この会話の経緯・話者から聞いた背景・社内ドキュメント・メッセージマップ・中核メッセージ・シーンの `伝えること:` と `見せ方:` です。聴衆は、スライドと話だけから中核メッセージを受け取ります。受け取れたかを確かめるため、中核メッセージは渡しません。

絵コンテから書き出したテキストを渡します。storyboard.md のファイルパスは渡しません。周りのファイルから文脈を拾ってしまうためです。

## 起動のしかた

Agent ツールで、会話の文脈を引き継がない新しいサブエージェントを起動します (fork は使いません)。判断を要するレビューなので、モデルは opus を指定します。依頼文は次のとおりです。`{...}` を埋めて使います。

```
あなたは、次のプロフィールの人物として、ある登壇を聞きに来ています。

{聴衆のプロフィール}

これから、その登壇の画面と、話者が話す内容を順に渡します。画面は、場面ごとに状態が切り替わっていきます。
あなたはこの題材について、プロフィールに書いてある以上のことを知りません。
知らないことを推測で補わず、分からないところは分からないと答えてください。

{絵コンテ: 場面と状態ごとに「番号 / 画面 / 話すこと」}

次の 4 つに答えてください。

1. 各場面について、その場面が言っていることを 1 行で書いてください。
   言っていることが分からない場面は「不明」と書き、なぜ分からないかを添えてください。
2. 初めて出てきて意味が分からなかった言葉を、場面の番号つきで挙げてください。
3. 前の場面から話が飛んだと感じたところ (唐突な転換) を挙げてください。
   何が足りないと感じたかも書いてください。
4. 聞き終えて、この登壇がいちばん伝えたかったことは何だと思ったかを、1 文で書いてください。
   あわせて、来た甲斐があったと思えたか、思えなかったならなぜかを書いてください。

画面の文字は 3 秒ほどしか見られないものとして読んでください。
話す内容は、話者の話として聞いたものとして扱ってください。
```

## 返ってきた指摘の扱い

- 質問 4 の答えを、中核メッセージ (絵コンテの `中核メッセージ:`) と比べます。ずれていたら、構成 (Phase 3) か本題の章に問題があります。スライドの言葉を直す前に、どこでずれたかを探してください
- 質問 1 で「不明」になったシーンは、`伝えること:` が 1 行で言えていないか、前提が足りていません。`slide-design.md` の 1 に戻ります
- 質問 2 と 3 は、前提・用語の置き場所の問題です。メッセージマップの「新しく出す用語」の列と照らして直します
- 指摘は 1 件ずつ判断します。直さない指摘には、直さない理由を書き残します。聴衆役の読み違いに見えても、同じ読み違いを本物の聴衆もしうるので、すぐには退けないでください

話者に見せるときは、聴衆役の指摘、直した内容、直さなかった理由を一緒に渡します。直したあとにもう一度聴衆役に読ませるかは、直した量で決めます。本題の章を組み替えたなら、もう一度読ませてください。

実装のあとで見せ方を大きく変えたときは、`check` の静止画 (`out/states/`) を画面の代わりに渡して読ませることもできます。
