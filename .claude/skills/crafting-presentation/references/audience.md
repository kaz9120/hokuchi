# 聴衆を描く

Phase 1 で開きます。聴衆像は、以降のすべての判断の基準になります。本は「聴衆に思いを馳せれば、自ずと彼らのニーズを優先するようになり、どういった基準でメッセージをチェックすればよいかが分かってきます」と書いています (p.34)。聴衆像は、書いて終わりの設計メタデータではありません。スライドを 1 枚足すか削るかを決めるたびに、この人に要るかを問うための道具です。

## 集団ではなく、名前のある 1 人として描く

本は、聴衆を個人レベルで理解するよう求めています。典型的な聴衆の画像を探して名前を付け、7 つの問いに答えます (p.35-36)。聴衆層が分かれるなら、層ごとに 1 人ずつ描きます (p.36)。

「AI の活用に悩むエンジニア」のような 1 行は、集団の説明です。この形だと、その人が何を知っていて何を知らないかが決まりません。前提をどこまで説明するかも決まらないので、「ハイコンテキスト」「唐突」の原因になります。

描いた人物は、会話の中で話者に見せて確かめます。`deck.audience.who` には、名前を含めずに人物像を書いてかまいません。

## 7 つの問い

本の 7 問 (p.35) の前提は 1 つです。「聴衆は『あなた』を見にくるのではなく、『あなたがどんなメリットをもたらしてくれるのか』を確かめにくる」。核心は第 1〜4 問です。第 5〜7 問は必要に応じて聞きます。

尋問のように順番に聞かないでください。Phase 0 で読んだ素材と話者の最初の説明から埋まるものは埋め、埋まらない核心だけを対話で聞きます。

### 1. どんな人か (核心)

役割、技術レベル、関心を、個人として描きます。言い換え例:「今回、目の前に座っているのはどんな人ですか。1 人思い浮かべると誰になりますか」

落とす先: `audience.who`

### 2. 何を得に来たか・なぜここにいるか (核心)

本の問いは「このプレゼンから何を得ようとしているのか」「話を聞きにきた理由は」です。イベントのテーマや募集文が、この問いの手がかりになります。この答えから、聴衆がすでに持っている前提と、まだ持っていない前提が分かります。前提をどこまで画面で説明するかは、ここで決まります。

言い換え例:「その人は、このイベントに何を持って帰りたくて来ていますか。どこまでは知っていて、どこからは知らない人ですか」

落とす先: `audience.why`

### 3. 何に悩んでいるか (核心)

聴衆の悩みに共感を示し、解決策を示すための問いです (p.35)。構成では、ここが課題の章になります。

言い換え例:「その人がいま困っていること、モヤモヤしていることは何ですか」

落とす先: `audience.pains`

### 4. 聞き終えて何が得られるか (核心)

本は「自分にとってどんなメリットがあるのか」を伝えない限り聴衆は動かない、と書いています (p.34)。第 5 問 (行動) より先に、この問いを埋めます。

言い換え例:「聞き終わったとき、その人は何が分かっていて、何が楽になっていますか」

落とす先: `audience.gains`

### 5. 何をしてほしいか (任意)

本は行動への呼びかけを大切にしています (p.34)。ただし、メリットを伝えることとセットで初めて効くという条件付きです。話者によっては「良いと思ったアクションは勝手に取ってくれる」と考え、行動を促しません。その場合は空欄でかまいません。中核メッセージ (Phase 2) とは別の問いとして扱ってください。この 2 つを 1 文に混ぜると、芯がぶれます (ADR-0024)。

落とす先: `audience.action` (任意)

### 6. どんな反発を受けるか (任意)

言い換え例:「その話を聞いて、『でも…』と言われそうな点はありますか」。想定される反論に先回りするスライドの材料になります。

落とす先: `audience.objections`

### 7. どんな形で受け取りたいか (任意)

会場の大きさ、スクリーンの見え方、資料の配布と公開の有無です。Phase 0 の前提と重なるので、そこで埋まっていれば聞き直しません。

## 話者と題材に向ける問い

事例を持つ登壇では、題材の芯を話者から聞かないと構成が定まりません。同じ対話の中で、次の 3 つを聞いてください。

- その事例で、本当に届けたかったものは何か。作り手の都合 (工数が減った、設定が増えた) ではなく、届け先の体験を聞きます。ここが空だと、手段だけが並び「なぜそれを?」に答えられなくなります
- その話を、すでにどこかで書いたり話したりしたか。あれば Phase 0 に戻って読みます
- この発表の結論は、話者が普段から考えていることのどこにつながるか。締めの行き先が決まります

## 聴衆像から論点を導く

本の見本では、聴衆のプロフィールから「プレゼンのポイント」を 3 つ導いています (p.36)。描いた聴衆に対して、「この人なら、何が分かれば来た甲斐があったと思うか」を 3 点ほど書き出してください。これが Phase 3 のメッセージマップの柱の候補になります。

## deck.audience の書き方

```yaml
deck:
  message: "AI は新しい組織課題を作らない。これまで放置できていた課題を、放置できなくする"
  audience:
    who: "AI で開発は速くなったが、チームの成果につながっている実感が持てないチームリード"
    why: "AI 時代の強いチームの作り方について、他社が何を考えているかを知りたい"
    pains: "速度が上がるほど、レビューや合意形成が追いつかない"
    gains: "自チームの課題を、技術と組織のどちらの問題として扱うかを切り分けられる"
    # action と objections は任意
```

`audience` と `message` は描画されない設計メタデータです (SPEC §3)。本も、聴衆プロフィールをデッキの冒頭に入れ、スクリーンには映さない運用をしています (p.36-37)。
