# シーンを実装する

Phase 7 で開きます。合意した絵コンテを、`packages/stage` のシーンとして実装します。フレームワークの仕様は `packages/stage/docs/design.md` にあります。着手前に開いてください。

## 1. ファイルを用意する

```
talks/<YYYY_MM_DD_タグ_演題>/
  storyboard.md   絵コンテ (Phase 4〜6 の成果物。ノートの正本)
  talk.tsx        defineTalk。title / description / event / speaker / theme / public / scenes (date と URL はディレクトリ名から読む)
  scenes/<id>.tsx 1 ファイル 1 シーン。defineScene({ id, steps, Component })
  assets/         写真など
```

- テーマは登壇の立場で選びます。個人は `hokuchi`、MOSH としては `mosh` です。この 2 つ以外のテーマは作りません
- `public` は絵コンテの `公開:` と揃えます。社内向けは `public: false` にします。サイトには `public: true` のトークだけが載ります
- `description` は OGP と一覧に出ます。中核メッセージを、聴衆向けの 1〜2 文に言い直して書きます
- シーンの `id` と `steps` は、絵コンテのシーン id と状態の数に一致させます。ノートと名前は絵コンテから流し込まれるので、シーンには書きません

## 2. 座標と大きさの型

ステージは 1280×720 です。トーク全体で次の型を揃えます。崩すのは意図した 1 シーンだけです。

| 項目 | 値 |
|---|---|
| 左右の余白 | 96px |
| 見出し | `Headline` (左 96px・上 60px・44px・太字) |
| 本文の領域 | 上 170px 〜 下 650px |
| 本文の文字 | 28〜32px。補助のラベルは 20〜24px |
| 出典 | `.source` (左下・18px) |
| 最小の文字 | 18px。`check` が 18px 未満を指摘する |

色はテーマのトークン (`var(--accent)` など) で書きます。強調色は、1 つの状態で 1 か所に絞ります。状態で色を変えるときは `Morph` の `tone` を使います (Motion は CSS 変数の色を補間できないためです)。

## 3. 部品の選び方

| したいこと | 部品 |
|---|---|
| 見出しを状態ごとに差し替える | `<Headline>{['…', '…']}</Headline>` |
| 要素を、ある状態から出す・消す | `<Reveal at={n} until={m}>` |
| 要素を状態をまたいで動かす・大きさを変える | `<Morph box={[…]} tone={[…]}>` |
| 2 つの要素をつなぐ | `<Connect from="a" to="b" at={n} flow label="…">`。端点には `node="a"` を付ける |
| 数を数え上げる | `<CountUp values={[1, 43]} />` |
| 状態ごとの値を選ぶ | `pick(useStep(), [...])` |

部品で足りないときは、シーンの中で素の要素・SVG・Motion を書いてかまいません。2 本以上のトークで同じものを書いたら、部品への昇格を検討します (発表後の振り返りで扱います)。

状態遷移の崩れ (見出しの重なり・縮む箱の中の歪み・折り返しの飛び) は部品が吸収します。部品を通さずに書くときは、同じ崩れを踏んでいないかをコマ撮りで確かめてください。

## 4. 確かめるループ

実装したら、話者に見せる前に、次を自分で回します。

```sh
bun run typecheck                      # 型
bun run check <名前の先頭> --motion     # 静止画・検査・照合・コマ撮り
```

1. `out/check.md` を読みます。実行時のエラー、絵コンテとの食い違い、重なり・はみ出し・小さい文字は、すべて直します
2. `out/states/` の静止画を、1 枚ずつと、全体を並べた形の両方で見ます。線と文字の重なり、構図の釣り合い、見出しや本文の左端がシーンをまたいで揃っているかは、機械では拾えません
3. `out/motion/` のコマ撮りを見ます。動きが〔役割〕どおりの意味を語っているか、「付けてはいけない動き」(`element-guide.md` の 1) に当たらないかを確かめます。始まりのコマで、新旧の要素が重なって読めない瞬間がないかも見ます
4. 直したら 1 に戻ります

話者には、作業用サーバで見てもらいます。サーバは長く動くので、話者に別ターミナルで立ててもらいます。

```sh
bun run dev <名前の先頭>
```
