# シーンを実装する

スライドの段 (`steps/slides.md`) で開きます。合意した絵コンテを、`packages/stage` のシーンとして実装します。フレームワークの考え方は `packages/stage/README.md` に、部品の仕様はコード (`packages/stage/src/`) にあります。着手前に README を開いてください。

## 1. ファイルを用意する

```
talks/<YYYY_MM_DD_タグ_演題>/
  storyboard.md   絵コンテ (承認した削った版。ノートの正本)
  talk.tsx        defineTalk。title / description / event / speaker / theme / public / scenes (date と URL はディレクトリ名から読む)
  scenes/<id>.tsx 1 ファイル 1 シーン。defineScene({ id, steps, Component })
  assets/         写真など
```

- テーマは登壇の立場で選びます。個人は `hokuchi`、MOSH としては `mosh` です。この 2 つ以外のテーマは作りません
- `public` は絵コンテの `公開:` と揃えます。社内向けは `public: false` にします。サイトには `public: true` のトークだけが載ります
- `description` は OGP と一覧に出ます。中核メッセージを、聴衆向けの 1〜2 文に言い直して書きます
- シーンの `id` と `steps` は、絵コンテのシーン id と状態の数に一致させます。ノートと名前は絵コンテから流し込まれるので、シーンには書きません

## 2. 世界を world に、章の中身をシーンに置く

ステージは 1280×720 です。座標・見出しの位置・文字の大きさに、トークをまたぐ型はありません。トークごとに世界 (`steps/slides.md` の 1) を決め、そのトークの中で揃えます。

- シーンをまたいで育つ物と、テーマが許すときの背景は `talk.tsx` の `world` に置き、`cut: 'fade'` にします。`world` はシーンの下に 1 つだけ描かれ、シーンが変わっても組み立て直されません。いまの位置は `useWorld()` で読みます (`scene` がシーンの id、`step` がシーンの中の状態、`at` が通しの状態)。8 枠の列を 20 年の並びに育てる、章で背景の明るさを変える、といった動きは、`world` の中で `at` か `scene` を見て CSS の transition で書きます
- シーンには、章ごとの中身を置きます。シーンの id と状態の数は絵コンテと揃えます
- `hokuchi` のテーマの枠 (右下の話者名) が構図に合わなければ、`theme: { ...hokuchi, Frame: … }` で差し替えます。`mosh` の枠 (ロゴと ©) と背景は差し替えません。`Frame` は `at` と `total` を受け取るので、ページ番号を置けます
- 見た目は CSS で書いてかまいません。トークの中に CSS のファイルを置き、クラス名にはトークの接頭辞を付けます (`base.css` の `.card`・`.label`・`.chip`・`.tile`・`.bullet` とぶつけないため)。状態ごとに根のクラスや `on` を付け替え、CSS の transition で動かす書き方は、要素が状態をまたいで生き続けるので、この stage と相性が良いです。
- フォントは、テーマのもの以外を使うなら、CSS の `@import` で Google Fonts から読みます。`check` は読み込みを待ってから撮ります。公開用のビルドに同梱するフォントは `packages/stage/node/fonts.mjs` の一覧にあるものだけなので、足したら一覧も確かめます
- 静止画のモードでは、CSS の transition は止まり、最後の姿が撮られます。`@keyframes` の動き (カーソルの点滅など) は止まらないので、撮るたびに少し違います。認めた見た目と比べるときの誤検出になるので、点滅は小さく保ちます
- `mosh` では、色はテーマのトークンから取ります。`hokuchi` では、トークの中の値でもかまいません。強調色の数に決まりはありません。目で見て、主役が 1 つに見えるかで決めます

## 3. 部品の選び方

部品は出発点で、使う義務はありません。

| したいこと | 部品 |
|---|---|
| 要素を、ある状態から出す・消す | `<Reveal at={n} until={m}>` |
| 要素を状態をまたいで動かす・大きさを変える | `<Morph box={[…]} tone={[…]}>` |
| 2 つの要素をつなぐ | `<Connect from="a" to="b" at={n} flow label="…">`。端点には `node="a"` を付ける |
| 数を数え上げる | `<CountUp values={[1, 43]} />` |
| 状態ごとの値を選ぶ | `pick(useStep(), [...])` |
| 文字列の見出しを状態ごとに差し替える | `<Headline>{['…', '…']}</Headline>`。一部だけ色を変えたいときは使えないので、自分で書く |

`Reveal` は退場で要素を外すので、ぼかしながら抜けるような退場は書けません。そのときは CSS で書きます。Motion は CSS 変数の色を補間できないので、状態で色を変えるときは `Morph` の `tone` か、CSS の transition を使います。

シーンに入ったときの登場の動きは、`useActive()` が true になってから始めます。前後のシーンは先に組み立ててあり、入ってくるシーンは切り替えが終わってから true になります。文字や写真まで待たせると、切り替えの間に空の画面が流れるので、待たせるのは線を引く・物が動くといった振り付けだけにします。

動きが速い・遅いと感じたら、トークの `tempo` を変えます (1.2 で 2 割ゆっくり)。

## 4. 確かめるループ

実装したら、話者に見せる前に、次を自分で回します。

```sh
bun run typecheck                      # 型
bun run check <名前の先頭> --motion     # 静止画・検査・照合・コマ撮り
```

1. `out/check.md` を読みます。実行時のエラー、絵コンテとの食い違い、重なり・はみ出しは直します。「小さい文字」は目安で、主役が大きく、小さいのがラベルや脚注なら直しません。絵コンテの頭に「見た目: 話者が認めた」があるトークでは、「認めた見た目からの変化」を見ます (`steps/fix.md`)
2. `out/states/` の静止画を、1 枚ずつと、全体を並べた形の両方で見ます。かっこいいか、資料に見えないかは機械では拾えません。見る問いは `steps/slides.md` の 4 にあります
3. `out/motion/` のコマ撮りを見ます。動きが話の流れに合っているか、目が忙しくならないかを確かめます。始まりのコマで、新旧の要素が重なって読めない瞬間がないかも見ます
4. 直したら 1 に戻ります

話者には、studio の「通しで見る」か作業用サーバで見てもらいます。作業用サーバは長く動くので、話者に別ターミナルで立ててもらいます。

```sh
bun run dev <名前の先頭>
```
