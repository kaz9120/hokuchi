# 見せ方と動きの選び方

Phase 4 (絵コンテの「見せ方」と〔動きの役割〕) と Phase 7 (実装) で開きます。シーンは素の React で書くので、表現の上限はありません。そのぶん、何を選ぶかは書き手の判断になります。この文書は、伝えたいことの形から、見せ方と動きを選ぶための判断ガイドです。

要素の形は、それ自体が関係を語ります。本は、要素の位置関係が「敵対／支援」「秩序／混乱」のような意味を帯びると書いています (p.124)。動きも同じです。どちらから現れ、どこへ動き、どの大きさになるかが意味を持ちます。選ぶときは、言いたい関係と、形・動きが一致しているかを確かめてください。

## 0. 判断の入口

| 伝えたいこと | 見せ方 | 状態の運び方の例 |
|---|---|---|
| 自分の主張を 1 文で | 大きな文 1 つ | 前提や問いを先に見せ、次の状態で主張に差し替える |
| 数字 1 つ | 大きな数 | 基準 → 数が数え上がる → 意味の 1 文 |
| 数値の意味 (比較・変化・割合) | グラフ | 基準や比較対象を先に置き、主役の系列を最後に伸ばす |
| 要素どうしの影響・流れ | 図 | 中心人物を先に置き、関係を 1 本ずつ引く |
| 2 つの立場・状態の対比 | 左右の比較 | 並べる → 推す側に寄る (ズームイン) |
| 分類・仕分け | カード | 1 列に並べる → 基準を示す → 移動して仕分ける |
| 複数の対象を複数の属性で読み比べる | 表 | 行を順に出すか、注目する行を強調する |
| 実物 (画面・写真・記事) | 画像 | 全体 → 見る場所を拡大 → 意味 |
| コード・端末・diff | コード | 全体 → 注目行の強調 |
| 他者の言葉が根拠になる | 引用 | 出典を添えて 1 度だけ |
| 並列な短い項目 | 箇条書き | 話す順に 1 つずつ。済んだ項目は薄くする |

主役は 1 つのシーンに 1 つです。2 つ要るなら、シーンを分けます。

## 1. 動きの 5 つの役割

本は、アニメーションを装飾ではなくコミュニケーション手段とし (p.200)、果たす役割で 5 つに分けています (p.205)。絵コンテの〔 〕には、このどれかを書きます。どれにも当たらない動きは付けません。

| 役割 | 何を伝えるか | 例 |
|---|---|---|
| 関係性の変化 | 距離・順序・比較・影響・対立・分裂と統合 | カードを仕分ける、2 つを近づける、線でつなぐ |
| 画面の演出 | 登場と退場・ズーム・新しい視点・パン・隠す／暴く | 推す側へ寄る、シーンをまたいで横にパンする |
| オブジェクトの変化 | 変形・拡大と縮小・簡略化と複雑化 | 棒が伸びる、カードが強調色になる |
| 連続性 | 場面転換・成長と衰退・作業手順・流れ | 線の上を粒が流れる、手順が順に進む |
| 強調 | 視線の誘導・コントラスト・前面と背面・ハイライト | 見出しを問いに差し替える、1 つだけ色を変える |

### 動きと意味の対応

本は、動きの組み合わせが関係を語ることを、円と矢印だけで示しています (p.208)。

| 動き | 意味 |
|---|---|
| 2 つが近づいて重なる | つながる・交わる・融合する |
| 近づいて押しつぶれる | 衝突する・争う・圧力をかける |
| 回転して入れ替わる | 変化する・入れ替わる・整列する |
| 大きいものが小さいものを包む | 支配する・管理する |
| 片方が大きくなる | 上回る・広がる・勝る |
| 横を通り過ぎる | 通過する・前進する |

### 動きの向き

向きは好みで決めません (p.207)。

- 左から右は自然で、右から左は違和感がある。前に進む話は左から右へ動かす
- 下降は容易で、上昇は困難に見える。成長や挑戦を語るときは、上昇の抵抗がそのまま説得材料になる
- 右下から左上への上昇は、いちばん抵抗が大きい。不用意に使わない

### 付けてはいけない動き

本の 8 項目です (p.220)。実装のあと、遷移のコマ撮り (`check --motion`) を見て当てはまらないかを確かめます。

1. 不自然で違和感がある
2. テンポがめまぐるしく、延々と続く
3. コンテンツに付加価値を与えていない
4. 動きに気を取られ、話者に注意が向かない
5. 機能があるという理由だけで使っている
6. 使いすぎで論点がぼやけている
7. 動きのスタイルがコンテンツの雰囲気に合わない
8. いきなり始まって、聴衆が面食らう

落ちてきて跳ねる、回転しながら現れる、のような動きは使いません (p.208)。1 つの状態で動く役割は、原則 1 つにします。

## 2. 文と引用

自分の主張は、自分の言葉で 1 点を大きく見せます。本は「ワンフレーズで要点を伝えてみましょう。たいていの場合、それ以外には何もいらないはずです」と書いています (p.166)。

- 前提や問いを先に読ませたいときは、先の状態で見せ、次の状態で主張に差し替えます (`Headline`)。前提を小さな補足として主張の下に置かないでください (`slide-design.md` の 2)
- 強調は 1 か所に絞ります。差をつけすぎると、どれが重要かが伝わらなくなります (p.115)

引用は、「誰がそう言ったか」が主張の根拠になるときだけ使います。

- 自分の主張を引用の体裁に入れないでください
- 社内文書の言葉を、引用の体裁で飾らないでください
- 原文を確かめて正確に引き、出典 (資料名・ページ・年) を添えます。要約を引用符で囲みません
- 1 本のトークで引用が 2 つを超えたら、使いすぎを疑います

## 3. 画像 — 最適な実物を先に考える

ストーリーを語るのに最適な写真は、多くの場合ストックフォトには存在しません。先に「どんな写真が最も効果的か」を考え、自分で撮るか探し出します (p.182)。

- 当時の画面・現場の写真・実際の記事のような実物は、本題の章の中心になります。話者に「いちばん見せたい実物は何か、どこを見てほしいか」を聞いてください
- 「全体 → 見てほしい部分を拡大 → 意味」と、状態で運べます。拡大は画面の演出です
- 現実に存在しない演出写真は使いません (p.180)。トーク内の写真は様式を揃えます (p.180, p.192)
- 写真がまだ無い段階では、絵コンテに「調達すべき写真の仕様」を書き、実装では仮の枠を置きます
- コード・SNS の投稿・記事のカードは、画像に焼かずに HTML で組めないかを先に考えます。テーマに追従し、文字も選べます

## 4. 図 — 関係の型を選び、中心を決めて磨く

図は関係を説明する道具です。本の定義は「全体を構成する各要素がどのように影響し合っているかを説明するのに便利」です (p.64)。項目が並んでいるだけなら、図にしません。

### 型を選ぶ

関係の性質を言葉にし、次のどれに当たるかで選びます (p.66-77)。

| 関係 | 型 |
|---|---|
| 明確な始点と終点がある | 流れ (直線) |
| 閉じたループで、終わりがない | 循環 |
| 途中で分岐する・合流する | 分岐・合流 |
| 日付が意味を持つ経緯 | タイムライン |
| 2 軸の分類 | マトリクス |
| 上下の階層 | ツリー |
| 下から積み重なる | 積層 |
| 利害や責任を共有している | 重なり (ベン図) |
| 部分が集まって全体になる | 集合 |
| 中心から放射する | 放射 |

循環を選ぶ前に、本当に終わりがないかを確かめます。1 チームの改善が組織を通って他のチームへ広がる、のように始点と行き先があるなら、それは流れです。デモの cycle シーンは、三角形のサイクル図をやめ、この流れで描き直しています。

### 中心を決めて磨く

型を選んだだけでは「一応の合格点」です (p.80)。

- この関係の中心にいるのは誰か (チーム、ユーザー、組織など) を決め、その人が図のどこにいるかを明確にします
- 箱のラベルが動詞句なら、主語を決めます。「仕組みにする」なら、誰が仕組みにするのかを書きます
- 矢印が何の力で動くのかを、線のラベルかノートで説明できるようにします
- 複雑な図は、状態で 1 本ずつ組み立てます (p.78)。関係を引く順が、話す順です

## 5. グラフと数字 — データではなく、データの意味

本の中心命題は「データスライドが伝えるべきは、データそのものではなく、データの意味です」です (p.84)。

1. このデータで、聴衆に何を持って帰ってほしいか。多くの場合、因果になります (p.88)。この答えを、最後の状態の 1 文にします
2. 一見した要点と、本当に言いたい要点は同じか。違うなら、本当の要点を注記で指します (p.88)
3. 注意をどこに引きつけるか。主役の系列だけを強調色にし、ほかは薄くします (p.95, p.97)
4. 比較の基準を先に見せます。基準のない数字は、大きいのか小さいのかが分かりません。デモの deploys シーンは、人数 3.5 倍を先に伸ばしてから、デプロイ数 43 倍を伸ばしています

言いたいことが数字 1 つなら、グラフを使わず大きく見せます (p.90)。単位の違う指標を 1 つのグラフに混ぜないでください。聴衆がエンジニアなら、出典を示します (p.86)。

## 6. 表と比較

表は、複数の対象を複数の属性で読み比べてほしいときだけ使います (p.68)。区分が 2 つだけなら、左右の比較にします。表の 1 行だけが本題なら、その 1 行を主張として大きく出します。

左右の比較では、側ごとに定義を地の文で書き、具体例を並べます。ラベルには、分けた結果ではなく分けた基準を書きます。どちらかを推すなら、推す側に寄る (ズームイン) 動きで示せます。

## 7. 箇条書き — 見出しとして書く

箇条書きは禁止ではありません。本は「箇条書きは単なる見出し」で、本文は話し手が肉付けするものだとしています (p.170-171)。項目数の上限ルールは退けています (p.170)。

- 項目は新聞の見出しのように短く書きます。読点が要る長さなら、見出しになっていません
- 項目間で言い回しを揃えます (p.171)
- 時系列や因果のように並列でない項目は、箇条書きにせず図にします
- 1 項目ずつ話すなら、1 つずつ出し、済んだ項目は薄くします (p.165, p.203)
