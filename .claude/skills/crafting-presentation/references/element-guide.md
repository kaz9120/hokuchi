# 要素と form の選び方

Phase 4 で開きます。要素は 15 種あります (statement / bullets / image / diagram / chart / quote / code / post / link / stat / table / versus / agenda / video / raw)。仕様は SPEC 第 6 章にあります。

要素の形は、それ自体が関係を語ります。本は、要素の位置関係が「敵対／支援」「秩序／混乱」のような意味を帯びると書いています (p.124)。versus は対立を、table は複数の属性の読み比べを、quote は他者の言葉を語ります。要素を選ぶときは、言いたい関係と要素の形が一致しているかを確かめてください。

## 0. 判断の入口

伝えたいことの形から選びます。

| 伝えたいこと | 要素 | レイアウト |
|---|---|---|
| 自分の主張を 1 文で大きく | statement | statement-stage。前提を上に置くなら `headline` を足す |
| 数字 1 つ | stat | stat-stage |
| 要素どうしがどう影響し合うか | diagram | diagram-stage |
| 数値の意味 (比較・変化・分布・割合) | chart | chart-stage |
| 2 つの立場・状態の対比 | versus | versus-stage |
| 複数の対象を、複数の属性で読み比べる | table | table-stage |
| 実物の画面・写真・図版 | image | image-stage、情景なら grid-direct の full-bleed |
| コード・端末・diff | code | code-stage |
| SNS の発言が実際にあったこと | post | post-stage |
| 記事・資料への誘導 (QR 付き) | link | link-stage |
| 他者の言葉そのものが根拠になる | quote | quote-stage |
| 目次・いまどの章か | agenda | agenda-stage (transition から導出) |
| デモ映像 | video | video-stage |
| 自己紹介 | image + statement + bullets | profile-stage |
| 上のどれでもない、並列な短い項目 | bullets | list-stage |

主役級の要素は 1 枚に 1 つです。2 つ要るなら、スライドを分けます (`one-idea` lint)。

## 1. statement — 自分の主張

自分の言葉で、1 点を大きく見せます。本は「ワンフレーズで要点を伝えてみましょう。たいていの場合、それ以外には何もいらないはずです」と書いています (p.166)。

- 前提や問いを先に読ませたいときは、statement-stage の `headline` に置きます。主張は中央に大きく置きます
- `support` は、主張を読んだあとに読む補足だけに使います。既定では付けません (`slide-design.md` の 2)
- `emphasis` は強調語の配列です。強調は 1 か所に絞ります。差をつけすぎると、どれが重要かが伝わらなくなります (p.115)
- 改行は `\n` で、意味の切れ目か句点の位置に入れます (`language.md`)

## 2. quote — 他者の言葉が根拠になるときだけ

quote を使うのは、「誰がそう言ったか」が主張の根拠になるときです。調査レポートの一文、当事者の生の声、原典の定義などです。

- 自分の主張を quote に入れないでください。引用の体裁は「他人の言葉だ」という連想を呼びます。自分の主張は statement で大きく出します
- 社内文書のタイトルや社内の議事録の言葉を、引用の体裁で飾らないでください。聴衆にとって、その文書の権威は意味を持ちません
- 引用するなら、原文を確かめて正確に引きます。引用箇所 (レポート名・ページ・年) を `attribution` に書きます。要約や言い換えを引用符で囲まないでください
- 1 本のデッキで quote が 2 枚を超えたら、使いすぎを疑います

## 3. image — 最適な実物を先に考える

本は、ストーリーを語るのに最適な写真は、多くの場合ストックフォトには存在しないと書いています。先に「どんな写真が最も効果的か」を熟考し、自分で撮るか探し出します (p.182)。写真は主張を運ぶ手段で、「理性と感情の双方に訴えかけ」ます (p.185)。

- 当時の画面・現場の写真・実際の記事・手書きのメモのような実物は、本題の章の中心になります。話者に「いちばん見せたい実物は何か、どこを見てほしいか」を聞いてください
- 見てほしい部分だけを切り出した版を用意すると、「全体 → 見る場所」と運べます (p.181)
- 現実に存在しない演出写真 (地球の前の握手、特徴のない人の笑顔) は使いません (p.180)。生成画像で情景を作るのは、現実の場面を描いていて、デッキの他の画像と様式が揃うときだけにします
- デッキ内の写真は「同じカメラマンが撮った」ように揃えます (p.180, p.192)
- コードのスクリーンショットは code、ポストは post、記事のカードは link で書けないかを先に確かめます。画像に焼くと、テーマに追従できず、再描画もできなくなります (ADR-0016)
- `src` が無い段階でも、`prompt` を「調達すべき写真の仕様」として残します (ADR-0006)

## 4. diagram — 関係の型を選び、中心を決めて磨く

図は関係を説明する道具です。本の定義は「全体を構成する各要素がどのように影響し合っているかを説明するのに便利」です (p.64)。項目が並んでいるだけなら、図にしません。

### 型を選ぶ

関係の性質を言葉にし、次の定義に代入して読めるかで選びます (p.66-77)。

| 関係 | form |
|---|---|
| 明確な始点と終点がある | `flow.linear` |
| 閉じたループで、終わりがない | `flow.cycle` |
| 途中で分岐する・合流する | `flow.branch` / `flow.converge` |
| 日付が意味を持つ経緯 | `flow.timeline` (label に出来事、detail に日付) |
| 行と列の関係 (2 軸の分類) | `structure.matrix` |
| 上下の階層 | `structure.tree` |
| 下から積み重なる (階層と順序の両方) | `structure.layer` |
| 利害や責任を共有している | `cluster.overlap` (交差が主役なら `shared`) |
| 部分が集まって、総和より大きな全体になる | `cluster.closure` |
| 高次のものの一部である | `cluster.enclosed` (nodes[0] が枠) |
| リンクで 1 つに結びついている (方向なし) | `cluster.linked` |
| 親子関係でまとまる | `radial.core` (nodes[0] が中心) |

`flow.cycle` を選ぶ前に、本当に終わりがないかを確かめます。`flow.timeline` は、日付そのものが聴衆に意味を持つときだけ使います。日付が主張を際立たせないなら、`flow.linear` にします。

`flow.network`・`radial.semi`・`radial.coreless`・`pictogram.*` は専用の描画を持たず、順序つきの横並びに落ちます (`form-fallback` lint)。coreless (中心なしに対等に引き合う) を順序つきで描くと、本が区別した意味と逆の絵になります。これらは使わず、別の型か statement で表します。

### 中心を決めて磨く

型を選んだだけでは「一応の合格点」です (p.80)。本はそこから、中心人物 (例では顧客) を図の中心に据えて磨き、メッセージを際立たせます。

- この関係の中心にいるのは誰か (チーム、ユーザー、組織など) を決め、その人が図のどこにいるかを明確にします
- ノードのラベルが動詞句なら、主語を決めます。「仕組みにする」なら、誰が仕組みにするのかを書きます
- 矢印が何の力で動くのかを、図か notes で説明できるようにします
- ノードの `detail` は、ラベルだけでは文脈が渡らないときに限って付けます。全ノードに付けると、情報のレイヤーが増えます (p.117)
- `emphasis` は、そのノードが他より重要だと伝えたいときだけ付けます。サイズを変えれば、図は別のストーリーを語り始めます (p.119)
- 複雑な図は `reveal: sequential` で順に出します (p.78)

## 5. chart と stat — データではなく、データの意味

本の中心命題は「データスライドが伝えるべきは、データそのものではなく、データの意味です」です (p.84)。

### 書く前に答える問い

1. このデータで、聴衆に何を持って帰ってほしいか。答えは多くの場合、因果になります。「なぜこうなったか」「ここから何が予想できるか」(p.88)。この答えを `message` に書きます
2. 一見した要点と、本当に言いたい要点は同じか。違うなら、`annotations` で真の要点を指します (p.88)
3. 聴衆の注意をどこに引きつけるか。1 つの系列なら `emphasis` に系列ラベルを書き、ほかの系列は薄くします (p.95, p.97)。1 つの時点なら `annotations` で指します
4. 聴衆に検証させたいか。それなら画面ではなく配布資料に回します (`detail: appendix`、p.84)

### 道具を選ぶ

- 言いたいことが数字 1 つなら、グラフを使いません。stat で大きく見せます (p.90)。複数の数字を言いたいなら、1 枚ずつ stat に分けることを検討します (p.99)
- 時間による変化は `trend`、項目の比較は `comparison`、ばらつきは `distribution`、全体に占める割合は `composition` です。棒・折れ線・円はレンダラが導出します。割合の差が小さい構成は、円ではなく棒に導出されます (p.91)
- 単位の違う指標を 1 つのグラフに混ぜないでください。chart で書けないからといって table に逃げず、指標ごとに stat か chart に分けます
- chart-stage の `headline` を省くと、`message` が見出しとして描かれます。見出しに数字だけを入れるより、意味を書いたほうが伝わります
- 聴衆がエンジニアなら、飾った明快さは疑われます (p.86)。出典を示し、完全版のデータを用意しておきます

## 6. table と versus — 読み比べと対比

table を使うのは、複数の対象を、複数の属性で読み比べてほしいときです (p.68 のマトリックス)。行と列を行き来して読む関係がないなら、表にしません。

- 区分が 2 つだけの比較は、table ではなく versus にします
- 表の 1 行だけが本題なら、その 1 行を statement にします。残りは話すか、配布資料に回します
- セルが小さな字になるなら、載せすぎです。行を減らすか、分割します (p.172)
- 強調は `emphasis` で行か列を指します (p.89)

versus は、2 つの立場・状態を並べて違いを見せるときに使います。

- 側ごとに、`description` で定義を地の文 1〜2 行で書き、`items` に具体例を並べます。定義を箇条書きで書かないでください
- `sides[].label` には、分けた結果ではなく、分けた基準を書きます
- どちらかを推すなら、その側に `emphasis: true` を付けます。どちらも推さない並置なら、`emphasis` は付けません

## 7. bullets — 見出しとして書く

箇条書きは禁止ではありません。本は控えめに使うよう求め、「箇条書きは単なる見出し」で、本文は話し手が肉付けするものだとしています (p.170-171)。項目数の上限ルールは「全て無視してください」と退けています (p.170)。

- 項目は新聞の見出しのように、短く書きます。読点が要る長さなら、その項目は見出しになっていません
- 項目間で言い回しを揃えます。体言止めか文か、句点の有無をデッキ全体で統一します (p.171、`bullet-parallel` lint)
- 時系列や因果のように並列でない項目は、箇条書きにせず、diagram か複数のスライドに分けます
- 1 項目ずつ話すなら、`reveal: one-by-one` にします (p.165, p.203)
- ネストは書けません (p.171)

## 8. 紹介系と技術素材 (ADR-0016)

| 要素 | 使うとき | 境界 |
|---|---|---|
| code | コード・端末 (`lang: console`)・diff (`lang: diff`) | 17 行以上か 81 桁以上の行があれば抜粋する (`code-budget`)。強調行は `emphasis: ["3-5"]` |
| post | SNS の発言が実際にあったことを見せる | 発言者の権威で語らせるだけなら quote。`source` を書くと SPA で実埋め込みになる (ADR-0017)。`avatar` には実画像を入れる |
| link | 記事・資料に誘導する (QR は自動) | title / image が未指定なら OGP を自動で解決する (ADR-0017)。見出しには、なぜその資料を紹介するのかを書く |
| agenda | 目次・現在地 | transition の statement から導出される。章題を直したいときは transition を直す |
| video | デモ映像 | 静的出力ではプレースホルダになる |

## 9. raw — 脱出口

語彙で表せない 1 枚のためだけの口です (p.135)。`svg` か `html` と、`waiver` (理由) が必須です。デッキの 1 割を超えると `raw-budget` warn が出ます。まず diagram / chart / image で表せないかを確かめてください。
