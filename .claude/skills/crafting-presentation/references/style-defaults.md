# 話者の型 (山本)

話者 (山本) 固有の既定です。過去の登壇で、初版とレビュー反映版の差分の多くは、ここに書いた型とのズレでした。そのため、完全版 (Phase 4) の段階から当てます。

登壇ごとに上書きしてかまいません。発表後の振り返りで新しい学びが出たら、理由と一緒にこのファイルに追記してください。slide:ology の原則と食い違う既定を足すときは、なぜこの話者にはそれが合うのかも書きます。

## 考え方

- 理解されることを、物語の演出より先に置きます。話者の言葉では「ストーリーは大事だが、それは同じ認知負荷であればの話。まずは理解される、届けるが大事」です (2026-09 Dev's Garden)
- 聴衆に行動を押しつけません。「良いと思ったアクションは勝手に取ってくれる」と考えています。締めはまとめにし、行動への誘いは入れるとしても軽くします
- 対面の登壇では、スライドは話の背景です。主張はスライドに、語りは notes に置きます。資料を公開するときは、スライド単体でも意味が通る文を足します (Phase 0 で確かめます)

## 構成

- タイトルスライドの副題には、イベント名 (イベントのテーマ) と日付を入れます。「〇〇の話」のような副題は付けません。どの発表も何かの話なので、情報になりません
- タイトルには、演題の名詞句をそのまま置くより、講演の背骨になる問いを掲げることを検討します
- 冒頭で結論を言い切らず、問いとして置きます。まとめの章がその問いに答える形にすると、前振りと締めが対になります (2026-08 山手ウエストで「結論を出すより問題提起くらいに留めた方が良い」と指摘されました)
- タイトル直後に自己紹介を 1 枚置きます (profile-stage)。bio の項目は「略歴」「実績」「趣味」の 3 つで固定します。略歴と実績は登壇をまたいで同じ文面を使い、趣味の欄だけ登壇ごとに入れ替えます。本編への伏線は趣味の欄に置きます (例: 「毎週 note を書いています」)。各項目は 2 行以内に収めます
- 聞き取りをまとめる登壇では、自己紹介を「聞いてきた人」の立場で書きます。評価者・分析者として立てると、偉そうに読まれます
- 章を設計し、content スライドに `chapter` を付けます。聴衆が現在地を見失わないための章ラベルです
- 場面の転換には `role: transition` の 1 枚を置きます。10 分なら 3〜4 回です
- opener バンパーは既定では置きません。10 分程度の登壇では、title が開幕を兼ねます
- MOSH を代表する登壇では、全体の方針から入り、本題がその中のどこに当たるかを示してから本題に入ります。本題でない領域 (別の発表で扱ったもの) は、薄い章で「今日は扱わない」と明示します
- 事例に入る前に、「何を届けたかったのか」を渡します。作り手の都合から語り始めると、そのあとの手段がすべて宙に浮きます
- 既製品を使わずに自作した題材では、既製品を試して届かなかった過程を 1 枚使って語ります。ここを飛ばすと、「作れるから作った」ように見えます
- 人に聞いた話が題材なら、集計より先に生の言葉を置きます。順序が逆だと数字が主張になり、声は後づけの飾りに落ちます (2026-08 fable5-meetup で「10名に聞いた割に薄い」と指摘されました)
- 結論の数字は、内訳より先に出します
- 抽象的な概念語 (心理的安全性など) を持ち出すときは、一般的な定義を 1 枚で共有してから、自分のケースに降ろします。定義のスライドに自分の実感を混ぜないでください
- まとめの項目は、抽象度を上げません。本編で使った言葉をそのまま持ってきます
- 短い持ち時間では、聴衆が持ち帰れない留保を落とします

## テンポ

- この話者は、1 語だけの大きなスライドを挟む速いテンポを使うことがあります。そのときの枚数は、1 枚 30 秒の平均で見積もります (10 分で 25〜29 枚)。本の一般的な目安 (2 分に 1 枚、p.256) よりかなり多いです
- この型は、削る段 (Phase 6) の選択肢として扱います。既定ではありません。30 秒は平均で、各スライドの持ち時間ではありません。全スライドに 25〜30 秒を配ると平らになります (`reduce.md`)

## 要素

- 体験談・事例の題材では、本人提供の実写真 (スクリーンショット・記念写真・人物写真) を使います。`prompt` は「調達すべき写真の仕様」として書き (ADR-0006)、写真が届いたら `src` を差します。実写真は `treatment: framed` を基本にします
- diagram のノードには、まず主語と中心を決めます (`element-guide.md` の 4)。`detail` は、ラベルだけでは文脈が渡らないノードに限って付けます
- versus の `sides[].label` には、分けた結果ではなく、分けた基準を書きます。側の説明は `description` に地の文で書き、箇条書きの「例)」で説明しません
- post の `avatar` には実画像を入れます。イニシャルの円だと、下書きに見えます
- 話者本人の感情を書く場面では、一般的な語で埋めないでください。本人が実際に使った言葉を引き出してから書きます。言葉が出てこないときは、候補を並べて選ばせるのではなく、その感情が何に向いているのかを問い直します

## 言葉

言葉の規則は `language.md` にあります。この話者に特有のものだけを書きます。

- 改行を入れた statement では、1 行目の末尾に読点・句点を置きません
- 短い statement と箇条書きには読点を打ちません (2026-09 Dev's Garden で「この短さで読点入れるのは違和感。だったら改行して」と指摘されました)
- スライドの文言は、狙った言い回しより、そのままの言葉を選びます。「あとで高くつく」より「リスクが高い」です
