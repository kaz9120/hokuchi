# 発表後 — 公開・収穫

パスは、このスキルのフォルダ (`.claude/skills/crafting-presentation/`) からの相対です。

1. 公開する前に、ノートを公開物として仕上げます。登壇までのノートは話者が自分の言葉に直す下書きでよいのですが、公開すると、ノートはトーク全体のテキスト (「テキストをコピー」と `talk.md`) に入り、閲覧者や AI が全文を読みます。全状態のノートを、会場にいなかった人の目で読み直します。直すのは、次のような話者なしでは通じない言葉です
   - 指さしと会場の前提。「こちらをご覧ください」「このあと交流会が」「このイベントの」。指す先は名前で書きます (資料なら作者と題名)。ノートはプレーンテキストなので、リンクは押せません
   - 前のシーンでしか定まらない指示語。「その間に」の起点の期間は、画面にもノートにも書きます
   - 年の無い日付と、社外の人が知らない社内の名前。初出で何者かを補います
   - 事実が素材で確かめられないときは、推測で埋めずに話者に聞きます
2. 公開するトークは `talk.tsx` の `public: true` を確かめ、`bun run site` でサイトを組み立てます。凍結はしません。全トークを最新のフレームワークでビルドし、前回と見た目が変わった状態があれば止まります。変化を確かめて話者に報告し、意図したものなら `--accept` で受け入れます。各トークの `talk.md` (トーク全体のテキスト) と PDF も開いて、話者なしで読める形になっているかを確かめます。デプロイは話者の確認を取ってから `bun run deploy` で行います。手順とつまずいたときの対処は `apps/slides/README.md` にあります
3. 振り返りをします。完全版・削った版・最終版の絵コンテの差分と、話者の指摘を読み、修正を 3 つに分けます。「何を伝えるか (芯・構成・前提)」「言葉」「見せ方」です。話者の型として残すべき学びは、理由と一緒に `references/style-defaults.md` に追記します
4. 部品を収穫します。このトークで素の React で書いた表現のうち、別のトークでも使えるものは `packages/stage/src/kit/` (中身を持たない汎用の部品) か `parts/` (自己紹介のように中身を持つもの) への昇格を検討します。2 本以上のトークで同じものを書いていたら、昇格します
