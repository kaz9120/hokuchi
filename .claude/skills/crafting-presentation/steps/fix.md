# 話者のフィードバックで直す (Phase 8)

パスは、このスキルのフォルダ (`.claude/skills/crafting-presentation/`) からの相対です。

反映は、シーンの `id` と状態の番号の単位で行います。studio の中では、話者の指摘はコマを指した会話で届きます。聴衆役の感想は `feedback.yaml` のスレッドに入っています。

### 認めた見た目を守る

絵コンテの頭に `見た目: 話者が認めた` があるトークは、話者が見た目を気に入っています。言葉や事実を直すうちに見た目が平均的な資料へ戻るのが、いちばん避けたい失敗です。

- 直すのは、話者が指した所と頼んだことだけです。CSS・配置・文字の大きさ・色・動き・背景は、頼まれない限り変えません。`check` の「小さい文字」の指摘は当てません
- 絵コンテからシーンを作り直しません。会話の前のほうに前の版のシーンの記憶があっても、いまのファイルが正です。直す前に、直すシーンのファイルを読み直します
- 言葉や事実を直したら、画面の文字と絵コンテの話すことの両方を揃えます
- 直したら `check --motion` を回し、`out/check.md` の「認めた見た目からの変化」に出た状態を返事に書きます。頼まれていない状態が変わっていたら、戻してから返事をします。話者がこれまでに頼んだ変更は、話者が認め直すまで変化に出続けますが、戻しません
- 認め直すのは話者です。`bun run look` は動かしません

### ふだんの直し

- 聴衆役の感想は、直したら `replies` に `by: Claude`・`thinking` (考えたこと)・`change` (変えたこと) を足して `ball: none`・`closed: 直した`、直さないなら `closed: そのままにした` にして、理由を `thinking` に書きます。返事に「直した n 件・見送った n 件」と見送った理由を書きます。話者は見送りを戻せます
- 話者に確かめたいことは、返事で番号付きで聞き、`proposals.yaml` の `ask` に書きます。絵コンテの「話すこと」の中に覚え書きを書かないでください (話者と聴衆役が読む文に混ざります)
- 部品 (`packages/stage/src/kit/`・`parts/`) を直す必要があるときは、studio の中では書けません。返事で伝え、話者が「部品を直すのを許す」を押すと、次の 1 回だけ書けます

細かい指摘は、作業用サーバの agentation から Markdown で貼られることもあります。見出しの `## Page Feedback: /#/<scene-id>/<step>` が状態で、各メモのセレクタと周辺の文字が対象の要素です。

- 変更するのは、指示されたシーンだけです。他のシーンには触りません
- 話者が手で直した絵コンテ・シーンは、書き直しで上書きしません
- 同じ種類の指摘が 2 回来たら、トーク全体に同じ問題がないかを探して、まとめて直します。話者に同じ指摘を 3 回させないでください
- 構成や言葉の指摘は、絵コンテを先に直し、実装を追従させます
- 反映のたびに `check --motion` を回し、意図どおりかを目で確かめます
