# スライドを作る (Phase 7)

パスは、このスキルのフォルダ (`.claude/skills/crafting-presentation/`) からの相対です。

この段では、承認した絵コンテから画面を作ります。目標は「かっこいい」です。理解されることは、絵コンテの構成と言葉が受け持っています。

- 入力: 承認した絵コンテ (`storyboard.md`。状態の行の画面の言葉と実物、話すこと)、トークの `assets/`、テーマ
- 出力: `talk.tsx`・`scenes/`・トークの中の CSS
- 開くもの: このファイル、`references/build-scenes.md` (stage の書き方)、`packages/stage/README.md`。部品の仕様は `packages/stage/src/` のコードにあります

この段では、`SKILL.md` とほかの段のファイル (`steps/`)、ほかの `references/` を開きません。規則を読むほど、画面は規則の挿絵になります。他のトークのシーン・CSS も読みません。読むと、その見た目に寄ります (2026-11 の比べ: 前の版を読んだ回は前の版とほぼ同じに、将棋の発表を読んだ回は将棋の世界になった)。トークの `scenes/` にある下書きのシーンも参考にせず、作り直します。

## 1. テーマが決めること

テーマは絵コンテの頭の `テーマ:` です。

- `mosh` (MOSH として登壇する): MOSH のテンプレートに厳密に従います。背景・色・書体・ロゴと © の枠は、テーマ (`packages/stage/src/themes/mosh/`) のものを使い、上書きしません。MOSH の Marp テンプレート (TheMoshInc/marp-slide-template) にある背景と型は次の 4 つで、これ以外の背景は作りません。表紙は `bg-cover.svg`、章の扉は `bg-section-cover.svg` (文字とロゴは白)、本文は `bg-default.svg`。自己紹介は、左を強調色で塗った面にし、右に写真を置く型 (テンプレートの split) を使えます。本文で背景が中身と競うときは、テンプレートの表やコードと同じく、白の半透明の面 (`rgba(255, 255, 255, 0.6)`) に中身を載せます。色はテーマのトークン (`--accent` など) から取り、トークの中で新しい色を作りません。テンプレートが決めるのはこの枠だけです。枠の上に置く中身 (盤・グラフ・写真・図・題材のモチーフ) と、構図・文字の大きさ・実物の見せ方・シーンをまたいで育つ物は自由に決めます。テンプレートに従うことは、控えめに作ることではありません
- `hokuchi` / `hokuchi-light` (個人として登壇する): 色と書体はテーマから取り、背景はトークの題材から決めてかまいません。`BRAND.md` を読みます

テーマに無い規定 (ブランドガイドラインの細部) を、推測で足しません。迷ったら返事で聞きます。

## 2. トーク全体の世界を決める

素材・写真・絵コンテを読み、次を決めます。

- 育つ物: シーンをまたいで形を変えながら残る物 (将棋の発表では、決勝の 8 枠の列が 20 年の並びに育った)。中核メッセージに関わる数や関係を、1 つの物の変化で見せます。トークの `world` に置き、`cut: 'fade'` にします
- 文字の階調: 主役の文は 64〜110px、補う文は 24〜30px、ラベルや脚注は 13〜16px。差をはっきりつけます
- 部品の語彙: 写真の枠、ラベル、線、数字の見せ方を 2〜3 種類に絞り、トーク全体で使い回します
- 題材のモチーフ: 題材から取った 1 つのモチーフ (将棋なら盤) を決め、表紙や章の扉にも中身として置きます。`hokuchi` では背景にしてもかまいません。`mosh` では背景を差し替えず、背景の上に置きます

## 3. 3 か所を先に作って見せる

表紙・覚えて帰る瞬間 (絵コンテの `伝えること:` に印がある) ・まとめの 3 か所を先に作って撮り、話者に見せます。世界の方向が違うと、全部作ってからでは直しが大きくなるためです。話者が良いと言ったら、残りを作ります。

## 4. 撮って、目で見て直す

`bun run check <トーク> --motion` を回し、`out/states/` の静止画を 1 枚ずつ自分の目で見ます。次の問いで見て、直しては撮り直します。

- 遠くから一目見て、何を見ればいいか分かるか。主役は 1 つで、十分に大きいか
- 資料に見えないか。どの画面も同じ構図 (左上の見出しと下の図) になっていないか
- 実物 (写真・表) は、全体 → 見る場所に寄る → 意味、の順で運べているか
- 架空の図形で済ませていないか。実物か実際の数で言えるなら、そちらを使う
- 素材に無い事実 (補った数字・年・肩書き) を画面に書いていないか

`check` の指摘のうち、実行時のエラー・はみ出し・重なり・絵コンテとの食い違いは直します。「小さい文字」は目安です。主役が大きく、小さいのがラベルや脚注なら直しません。

## 5. 絵コンテと揃える

構成と言葉は、この段では変えません。画面を作るうちに状態を足したり分けたりしたら、絵コンテの状態の行と話すことの割り当てを、できた画面に合わせます。話すことの中身は変えません。足した状態の話すことは素材から書き、返事でどこを足したかを伝えます。

## 6. 見せる

返事には、各シーンで狙ったことを 1 行ずつと、確かめていないことを書きます。話者が見た目を認めたら (studio の「この見た目を認める」、ターミナルでは `bun run look <トーク>`)、直しの段 (`steps/fix.md`) に移ります。
