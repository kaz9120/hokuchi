# 読み返しと評価

## 誰が何を見るか

| 見るもの | 担当 |
|---|---|
| 文の長さ、段落の長さ、漢字率、ぼかしの密度、禁止語、共感要求、結びの重さ、タグの数 | `hokuchi-note lint` |
| 芯が伝わるか、フックが効くか、具体があるか、リズム、炎上リスク | 人 (と Claude の読み) |

lint で見られるものを、人が目視で数えることはしません。人は lint に見えないものを見ます。

---

## 読み返しの 4 問

まずこの 4 つだけを確認します。ここが通らなければ、細部を直しても意味がありません。

1. 芯の 1 文が伝わるか。読み終えた人が、記事の主張を自分の言葉で言えるかを見ます
2. 冒頭 3 行で読む気になるか。説明から始まっていないかを見ます
3. 抽象語で済ませた箇所はないか。「さまざまな」「効率的に」「大幅に」を具体に置き換えられないかを見ます
4. どこが密か指させるか。見出しごとの字数を並べて、山が 1 つ見えるかを見ます。読み終えて覚えている場面があるかも確かめます。全ブロックが同じ重さなら、1 文ずつ直しても退屈なままです (`somitsu.md`)

最後に声に出して読みます。カフェで友人に話して違和感があるところは直します。

---

## 評価の観点

原稿のレビューを求められたときは、次の 8 観点で見ます。スコアを出すときは、迷ったら低いほうを付けてください。5.0 はめったに付けません。

| スコア | 意味 |
|---|---|
| 5.0 | プロの編集者が見ても非の打ち所がない (5% 未満) |
| 4.0-4.9 | 商業メディア掲載レベル (15% 程度) |
| 3.0-3.9 | 標準的な技術ブログ (50% 程度) |
| 2.0-2.9 | 改善が必要 (25% 程度) |
| 1.9 以下 | 大幅な改善が必要 (5% 程度) |

### 1. 簡潔性 — 濃度

削っても意味が変わらない文がないかを見ます。同じことを別の言葉で繰り返していないか、装飾的な比喩や余韻が目的化していないかも見ます。結びが簡潔に着地しているかも確かめます。

このスキルでいちばん重視する観点です。ここが低いなら、他が高くても直します。

### 2. 思考整理力

情報の優先順位と強弱、論理的な流れ、抽象と具体のバランス、結論への道筋を見ます。

強弱は粗密で見ます。密にした場所が芯の根拠になっているかを確かめます。背景や定義が、山場と同じ字数を使っていないかも見ます。全段落が均等に丁寧なら、ここは 3.0 を超えません。

### 3. 構成と読みやすさ

導入の魅力 (フック・ファースト)、見出しと段落の構成、画像配置、文章のリズムと緩急を見ます。

### 4. 実践応用性

読者が行動に移せる情報があるかを見ます。具体的な手順、著者独自の経験、再現性です。

### 5. コミュニケーション力

著者の声が自然に聞こえるかを見ます。自己開示の深さ、専門用語の説明、「私はこう思う」が明確に届くかも見ます。

観客にマイクを向ける問いかけは減点します。自分が面白がっている問いかけは加点します。

### 6. 防御力

主観と客観を区別しているか、前提条件と制約を明示しているかを見ます。根拠と出典、異なるアプローチへの配慮も見ます。

### 7. 人間らしさ

失敗談や苦労話が生々しいか、感情の起伏が自然かを見ます。文章にリズムの変化があるか、声に出して読んで違和感がないかも見ます。

減点するのは、文体が均一、具体例が表面的、感情表現が型どおり、「まず」「次に」「最後に」の多用、過剰な箇条書きです。

### 8. 炎上リスク・社会的配慮 (高いほど安全)

著者の意図ではなく、読者がどう受け取るかで見ます。

- 人を動物・モノ・機械に例えていないか
- 特定の属性をステレオタイプ化していないか
- 予防線が「分かっていてやった」と読まれないか
- SNS で切り取られて拡散されても問題ないか
- MOSH のブランドへの影響を考慮しているか

## レビューの出し方

```markdown
## スコア

| 観点 | スコア |
|---|---|
| 簡潔性 | X.X |
| 思考整理力 | X.X |
| 構成と読みやすさ | X.X |
| 実践応用性 | X.X |
| コミュニケーション力 | X.X |
| 防御力 | X.X |
| **平均** | **X.X** |
| 炎上リスク | X.X |
| 人間らしさ | X.X |

## 良い点
（具体例を引用して 2〜3 点）

## 削れる箇所
（削っても意味が変わらない文を、行を引用して列挙。density.md の手順の何番に当たるかを添える）

## 直したい箇所
（問題 → 改善案 の順に。リライト例を Before / After で示す）

## タイトル・タグ
（タイトル 3 案、タグ 3〜5 個）

## 画像
（追加すべき位置と内容）
```

指摘は削る話から始めます。足す話より削る話のほうが、記事が良くなるからです。
