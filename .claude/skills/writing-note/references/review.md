# 読み返しと評価

## 誰が何を見るか

| 見るもの | 担当 |
|---|---|
| 文の長さ、段落の長さ、漢字率、ぼかしの密度、段落の中の留保、常体の混ざり、禁止語、共感要求、結びの重さ、タグの数 | `hokuchi-note lint` |
| 素材に無いことを書いていないか、型で畳んでいないか (`ai-tells.md`) | 文脈を持たないサブエージェント (Phase 6) |
| 芯が届くか、どこで読むのをやめたくなるか、覚えている場面、勧めたいか | 素材を持たない読者役 (Phase 6) |
| 芯が伝わるか、フックが効くか、具体があるか、炎上リスク | 人 (と Claude の読み) |

lint で見られるものを、人が目視で数えることはしません。人は lint に見えないものを見ます。

---

## 読み返しの 4 問

まずこの 4 つだけを確認します。ここが通らなければ、細部を直しても意味がありません。

1. 芯の 1 文が伝わるか。読み終えた人が、記事の主張を自分の言葉で言えるかを見ます
2. 冒頭 3 行で読む気になるか。説明から始まっていないかを見ます
3. 抽象語で済ませた箇所はないか。「さまざまな」「効率的に」「大幅に」を具体に置き換えられないかを見ます
4. どこが密か指させるか。見出しごとの字数を並べて、山が 1 つ見えるかを見ます。読み終えて覚えている場面があるかも確かめます。全ブロックが同じ重さなら、1 文ずつ直しても退屈なままです (`somitsu.md`)

最後に声に出して読みます。カフェで友人に話して違和感があるところは直します。息継ぎしない所の読点も、ここで外します。

## 評価の観点

原稿のレビューを求められたときは、次の 6 観点で見ます。スコアを出すときは、迷ったら低いほうを付けてください。5.0 はめったに付けません。

| スコア | 意味 |
|---|---|
| 5.0 | プロの編集者が見ても非の打ち所がない (5% 未満) |
| 4.0-4.9 | 商業メディア掲載レベル (15% 程度) |
| 3.0-3.9 | 標準的な技術ブログ (50% 程度) |
| 2.0-2.9 | 改善が必要 (25% 程度) |
| 1.9 以下 | 大幅な改善が必要 (5% 程度) |

### 1. 素材への忠実さ

素材に無い描写・数字・気持ち・教訓・因果を足していないかを見ます (`ai-tells.md` の 1 の層)。他人の好意を事実として書いていないか、体感を言い切っていないかも見ます。ここが低いなら、ほかが高くても直します。

### 2. 組み立て

結論かいちばん動いた場面から始まっているか、見出しが主張になっていて読者の問いの順に並んでいるか、タイトルの約束が最初の節までに回収されているかを見ます。素材の話した順をなぞっていたら、3.0 を超えません。

### 3. 粗密

密の場所が芯の根拠になっているか、背景や定義が山場と同じ字数を使っていないかを見ます。全段落が均等に丁寧なら、3.0 を超えません (`somitsu.md`)。

### 4. 面白さ

書き手しか持っていない細部があるか、感想の直前に事実があるか、誰でも書ける文が残っていないかを見ます (`interest.md`)。

### 5. 書き手の声

です・ます でつながっているか、接続語が残っているか、Claude が足した常体・短文の連打・不要な読点が無いかを見ます (`voice.md`、`ai-tells.md` の 3 の層)。話者の素の反応や生活圏の比喩が、1〜2 か所残っているかも見ます。

### 6. 炎上リスク・社会的配慮 (高いほど安全)

著者の意図ではなく、読者がどう受け取るかで見ます。

- 人を動物・モノ・機械に例えていないか
- 特定の属性をステレオタイプ化していないか
- 予防線が「分かっていてやった」と読まれないか
- SNS で切り取られて拡散されても問題ないか
- MOSH のブランドへの影響を考慮しているか

## レビューの出し方

```markdown
## スコア

| 観点 | スコア |
|---|---|
| 素材への忠実さ | X.X |
| 組み立て | X.X |
| 粗密 | X.X |
| 面白さ | X.X |
| 書き手の声 | X.X |
| **平均** | **X.X** |
| 炎上リスク | X.X |

## 良い点
（具体例を引用して 2〜3 点）

## 素材に無い文
（出どころを指せない文を、行を引用して列挙）

## 削れる箇所
（削っても意味が変わらない文を、行を引用して列挙。density.md の手順の何番に当たるかを添える）

## 直したい箇所
（問題 → 改善案 の順に。リライト例を Before / After で示す）

## タイトル・タグ
（タイトル 3 案、タグ 2〜5 個）

## 画像
（追加すべき位置と内容）
```

指摘は、素材に無い文から始め、次に削る話をします。足す話より、この 2 つのほうが記事が良くなります。
