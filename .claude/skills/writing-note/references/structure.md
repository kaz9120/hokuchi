# 構成・タイトル・タグ・画像

## 分量

2026-06 以降の公開済み 24 本は、中央値 1,396 字です。迷ったら短いほうに寄せてください。分量は、素材に話者の言葉がどれだけあるかで決まります。話者の言葉が 500 字分しかないのに 1,500 字の記事を書くと、残りの 1,000 字は Claude の作文になります。

行数を各ブロックに均等に配りません。密にする 1 ブロックに寄せ、残りは 1〜3 行で通過します (`somitsu.md`)。

## 構成の原則

### フック・ファースト

時系列順 (背景 → 経緯 → 結果) では書きません。いちばん面白かったことや、自分が引っかかった瞬間を冒頭に置きます。冒頭の段落は中央値 44 字で、短めです。

> 自分が欲しいツールがその日のうちに動く。 最初はそれだけで楽しかった。
> 7月25日の大吉祥寺.pmで、wabiさんがこんな話をしていました。
> 発表は1分オーバーしました。

タイトルがフックを言っているときは、冒頭でそれを繰り返さず、事実から入ります。

> タイトル「音声入力を再開した。やめた理由が、もう思い出せない」
> 冒頭「6月末に音声入力をやめたのですが、11月から Aqua Voice の課金を再開しました。」

### 見出しは、その節の主張にする

見出しは平均 18 字です。見出しだけを拾い読みしても、記事の筋が追えるようにします。

- 理由ではなく主張にします。「最終的な限界は肉体にある」は理由で、主張は「体験だけは並行できない」でした
- 比喩にしません。「懇親会の話は手からこぼれ落ちる」は比喩で、主張は「損失なく記録するのは難しい」でした
- 見出しに読点は入れません
- 例外は、話者の素の反応をそのまま見出しにするときです (「前って、こんなに変換うまかったっけ」)。主張の見出しが並ぶ中に 1 つだけなら、温度の違う見出しとして効きます
- 「おわりに」「作ったもの」「〇〇とは」は、この下に何があるかが分からないので使いません

### 読者の問いを 1 つずつ消す

見出しの並びは、読者の頭に浮かぶ問いの順にします。前の節を読んだ読者が「で、なぜ？」「それでどうなった？」と思ったことに、次の節が答えます。大見出し → 中見出しの入れ子は作りません。

芯を支えない節は、合意した骨組みにあっても削ります。構成を 2 回変えても「主張が謎」と言われた節は、たいてい芯の外にあります。

### 結びは短く

結びは 3 文以内、中央値 38 字です。まとめ直し・抱負・教訓は書きません。次のアクションか、いちばん言いたかったことで終えます。

> 進んだら、また書きます。
> 新宿が近い人はぜひ。
> 名前はまだ付けていません。付けて愛着を育てながら、しばらく使い続けてみます。

## 記事の種類ごとの約束

| 種類 | 約束 |
|---|---|
| イベントレポート | 自分が登壇したなら、何の発表をしたのか (演題と主題を 1 文) を、反省や反響より先に書きます。参加していない読者は、主題が分からないと反省の細部を読めません。自分がいちばん動いた 1 つ (自分の登壇、1 本のセッション、1 つの会話) を密にし、ほかのセッションは 1〜2 行で通過します。登壇者の名前と演題はページで分かるので、当日の感想で埋めます |
| 月次振り返り | 冒頭は、山の予告ではなく見出し画像の説明を兼ねます。イベントの節は、ページを見れば分かる事実より書き手が感じたことで埋めます。結びは翌月以降の予定とペース配分にし、別記事の予告は該当する節の末尾に置きます |
| 書評・読書感想 | 本が主役です。自分の話は 1 ブロックに下げます。引用には出典をページまで添えます (Kindle なら位置) |
| 感謝・お知らせ | 記事の役 (感謝) だけを書きます。他の事例や主張は持ち込みません。前編にあたるなら短く畳み (650 字で公開した例があります)、比重は後の記事に残します |
| 開発日誌・近況報告 | 一覧は時系列にします。タイトルは数字の見出しより、連載の名前 (「将棋AI開発日誌」) に寄せます |
| 判断・やめた話・目標の立て方 | 当時の前提 (なぜ始めたか) は 1 節で粗く通過し、やめる決め手や、選択肢を比べて決めた瞬間を「判断の密」にします (`somitsu.md`)。決め手が素材に無ければ、書く前に聞きます |
| エッセイ | 自分が動いた場面を 1 つ密にします。本や他人の情報を足した節より、自分が感じた 1 文のほうが残ります |

## タイトル

note は SNS 経由の流入が多いです。タイムラインで目に留まるかどうかで、読まれるかが決まります。

- 何が書いてあるか 1 秒で分かるようにします。内容は隠さず、結論を入れてもかまいません
- 先頭 25 字に核を置きます。SNS や検索結果では、それ以降が省略されるからです
- 読者が知っている名前 (制度・イベント・道具) を先頭に置きます
- 煽りや釣りは使いません

話者が選んだタイトルの例です。どれも、Claude が勧めた案ではありませんでした。

| 選ばれたタイトル | Claude の案 | 何が効いたか |
|---|---|---|
| 小学5年生で出会ったコンピュータ将棋と、世界9位まで | コンピュータ将棋を作り始めた理由 | 理由を名乗るより、始点と到達点を見せる |
| LINE API Expert制度への感謝 | 初代で、最後の LINE API Platform Evangelist でした | 読者が知っている制度名と、記事の役をそのまま名前にする |
| 将棋AI開発日誌 | (数字の見出し) | 近況の報告は連載の名前にする |
| 「名作に墨汁をぶっかけた」 50代・木村一基九段に学ぶ、AI時代の生き方 | 「どんどんバカになっていきますね」を推した | 生々しいだけの言葉より、凄絶さのある一文 |

タイトルは 3 案出して、選んでもらいます。案は質の違うものにします (始点と到達点 / 記事の役そのまま / いちばん強い一文)。

## タグ

タグは話者が決めます。公開済みの記事は 2〜5 個です。案を出すときは、主題 (エンジニア、個人開発、AI駆動開発)、形式 (イベントレポート、エッセイ、振り返りnote)、固有名 (イベントのハッシュタグ、道具の名前) から選びます。イベントレポートは「イベントレポート」とイベントのハッシュタグの 2 個に絞った例があります。

note 公式のお題は https://note.com/contests で確認します。

## 画像

- 見出し画像は必ず設定します。推奨は 1280×670px です。作り方は `eyecatch.md` にあります
- 本文の画像は密の場所に寄せます。均等には撒きません
- 画像に添える数字は、その画像に写っている表記のまま書きます
- キャプションは、画像を見た話者の素の反応が効きます (「私は一体何を喋ったんだ」「緊張でいっぱいです＞＜」)。説明のキャプションより、読者が笑うか頷くものにします。話者に写真をもらったら、キャプションの一言も聞きます

## 埋め込みとリンク

X のポスト、外部記事、connpass、Speaker Deck は、URL だけの行を置くとカードになります。

- リンクは、それを指す文のすぐ後に置きます
- 当日のポストは、節の頭ではなく、感想を読み終えた位置に置きます。感想を先に読ませ、ポストは余韻にします
- 引用した本や記事には、出典 (URL や書名とページ) を斜体で添えます
- 埋め込みは説明の代わりになりません。何を見てほしいのかを地の文で書いてから置きます
