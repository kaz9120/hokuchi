# 構成・タイトル・タグ・画像

## 分量の型

公開済み 44 本の中央値は 1,365 字です。最短は 246 字、最長は 4,995 字でした。迷ったら短いほうに寄せてください。

下の型に書いた行数は総量の目安で、各ブロックに均等に配る数字ではありません。密にする 1 ブロックに寄せ、残りは 1〜3 行で通過します (`somitsu.md`)。「本題① 10〜15 行、本題② 10〜15 行」をそのまま埋めると、平らな記事になります。

### ショート (500〜800 字 / 30 分)

書きたいことが 1 つだけあるときの型です。「とにかく出す」ために使います。

```
[見出し画像]
フック（体験・エピソード・問い）   3〜5 行
本題（言いたいこと）              10〜15 行
結び（次のアクション or 一言）     1〜3 行
```

### スタンダード (1,500〜2,500 字 / 1〜2 時間)

テーマを掘り下げたいときの型で、note の標準です。

```
[見出し画像]
フック                            3〜5 行
背景・前提                        5〜10 行
[画像 or 区切り線]
本題① 具体的なエピソード・事実     10〜15 行
[画像]
本題② 考察・学び                  10〜15 行
結び                              1〜3 行
```

### ロング (3,000 字以上 / 3 時間以上)

ノウハウ系・振り返り系で、情報量が多いときの型です。セクションごとに画像を挟みます。

```
[見出し画像]
フック                            3〜5 行
この記事で伝えること（1〜2 文）
[画像 or 区切り線]
セクション 1〜3                   各 10〜20 行 + 画像
結び                              1〜3 行
```

## 構成の原則

### フック・ファースト

時系列順 (背景 → 経緯 → 結果) では書きません。いちばん面白かったことや、自分が引っかかったエピソードを冒頭に置きます。そこから本題へつなげます。

公開済み記事の冒頭は中央値 41 字です。

> 自分が欲しいツールがその日のうちに動く。 最初はそれだけで楽しかった。
> 7月25日の大吉祥寺.pmで、wabiさんがこんな話をしていました。
> 3週間前、コンピュータ将棋の開発を Claude Code と再開した話を書きました。

避けたい冒頭 (初期記事に多いもの) は次のとおりです。

> 本記事は 〇〇 Advent Calendar 2025 の1日目の記事です。
> MOSHにジョインして、気づけば半年が経ちました。

### 結論 → 背景 → 補足

「背景 → 経緯 → 気づき → 結論 → 余韻」の順では書きません。読者に「で、何が言いたいの？」と思わせてしまうからです。

### 見出しは言い切る

見出しは平均 18 字です。説明ではなく主張にします。見出しだけを拾い読みしても記事が追える状態を目指しています。

> 「プロジェクトごと」に分けるのをやめた
> 打率は67%から27%に落ちた
> 覚えているのは技術のほうではありません
> 大雨の日に限って、足が向きます

「おわりに」「作ったもの」「〇〇とは」は情報がなく、この下に何が書いてあるか分かりません。中身を見出しに出してください。

### リニアに展開する

大見出し → 中見出しの入れ子は避けます。読者の「なぜ？」を 1 つずつ消していきます。

### 密は 1 つ、残りは通過

骨組みの各ブロックに「密」か「粗」を書きます。密は 1 つで、長い記事でも 2 つまでです。芯の 1 文の根拠になる場面を密にし、背景・経緯・一般論は粗にします。決め方は `somitsu.md` にあります。

背景を丁寧に積んでから本題に入る構成にすると、読者は本題に着く前に眠くなります。背景は密を読むのに足りる分だけにして、密の直前か途中に置きます。

### 結びは短く

結びは 3 文以内にします。まとめ直し・振り返り・抱負は要りません。公開済み記事の結びは中央値 44 字です。

## タイトル

note は SNS 経由の流入が多いです。タイムラインで目に留まるかどうかで、読まれるかが決まります。

- 何が書いてあるか 1 秒で分かるようにします。内容は隠さず、結論を入れてもかまいません
- 先頭 25 字に核を置きます。SNS や検索結果では、それ以降が省略されるからです
- 固有名詞・数字・具体的なエピソードを含めます
- 煽りや釣りは使いません。等身大のトーンを保ちます

| パターン | 例 |
|---|---|
| 具体的な体験 + テーマ | Slackの通知を全部切った。フルリモート半年の結論 |
| 言い切り | サクッと作れる楽しさに、飽きた |
| 問い + 主観 | 「仕事」と「好き」の境界線で。今年、コミュニティについて考えたこと |
| 対象 + 意外性 | ドキュメントは、AI に渡す前に作り直す |
| 数字 + スコープ | AIが将棋AIを作る3週間、見えてきた壁 |

避けるものは次のとおりです。

| パターン | 例 | 理由 |
|---|---|---|
| まとめ記事風 | 【完全保存版】エンジニアのためのSlack活用術10選 | 個人 note の温度感と合わない |
| 煽り・釣り | 知らないと損！SNSアカウント名の最強戦略 | ハイカロリー。ブランド毀損 |
| 内容が分からない | 最近思ったこと | クリックされない |

タイトルは 3 案出して、選んでもらいます。記事の芯の 1 文 (Phase 2) から作ると外れにくいです。

## タグ

タグは 1 記事あたり 3〜5 個にします。多すぎると逆効果です。3 つの層で構成します。

| 層 | 説明 | 例 |
|---|---|---|
| 主題タグ | 記事のテーマそのもの | エンジニア、個人開発、AI駆動開発 |
| ジャンルタグ | 記事の形式・カテゴリ | エッセイ、イベントレポート、振り返りnote |
| お題タグ | note 公式の募集中のお題に該当する場合 | (公式お題) |

公開済み 44 本のうち 19 本は、タグが 2 個以下でした。ここは伸びしろがあると考えています。3 個を下回らないようにしてください。

note 公式のお題は https://note.com/contests で確認します。

## 画像

- 見出し画像は必ず設定します。有無で PV とスキ数が変わるからです。推奨は 1280×670px です。大きな造形や色面のあるシンプルなデザインが目に留まります
- 本文中の画像は 800 字に 1 枚が目安です。ただし均等には撒かず、密の場所に寄せます。「サクッと作れる楽しさに、飽きた」は、設定項目が増えていく場面に 2 枚、100 案を並べた場面に 2 枚を集めています
- 画像の役割は 3 種類です。①内容の補足 (スクリーンショット、図解)、②空気感の演出 (写真)、③区切りです
- スクリーンショットや図解は、直後の説明文とセットで置きます
- キャプションを付けると、画像が語り出します。公開済み記事では 37 枚にキャプションがあります

## 埋め込み

X のポスト、外部記事、YouTube、Speaker Deck を本文に埋め込めます。公開済み記事の中央値は 1 記事 1 個です。

- 自分のポストを引くと、そのときの熱量がそのまま入ります
- イベントレポートでは connpass ページを埋めると、読者がそのまま辿れます
- 埋め込みは説明の代わりにはなりません。何を見てほしいのかを地の文で書いてから置きます
