# 確かめて直す (Phase 5〜6)

パスは、このスキルのフォルダ (`.claude/skills/writing-note/`) からの相対です。

書き切った原稿を確かめて直します。この段の目的は、素材に無い中身と、強めた留保と、読みにくい文を見つけて直すことだけです。削って短くすることも、言葉を足して厚くすることもしません。

2026-11 の比べでは、書いた直後の原稿のほうが、この段を通した後の原稿より、2 人の採点者のどちらでも点が高かった (2 本とも)。直しすぎると、話者の言葉を戻しすぎて冗長になるか、削りすぎて温度が落ちます。指摘された文だけを、最小の直しで直します。

- 入力: 原稿 (`index.md`)、材料、芯
- 出力: 直した `index.md` と、検査の記録 `check.md`

## 直さないもの

2026-11 の比べでは、規則に沿って削った原稿ほど点が下がりました。次は、検査の指摘があっても消しません。

- 冒頭のフックと、冒頭からタイトルへ戻る線
- 山場の具体 (固有名詞・数字・画像・素の反応)
- 山場での話者の生の言い方 (「やばい、これをもう 1 年やるんだ」「しんど」)。地の文の「〜と思いました」に丸めません。2026-11 の比べで、採点者は 2 人とも、1 位の原稿の弱点に、山場の声を丸めて温度を落としたことを挙げた
- 話者の推量と留保の強さ
- 節そのもの。節が芯を支えていないと見たら、落とす案を `check.md` の「話者に見せる変更」に書きます

## 1. lint

`node tools/notes/cli.mjs lint <名前>` を回します。error は直します。warn と info は読み直す場所の印で、数値を合わせるために文を切る・つなぐ・削ることはしません。字数 (`over-total`・節の予算) も目安です。字数を収めるために、温度のある言葉や具体を削りません (2026-11 の比べで、字数の warn に合わせて 1,547 字を 1,164 字に削った版は、話者の言葉が落ちて点が下がった)。

## 2. 素材と照らす (1 回)

Agent ツールで、会話の文脈を引き継がない新しいサブエージェントを起動し (fork は使いません)、原稿・材料 (話者の言葉)・芯を渡します。頼むのは次の 3 つです。

1. 素材に出どころの無い文 (描写・数字・気持ち・原因・教訓) を、行を引用して挙げる。誤変換を推測で直した語と、素材に無い換算も挙げる
2. 話者の推量や留保を言い切りに強めた所を挙げる
3. 日本語として読みにくい文 (直しのつぎはぎ、主語の入れすぎ、同じ語尾の連続) を引用して挙げる

1 と 2 は直します。直すときは話者の言葉に戻し、足りなければ `<!-- 聞く -->` にします。結びで芯を言い直すときも、話者が言っていない因果 (「〜だから〜だと思います」) にしません。3 は直します。話し言葉の程度の語 (「結構」「ちょっと」) が続く所と、言いさし (「体感なので。」) は、書き言葉に直します。話者が書き手に向けた反応 (「いやー、困るかもしれません」) は本文に入れません。指摘されていない文は直しません。

## 3. 読者の目で読む (1 回)

素材も芯も渡さない読者役のサブエージェントを起動します。渡すのは、`readers.yaml` か `personas/` から選んだ読み手のプロフィールと、原稿の本文だけです。聞くのは次の 4 つです。

1. この記事がいちばん伝えたいことは何だと思ったか (1 文)
2. 読みにくかった文と、誰がどこで何をしている場面か分からなかった段落
3. 目が滑って読み飛ばした段落
4. 人に勧めるなら、どう紹介するか。勧めないなら、なぜか

2 は、誰が何をしている場面か分からない所にだけ、前提か場面の説明を 1 文足します。3 は、読者の目が滑らない記事にするための問いです。読み飛ばされた段落のうち、前の段落の要約や言い換え、一般論だけの文を削ります。固有名詞・数字・話者の言葉の入った文は削りません。1 が芯とずれたら、芯を言う文の位置か節の順を直し、「話者に見せる変更」に書きます。

照合と読者役は 1 回ずつです。直したら lint をもう一度回し、冒頭から 1 回通して読んで継ぎ目を整えます。

## 4. 話者に渡す

`check.md` に次の形で記録します。

```
検査の記録:
- 芯: <合意した 1 文>
- lint: error 0、warn 1 (直さない理由)
- 素材との照合: 指摘 n 件 (直した n、直さない n: 理由)
- 読者役: 芯「〜」、勧め方「〜」、直した段落 n
- 話者に見せる変更: …
```

`<!-- 聞く -->` が残っていれば「聞くことの答え待ち」として渡し、答えが来たら書き直して、この段をもう一度通します。`<!-- 聞く -->` が残っている原稿は、公開の段に進めません。

## 話者の直しと感想を受ける

話者は原稿の画面で段落をその場で直すか、段落を指して話します。指した場所は「指している場所: 段落 3「…」」の形で届きます。話者が直した段落は上書きしません。

聴衆役の感想は、原稿のフォルダの `feedback.yaml` のスレッドに入ります (`para` が段落の番号、`head` が段落の書き出し、記事全体は `"*"`)。`ball: Claude` のスレッドを 1 件ずつ判断します。直すなら `index.md` を直し、`replies` に `thinking` (考えたこと) と `change` (変えたこと) を足して `ball: none`・`closed: 直した` にします。直さないなら `closed: そのままにした` にして、理由を `thinking` に書きます。話者の材料や判断が要るものは `ball: 話者` にします。返事に「直した n 件・見送った n 件」と、見送った理由を書きます。「いちばん伝えたいこと」の答えが芯とずれていたら、段落ではなく構成を疑います。コメントが構成そのものに及ぶなら、構成の段に戻って合意し直します。
