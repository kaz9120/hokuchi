# hokuchi studio

発表資料と note の記事を、AI と一緒に企画から公開まで作るローカルの制作アプリです。作ったものを管理するより、作る過程を支えることを主にします。

```sh
bun run studio           # http://localhost:5300/ にホームを立てる
bun run studio <talk>    # 同じものを立て、そのトークの編集画面の URL も出す (<talk> は名前の先頭か slug)
bun run test:studio      # 振る舞いとファイルの形・API の規則のテスト (偽物の claude で動く)
```

長く動くので、別ターミナルで立ててください。同じプロセスの中で、サイト全体の開発サーバ (http://localhost:5280/) も立てます。`bun run dev` と同じポートを使うので、両方は立てられません。

| 環境変数 | 既定 | 中身 |
|---|---|---|
| `HOKUCHI_PRIVATE` | `~/Hobby/hokuchi-private` | 企画シート・ネタ帳・記事の原稿・社内向けの発表の置き場 (公開リポジトリの外) |
| `HOKUCHI_STUDIO_PORT` | 5300 | studio の画面 |
| `HOKUCHI_SITE_PORT` | 5280 | 中で立てるサイト全体の開発サーバ |

## 考え方

slide:ology、note の本、note 公式の記事は、媒体が違っても同じことを言っていました。studio はこの順序を画面の並びにします。

- 何を言うかが、どう言うかより先で、比重も大きい
- 作る前に、相手と一言を決める。相手は属性ではなく、名前のある 1 人として描く
- 量を出してから捨てる。最初の案を採らない
- 構成ができるまで、本文やスライドに入らない
- 最後に決めるのは人。AI は候補と反論を出し、欄を勝手に書き換えない

使いながら決めたことは次のとおりです。

- 画面には、話者が読む・決める・書くものだけを出す。Claude が実装を合わせるための情報 (絵の作り方・動きの役割・検査) は出さない
- AI との対話は画面に置かない。話者は画面に指摘を書き、Claude Code はファイルを読んで直す。接点はファイルにある
- 1 つの面でする仕事は 1 つにする
- 話者の頭の中にあるのは「KomeKaigi の発表」1 つ。置き場が分かれていても、画面では 1 つの作品として見せる
- 作品の状態は進み具合 (下書き・完成) と公開範囲 (非公開・公開) の 2 つの軸で持つ。人が書くのは進み具合だけで、公開範囲は実物 (サイトに載っているか、note のアーカイブにあるか) から決める。公開から非公開には戻せない。一度出たものは履歴や検索に残るため
- 同じ意味の値の正は 1 つにする。Claude Code と画面が同じファイルを直すので、書き込みは「読んだ版と違えば保存しない」(409) にそろえる
- 公開とデプロイは画面から行わない。手作業とデプロイの確認が要るので、頼み方だけを出す
- 削除はリポジトリの外のごみ箱 (`<HOKUCHI_PRIVATE>/trash/`) に移す。リポジトリの中のファイルは触らない
- 聴衆役の読みは自動で走らせない。画面には「聴衆役の読み」と明記する。AI が演じる聴衆で、本物の聴衆ではない
- 見た目は shadcn/ui のまま中立にし、ブランドの色には乗らない。手触りは骨組み・余白・字の大きさ・動きで出す

## 画面の言葉

画面の言葉は『ユーザーの問題解決とプロダクトの成功を導く エンジニアのためのドキュメントライティング』に沿って書きます。

- 書き手が本や実装で覚えた言葉 (「種」「関門」「中核メッセージ」「粗密」「予算」「slug」「ball」・絶対パス) を、そのまま画面に出さない
- ボタンは、押すと何が起こるかを動詞で言う。造語を作らず、一般的な Web サービスで同じ操作を呼ぶ言葉を選ぶ
- 数には何の数かを付ける。「残り」「未対応」のような主語の無い言葉を使わない
- 「まだ」と「間違い」を分ける。決めていないもの・無いものは灰色で「未定」「未設定」と出す。橙と赤は、話者が決めた値と食い違ったときだけに使う
- 最初に読まれる所に、いちばん大事なことを置く
- 文字は shadcn/ui の既定より一回り大きくする (根の大きさを 112.5%)。文言を足したら、Gemini でも総点検する

| 指すもの | 使う言葉 | 使わない言葉 |
|---|---|---|
| 発表と記事をまとめた呼び名 | 作品 | トーク |
| 絵コンテの単位 | シーン・コマ | 場面・状態 |
| 指摘のスレッド 1 件 | 指摘 (聴衆役のものは感想) | コメント・フィードバック |
| 指摘への操作 | 返信・解決・見送る・戻す | 追記する・取り下げる・未解決に戻す・再開 |
| `ball` | あなた宛て・Claude 宛て (レールでは「Claude へ」) | あなたが答える・Claude の番 |
| 閉じた指摘 | 解決済み (解決・見送り・再読で終了) | 済んだ件 |
| AI が演じる聴衆 | 聴衆役 | 読み手 |
| 作品の状態 | 下書き・完成・完成（社内）・公開・改稿中 | 進み具合と公開範囲の 2 つのバッジ |
| 画面の単位 | 画面・面 (画面の文言では「原稿の画面」のように言う) | タブ |
| 構成の粗密・予算 | 厚く書く・短く通る・目安の字数 | 密・粗・予算 |
| 絵の作り方 | Claude への絵の指示 | 画面の説明 |
| 決まっていない・無い | 未定・未設定・無題 | まだ決めていません・まだありません |
| 保存の表示 | 保存中…・保存済み | 保存しました |
| 原稿の置き場の名前 | 原稿の名前 | slug |

## しくみ

```
server/
  main.ts    起動。画面 (5300)・サイト全体の開発サーバ (5280)・撮影に使うブラウザを立てる
  http/      ルーティングと、薄いハンドラ
  domain/    作品・状態の表 (state.ts)・企画シート・ネタ・指摘・読み・ごみ箱・原稿の名前・作品ごとの購読
  media/     発表と記事の違いを持つ部品。kind の分岐は media/index.ts の 1 か所だけ
  infra/     ファイルの読み書き (版つき)・監視・SSE・claude の呼び出し・撮影・サイト
shared/      画面とサーバで共有する型 (API の契約)
ui/          画面。lib/router.ts がルータ、lib/works.ts が作品ごとのデータの層、work/ が作品の画面の骨組み
test/        振る舞いの固定 (studio.test.ts) と API の規則 (contract.test.ts)
```

- サーバは TypeScript で、Node 22 の型の取り除き (`--experimental-strip-types`) で動かします。ビルドは要りません
- 状態の判定はサーバの状態の表 1 か所で行います。画面は判定を持ちません
- YAML は、人が読めて AI も直せるように、コメントと並びを保って書き戻します
- `claude -p` を呼ぶときは、リポジトリの文脈 (CLAUDE.md) を拾わないよう、一時ディレクトリで起動します
- 新しい部品は `bunx shadcn@latest add <部品>` で足します (`apps/studio` で実行)。CLI が `cn` の読み込み先を `"cn"` と書くことがあるので、`@/lib/utils` に直してください
