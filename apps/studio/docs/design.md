# studio の設計

studio は、発表資料と note の記事を、AI と一緒に企画から公開・振り返りまで作るローカルの制作アプリです。CMS に近いものですが、作ったものを管理するより、作る過程を支えることを主にします。この文書は生きた設計書で、試しながら書き換えます。根拠は `research/` にあり、決定の経緯は ADR-0036・0039・0040・0041・0043・0044・0045・0046・0047 にあります。

## 1. 考え方

3 つの調査 (slide:ology、note の本、note 公式の記事 10 本) は、媒体が違っても同じことを言っていました。

- 何を言うかが、どう言うかより先で、比重も大きい
- 書く・作る前に、相手と一言を決める。相手は属性ではなく、名前のある 1 人として描く
- 量を出してから捨てる。最初の案を採らない
- 構成ができるまで、本文やスライドに入らない
- 最後に決めるのは人。AI と機械は、量を出す・抜けを指摘する・数えて検査する側に回る

studio は、この順序を画面の並びにします。もう 1 つ、使いながら決めたことがあります。

- 画面は、話者が読む・決める・書くものだけを出す。Claude が実装を合わせるための情報 (絵の作り方・動きの役割・検査) は、話者の画面に出さない
- AI との対話は、画面に置かない。話者は画面に指摘を書き、Claude Code はファイルを読んで直す。接点はファイルにある (ADR-0038・0040)
- 1 つの面でする仕事は 1 つにする。読み方の違う仕事を、同じ面に同居させない

## 2. 扱うもの

| もの | 中身 | 置き場 |
|---|---|---|
| 作品 | 発表 1 本、または記事 1 本。企画・絵コンテ・指摘・聴衆役の読みを持つ | 企画シートは `~/Hobby/hokuchi-private/works/<id>/brief.yaml`。`talk` に紐づくトークの slug を、`note` に紐づく記事の slug を書く。完成にした作品は `finishedAt` (押した日時) を持つ |
| トーク | 発表 1 本の絵コンテ・シーン・指摘・読み。公開する発表はリポジトリに、非公開 (社内向け) の発表は外に置く (ADR-0041) | `talks/<トーク>/` か `~/Hobby/hokuchi-private/talks/<トーク>/` |
| 絵コンテ | 章 → シーン → コマ。シーンは「伝えること」と「かける時間」、コマは絵と「話すこと」を持つ | `<トーク>/storyboard.md` |
| 指摘 | 1 件の指摘と、その往復 (スレッド)。話者・聴衆役・Claude のどれが書いたものも同じ形 | `<トーク>/feedback.yaml`、記事は `<原稿>/feedback.yaml` |
| 聴衆役の読み | 読み手が 1 回読んだ結果。アンケート 8 項目・自由記述 2 つ・コマへの感想 | `<トーク>/reads/<番号>.yaml` |
| ペルソナ | 聴衆役の「人」。発表でも記事でも使い回すプリセット | `personas/<id>.yaml` |
| 読み手 | この発表を読んでもらうペルソナと、その「場」(なぜここに来たか) | `<トーク>/readers.yaml` |
| 原稿 | 記事 1 本の本文。段落を単位に、指摘と聴衆役の読みを回す (ADR-0046) | `~/Hobby/hokuchi-private/notes/<slug>/` (`index.md`・`assets/`・`outline.yaml`・`feedback.yaml`・`readers.yaml`・`reads/`) |
| 構成 | 記事の見出しの並びと、見出しごとの粗密・字数の予算・伝えること | `<原稿>/outline.yaml` |
| ネタ | 作品になる前の種 | `~/Hobby/hokuchi-private/seeds/` |

話者の頭の中にあるのは「KomeKaigi の発表」1 つです。置き場が 2 か所 (企画は公開リポジトリの外、絵コンテは中) に分かれているのは実装の都合なので、画面では 1 つの作品として見せます。非公開 (社内向け) の発表は、絵コンテも外に置きます。社内向けの資料が公開リポジトリに入る道を、置き場の段階で断つためです。studio は両方の置き場を読むので、画面での扱いは変わりません (ADR-0041)。

### 作品の状態

作品の状態は、進み具合と公開範囲の 2 つの軸で持ちます (ADR-0045)。話者の頭の中にある「できたか」と「出したか」の区分に揃えています。

| 軸 | 値 | 決め方 |
|---|---|---|
| 進み具合 | 下書き・完成 | 話者が決める。作品の画面の「完成にする」で企画シートに `finishedAt` を書き、「下書きに戻す」で消す。完成しても編集はできる。公開した作品は完成として扱う。ただし、公開済みの記事を改稿している (原稿がある) あいだは下書きとして見せる (ADR-0047) |
| 公開範囲 | 非公開・公開 | 実物から決める。発表はサイトに載るもの (`talks/` の `public: true`)、記事は note のアーカイブ (`articles/note/<公開日>-<slug>/`) にあるもの。それ以外は非公開 |

進み具合は行き来できます。登壇の直前に直す、記事を改稿するといった場面があるためです。公開から非公開には戻せません。一度サイトや note に出たものは、リポジトリの履歴や検索に残るためです (ADR-0043)。非公開の発表は、リポジトリの外に置きます (ADR-0041)。

人が書き込むのは進み具合だけです。公開範囲を企画シートに書かないので、書いた状態と実物がずれません。

## 3. 画面

画面は、ホーム → 作品の画面 → 面、の 2 階層です (ADR-0049)。発表も記事も、公開済みも改稿中も、企画シートの無い作品も、同じ作品の画面で開きます。

```
ホーム ──→ 作品の画面 ┬ 企画          場・聴衆・聞き終えたあと・伝えたいこと (段階 1〜4)
                    ├ 流れ / 構成   全体を見渡して、順序と量 (時間・字数) を決める
                    ├ コマ / 原稿   上から読んで、その場で直し、指摘を書く
                    ├ 読み          聴衆役に読んでもらう
                    └ 公開          通して見る (発表)。タイトル・タグ・見出し画像を決め、note に貼る (記事)
```

記事の面は、発表と同じ骨組み (ADR-0046) で、流れが構成に、コマが原稿に当たります。読みと公開は、発表と同じ名前で同じ役目です。

URL は `/works/<key>#<面>/<場所>` です (`#plan/audience`・`#koma/<シーン>`・`#draft/<段落>`)。key は企画シートの id で、企画シートの無い作品は `talk:<slug>`・`note:<アーカイブ>`・`draft:<原稿>` です。前の `/talks/<slug>`・`/notes/<dir>` は、作品の画面に移します。

### 作品の画面

```
┌ ← 作品一覧   AIに任せられるのは、磨いてきたものだけ                    下書き  ⋯ ┐ 帯
├ 伝えたいこと   ┬──────────────────────────────────────────────────────┤
│ 聴衆           │                                                      │
│ ✓ 企画         │                                                      │
│ ● コマ   98    │   面                                                  │
│    表紙        │                                                      │
│    自己紹介 …  │                                                      │
│ ○ 読み   2 回  │                                                      │
│ あなた宛て 11  │                                                      │
│ Claude へ 45   │                                                      │
│ KomeKaigi あと 11 日                                                  │
└───────────────┴──────────────────────────────────────────────────────┘
```

- 帯は 1 行です。戻る・タイトル・状態・「⋯」だけを置きます。タイトルは省略せず、長ければ折り返します。その場で直せます (公開した作品は読むだけです)
- 左のレールは、上から芯・工程・受け渡し・場の 4 段です。工程の面の行はいつも見えるように固定し、開いている面の子 (目次) だけがスクロールします。受け渡しと場は下に留めます
  - 芯: 伝えたいこと (企画の段階 4) と聴衆 (段階 2 で描いた人。企画シートが無ければ読み手)。企画の面のほかでは、伝えたいことを 2 行、聴衆を「高橋さん ほか 3 人」の 1 行に縮めます。決めていないものは灰色で「未定」と出します。slide:ology がメッセージマップを常に表示させるのと同じ考えです (p.36-37, p.39)
  - 工程: 面の並びで、ナビはこれ 1 つです。各面に数字を 1 つ添えます (流れは合計時間、構成は見出しの数、コマはコマの数、原稿は字数、読みは読んでもらった回数)。開いている面は子を開きます。企画は段階 1〜4、コマはシーン、原稿は見出しです。コマのシーンは章で畳み、読んでいる章だけを開きます。使えない面は灰色にし、理由をホバーで出します (絵コンテの無い発表の流れ、原稿の無い記事の構成など)
  - 受け渡し: あなた宛ての指摘と、Claude へ渡す指摘の件数です。件数はここにだけ出します。「Claude へ」を押すと依頼文をコピーし、ターミナルに貼るよう知らせます
  - 場: イベント・日付・持ち時間・あと何日か。記事は公開日です。企画の意図と実物が食い違うとき (状態の `notices`) は、ここに知らせます
- 面は、面ごとの仕事 1 つに使います (1 章)。どの面も上に同じ形のツールバーを 1 本持ちます。左に面の名前と要約 (合計時間・字数・何回目の読みか など)、右にその面の操作 (読んでもらう・絵の作り方を表示・改稿する など) を置きます
- URL に面が無いとき、使えない面を指しているときは、開ける面の URL に置き換えます (下書きで企画が残っていれば企画、それ以外はコマか原稿)

### 状態の見せ方

状態は、サーバの状態の表 (`server/domain/state.ts`。rebuild.md 4.1) が導きます。画面は判定を持たず、帯にその 1 語をそのまま出します。

| 状態 | 「⋯」に出る操作 |
|---|---|
| 下書き | 完成にする・削除 |
| 完成 (社内向けは「完成（社内）」) | 下書きに戻す・公開の手順 |
| 公開 | 改稿する (記事) |
| 改稿中 | 改稿をやめる |

- 「⋯」には、状態の表がその状態で許す操作だけを出します。どの状態でも「置き場を開く」(Finder で作品のフォルダを開く) を置き、公開した記事には「note で開く」も置きます
- 「完成にする」「下書きに戻す」は、押すとすぐ変わります (戻せるので確かめません)。「公開の手順」は、公開の頼み方を出します。手作業とデプロイの確認が要るので、画面からは公開しません (ADR-0043)
- 削除と「改稿をやめる」は、確かめる文を 1 文で出します。パスは出しません。削除は、企画シートと、リポジトリの外に置いた紐づくトーク・原稿を、ごみ箱 (`<HOKUCHI_PRIVATE>/trash/`) に移します。リポジトリの中のファイルは git の操作が要るので触らず、「リポジトリのファイルは残ります」とだけ添えます。削除のあとはホームに戻ります (ADR-0044・ADR-0045)
- 公開済みの記事は、原稿の面で読むだけの状態として出します。「改稿する」を押すと、同じ面が直せる状態になります (ADR-0047)
- 企画シートの無い作品は、企画の面に「企画シートはありません」と出します。公開済み・改稿中の作品で、何も書いていない企画シート (改稿のときに作ったもの) も同じに見せます

### 画面の土台

- ルータは `ui/lib/router.ts` の 1 つで、パスとハッシュはここでだけ読みます。面の切り替えは履歴に積み、面の中の場所 (読んでいるシーン・段落) は積まずに書き換えます。画面の移動で、ページを読み込み直しません
- 作品のデータは `ui/lib/works.ts` が持ちます。取得・購読 (SSE)・書き込みを 1 か所にまとめます。書き込みは、手元の作品にすぐ映してから送ります (楽観的な更新)。サーバが 409 (読んだ版と違う) を返したら、読み直して「ほかで変更されていたので、保存しませんでした」と知らせます
- 作品が無くなったら (ごみ箱に移したら)、ホームに戻ります

各面で、話者がすることを 1 つに絞ります。

| 面 | 読む | 決める | 書く |
|---|---|---|---|
| ホーム | 発表と記事の一覧と、下書きの次にやること | どれを開くか | ネタ |
| 帯とレール | 状態・伝えたいこと・聴衆・工程・指摘の件数・場 | どの面を開くか・完成にするか | タイトル |
| 企画 | 自分が前に書いたこと | 伝えたいこと (確定する) | 段階ごとの欄 |
| 流れ | 発表全体 (シーンのカードと時間の帯) | 順序と、シーンごとの時間 | シーンの「伝えること」、時間 |
| コマ | 絵と話すこと (上から通して) | このコマはこれでいいか | 話すこと、コマへの指摘 |
| 構成 | 記事全体 (見出しのカードと字数の帯) | 見出しの並びと、どこを密にするか・字数の予算 | 見出し、伝えること、粗密、予算 |
| 原稿 | 本文 (上から通して) と、段落の横の検査結果・指摘 | この段落はこれでいいか | 本文、段落への指摘 |
| 読み | アンケートの結果 | 次に何を直すか | — |
| 受信箱 | あなた宛ての指摘と、届いたばかりの聴衆役の感想 | 返信・解決・見送る、感想を Claude に渡すか | 返信 |
| 公開 (記事) | タイトルの案・タグ・見出し画像・note に貼る本文 | タイトル・タグ・見出し画像 | タイトル、タグ |

### ホーム

上を「いま」、下を「積み上げ」に分けます (話者の決定。rebuild.md 9 章)。vision.md の「ネタ → … → 積み上げる」の両端を、ホームの上下にします。

```
┌ hokuchi studio  [気になったことを書き留める（Enter）]      スライドのサイト  ＋ 作成 ┐
│ いま 5 本      下書き・完成・改稿中のカード                                      │
│ ▸ ネタ 3 件                                                                    │
│ 積み上げ 52 本            [すべて | 発表 | 記事]  [探す]                          │
│   2026年10月 2 本  公開したもののカード                                          │
│   2026年9月 4 本   …                                                            │
└────────────────────────────────────────────────────────────────────────────────┘
```

- 帯: ネタを 1 行で書き留める欄 (Enter で書き留める)・スライドのサイト (本番 `https://slides.y-kaz.com/` を開く)・「＋ 作成」(発表か記事を選ぶメニュー。ADR-0044) を置きます
- いま: 下書き・完成・改稿中です。日が迫っている発表を先に (近い順)、次に作りかけを触った順、完成を最後に並べます。下の「ネタ n 件」は畳んでおき、開くと各ネタを「発表にする」「記事にする」で作品にできます
- 積み上げ: 公開したものを、月で区切って新しい月から並べます。絞り込みは「すべて・発表・記事」と、タイトル・タグ・イベントで探す欄だけです
- カードは 1 種類です。表紙 (発表は表紙のスライド、記事は見出し画像) + 種類 + 状態 1 語 + タイトル + 1 行。表紙の無いものは、伝えたいことを表紙の代わりに大きく出します。1 行は、下書き・完成・改稿中なら「次に: 〜」で、押すとその面が開きます。公開済みは日付とイベントです
- 次にやることは、企画が残っていれば企画、発表は 絵コンテを頼む → あなた宛ての指摘 → 読んでもらう → コマを読む、記事は 原稿を作る → 構成 → 下書きを頼む → あなた宛ての指摘 → 読んでもらう → 公開、の順です。完成は「公開の手順を確かめる」です。改稿中は企画と構成を飛ばします

### 企画 (段階 1〜4)

左に段階、右にその段階の欄です。★ は、人が「確定する」を押して進む段階です。

| 段階 | 発表 | 記事 | 根拠 |
|---|---|---|---|
| 1. 場と素材を集める / 書きたいことを書き出す | 素材・場 (イベント・持ち時間・会場・公開するか) | 出来事・素材・種類 | slide:ology p.32, 39 / けんすう |
| 2. 聴衆を描く / 読者を決める | プロフィールシート: 名前のある聴衆と 7 つの問い | 読者 1 人と、その悩み | slide:ology p.35-37 / 本 p.126-132 |
| 3. 聞き終えたあと / 読み終えたあとを決める | 行動への呼びかけ、聴衆との関係 | 読後感 | slide:ology p.34-35 / 本 p.636 |
| 4. 伝えたいことを 1 文にする ★ | 中核メッセージを 1 文 | 芯を 1 文 | 鈴木・佐伯・本 p.161 |

AI に頼めること (1 文の案を出す、反論を挙げる、など) は、欄の下に小さく置きます。案や意見が出るだけで、欄は書き換わりません。

### 流れ

slide:ology の「ポストイットを壁に貼って並べ替える」(p.48) とメッセージマップ (p.39) に当たる面です。

- 上の帯は、シーンごとの時間を 1 本に並べたものです。章ごとに濃さを変え、持ち時間を超える所に線を引きます。どの章が厚いかと、収まるかが分かります
- カード 1 枚がシーン 1 つです。最初のコマの絵・名前・伝えること・コマの数・時間を出します。伝えることと時間は、その場で直せます
- 時間は、話すことの字数から見積もります (1 分 300 字)。話者が時間を書くと、それを使います (絵コンテの `粗密:` に入ります)。決めた時間と話すことの量が 15 秒以上ずれると、カードに出します
- カードは、章の中で前後に動かせます。章をまたぐ移動、削る、骨組みの案を比べる、はまだありません

### コマ

絵コンテ用紙と同じ、縦の並びです。1 行が 1 コマで、左に絵、真ん中に話すこと、右の余白にそのコマへの指摘を置きます。

- シーンの目次は、レールの「コマ」の子に出します。読んでいるシーンを示し、あなた宛ての指摘があるシーンに数を出します
- 話すことは、その場で直して欄の外を押すと、絵コンテに保存されます
- 絵を押すと、その絵に変わる動きを大きく再生します。← → で前後のコマ、Esc で閉じます
- 絵の作り方 (絵コンテの「画面の説明」) は Claude への指示なので、既定では出しません。絵がまだ無いコマと、レールの下の切り替えを入れたときだけ出します
- 右の余白は、あなた宛ての件・あなたが書いた件・聴衆役の感想 (詰めて表示)・解決済み (畳む) の順です。カードは行の高さを変えずに余白に重ねます (4 章)。「指摘を書く」は行にカーソルを乗せたときだけ出て、何度でも書けます。話す内容でも、スライドの見た目でも、同じ所に書きます

studio という道具そのものへの意見は、右下の agentation で書きます (ADR-0032)。

### 原稿 (記事)

記事の「下書き」を読んで磨く面です (ADR-0046)。発表のコマの面と同じく、上から通して読み、気になった所でその場で直すか、指摘を書きます。

誰が・何を・どう使うか:

- 読むのは話者です。読者と同じ順で本文を頭から読み、「この段落はこれでいいか」を決めます。決め方は 3 つで、その場で直す・指摘を書いて Claude に渡す・そのままにする、です
- 書くのは本文と指摘です。本文は段落の欄を直して欄の外を押すと、`index.md` に書き戻します。front matter (タイトル・タグ) には触りません
- 機械の検査 (`hokuchi-note lint`) は、人の指摘と並べますが、混ぜません。検査は直せば消える目印で、返信も閉じる操作もありません

並べ方:

```
┌ 記事全体: タイトル・字数・段落・文の中央値 ─────┬ 記事全体への検査・指摘 ┐
│ ¶1 本文 (その場で直せる)                       │ ¶1 の検査・指摘        │
│ ## 見出し                                     │                       │
│ ¶2 本文                                        │ ¶2 の検査・指摘        │
└──────────────────────────────────────────────┴───────────────────────┘
```

- 見出し (##・###) の目次は、レールの「原稿」の子に出します。押すとその見出しへ移り、あなた宛ての指摘がある見出しには数を出します
- 真ん中は本文で、段落 1 つが 1 行です。幅は note の本文に近い読みやすさを優先し、コマの面の「話すこと」と同じ大きさの文字にします。見出し・画像・埋め込み・コードも同じ並びに出し、元の Markdown のまま直せます
- 右は、その段落への検査と指摘です。検査が上で、指摘のスレッドが下です。指摘の並べ方 (あなた宛て → Claude 宛て → 聴衆役の感想 → 解決済み) はコマの面と同じです
- いちばん上の帯は記事全体です。段落に寄せられない検査 (ぼかし表現の率・漢字の率・タグの数など) と、記事全体への指摘をここに出します

コマの面との違い:

| | コマ | 原稿 |
|---|---|---|
| 単位 | シーン → コマ | 見出し → 段落 |
| 左の列 | 絵 | (無い。本文を広く取る) |
| 直すもの | 話すこと | 本文そのもの |
| 右の余白 | 指摘 | 検査と指摘 |
| 位置の持ち方 | シーンの id とコマの番号 | 段落の番号と、段落の書き出しの文字列 |

段落の番号は、本文を直すとずれます。指摘は書き出しの文字列も持っているので、番号がずれても書き出しで付け直します。付け直せない指摘は、記事全体への指摘に寄せます。画面で段落を直したときは、その段落の指摘を新しい書き出しで持ち直します。

原稿がまだ無い記事では、この面に「原稿を作成」を置きます。押すと、企画のタイトルを入れた `index.md` を作り、企画シートの `note` に書きます。置き場の名前 (slug。`notes/<slug>/` と、公開後の `articles/note/<公開日>-<slug>/` の名前) は話者に聞かず、企画のタイトルと伝えたいことから、Claude に短い英語の名前を 1 つ付けてもらいます (`claude -p`。45 秒まで待つ)。Claude が失敗したとき・決まりに合わない名前を返したときは、タイトルのかなをローマ字にした名前に落とします (英数字は残し、漢字は落とす。短すぎれば `note-<日付>`)。直したいときは「⋯」の「原稿の名前を変更」で変えます (公開前の原稿だけ)。

### 構成 (記事)

発表の流れに当たる面で、writing-note skill の Phase 3 (フックと骨組み・粗密) を画面にしたものです。本文を書く前に、何をどの順で、どこに力を入れて書くかを決めます。

- 読むのは記事全体の形です。決めるのは、見出しの並びと、どこを密にするかと、見出しごとの字数の予算です
- カード 1 枚が見出し 1 つです。先頭は「冒頭」で、伝えることの欄がフック (冒頭に置く場面) になります。カードには、見出し・伝えること (1 行)・密か粗か・予算・原稿の実際の字数を出し、その場で直せます。前後に並べ替え、足し、消せます
- 上の帯は、発表の流れの時間の帯と同じ考えです。予算の合計と、原稿の実際の字数を並べます。帯は見出しごとの実際の字数で、密は濃く、粗は薄く塗ります。予算の帯も下に並べ、どこが太りすぎたかを見比べます
- 粗密は「中」を作りません (somitsu.md)。密は 2 つまでで、3 つ目を選ぶと知らせます。粗のカードで実際の字数が 150 字を超えたら、カードに出します。密が本文の 3 割に届いていなければ、帯に出します
- 原稿の見出し (##) と構成の見出しが食い違ったら、帯の下に出します (「原稿に無い見出し」「構成に無い見出し」)。「原稿の見出しを取り込む」で、構成に足りない見出しを足せます
- 保存先は `<原稿>/outline.yaml` です。Claude Code も同じファイルを読んで書きます

### 読み

slide:ology の「同僚に見せて、要点を押さえているかを評価してもらう」(p.54) に当たる面です。記事も同じ面を使い、絵コンテの代わりに原稿を読んでもらいます。

- 「読んでもらう」を押すと、読み手がいまの絵コンテを読みます。読み手は毎回まっさらで、渡すのはペルソナ・場・絵コンテの画面と話すことだけです。数分かかります。自動では読ませません
- アンケートは 8 項目で、5 段階と理由 1 行です。行を選ぶと、その項目に付けた理由が読めます。最初は、いちばん点の低い項目を開いておきます。2 回目からは、前回との差を出します
- 「いちばん伝えたかったことは何だと思ったか」を、話者の「伝えたいこと」と並べます
- あなた宛ての指摘は、この面には置きません。受信箱で裁きます (4 章)。読み終えると受信箱が開き、聴衆役の感想をまとめて扱えます

画面には「聴衆役の読み」と明記します。AI が演じる聴衆で、本物の聴衆ではありません。

読んでもらう人は、発表も記事も、読みの面の先頭で同じ形で選びます。選べるのは、企画の段階 2 で描いた人 (聴衆の正。rebuild.md 4.2) と、`personas/` のプリセットです。企画で描いた人は `readers.yaml` に `persona: brief:<名前>` と書き、中身は企画シートから読みます。同じ名前のプリセットがあれば、そのプリセットが演じます。まだ誰も選んでいなければ、企画で描いた人を選んだ状態から始めます。記事の読み手は「note で記事を見つけて読みに来た」人として、段落の番号の付いた本文を読みます。感想は段落を単位に返り、指摘のスレッドに入ります。

### 公開 (発表・記事)

発表も記事も、確かめる項目を上から順に並べ、最後に依頼文をコピーする型にします。項目には「済み」「まだ」(灰色) 「食い違い」(橙) を出し、まだのものを赤くしません。

- 発表: 通しで再生 → 表紙の絵 (OGP) → 公開するか (企画の意図と、いまの置き場) → 公開を頼む依頼文。社内向けと公開済みの発表は、依頼文を出しません
- 記事: タイトル → タグ → 見出し画像 → note に貼る (本文をコピー) → 取り込みを頼む依頼文

企画の最後 (段階 4) には、発表は「Claude Code に絵コンテを頼む」、記事は「Claude Code に下書きを頼む」の依頼文のコピーを、同じ場所に置きます。記事で原稿がまだ無ければ、先に原稿を作ってから依頼文をコピーします。

### 公開 (記事) の項目

note に出すための最後の面です。決めるのはタイトル・タグ・見出し画像で、作業は note に貼る本文のコピーです。

- タイトル: 原稿の frontmatter の `title` が正です。原稿があるあいだは、作品の画面の上のタイトルも原稿のタイトルを読み書きし、企画シートの `title` も同じ値に揃えます。「タイトルの案を出す」で、Claude が原稿を読んで 3 案を出します。案を選ぶとタイトルに入ります
- タグ: 3〜5 個です (structure.md)。外れると知らせます
- 見出し画像: 1280×670 の画像を原稿の `assets/` に置くよう案内します。置いた画像は一覧に出て、選ぶと frontmatter の `eyecatch` に入ります。大きさが違えば知らせます
- note に貼る: 「本文をコピー」で、`tools/notes` の paste と同じ本文 (画像行は「（画像 n/N: …）」の 1 行に置き換え) をクリップボードに入れます。画像を入れる位置と、ファイルの一覧を並べます
- 公開したら: note で公開 (改稿なら更新) したあと、取り込み (`sync`) を Claude Code に頼む依頼文をコピーできます。取り込みが済んだら、原稿は Claude Code が trash に移します

### 改稿 (ADR-0047)

公開済みの記事は、原稿の面で読むだけの状態として開きます。「改稿する」(面の上と「⋯」) で、アーカイブの `index.md` と `assets/` を `<HOKUCHI_PRIVATE>/notes/<slug>/` に写します。frontmatter には `revises: <アーカイブのディレクトリ名>` を残します。企画シートが無ければ作り、`note` に slug を書いて紐づけ、同じ原稿の面が直せる状態になります。アーカイブは読むだけで、書き換えません。同じ記事を改稿中なら、その原稿を開きます。

改稿をやめるときは、作品の画面の「⋯」の「改稿をやめる」を押します (ADR-0048)。改稿の原稿だけを `<HOKUCHI_PRIVATE>/trash/<日時>-revise-<slug>/` に移し、企画シートは残します。note の記事とアーカイブは変わらず、カードは「公開」に戻ります。

## 4. 指摘のスレッド

1 件の指摘と、その往復を 1 本にします。見るのは 2 つだけです。

| 項目 | 値 | 意味 |
|---|---|---|
| `ball` | 話者 / Claude / none | いま誰が動く番か |
| `closed` | 直した / そのままにした / 良かった点 / 読み直した | 済んだ件の終わり方 |

画面の言葉は、`ball: 話者` が「あなた宛て」、`ball: Claude` が「Claude 宛て」です。`closed` は、直した が「解決」、そのままにした が「見送り」、読み直した が「再読済み」と出ます。

指摘の導線は 1 本です。余白で書き、受信箱で裁き、レールから 1 手で渡します (rebuild.md 6 章)。

- 書く: コマ・段落・シーン・記事全体の余白です。行にカーソルを乗せたときだけ「指摘を書く」が出て、その場の欄に書いて Enter で送ります (Claude の番になる)。指摘のカードは行の高さを変えません。Google ドキュメントのコメントと同じく、行の右の余白に重ね、前のカードと重なるときだけ下にずらします
- 裁く: レールの「あなた宛て」を押すと、どの面からでも右から受信箱が開きます。1 件ずつ出し、動詞は「返信」「解決」「見送る」の 3 つです。押すとその件は受信箱から外れ、次の件に進みます。済んだ件には「戻す」だけを置きます。Claude の番の件の「返信」は追記に、自分が書いた件の「見送る」は取り下げに当たります。状態は選びません
- 渡す: レールの「Claude へ」を押すと、依頼文をコピーします。依頼文は「feedback.yaml に Claude の番の指摘が n 件ある。〜 skill の Phase に従って直して」の 2 行だけにし、直し方と feedback.yaml の書き方は skill の側に書きます
- Claude ができるのは 3 つです。直して閉じる、直さずに閉じる、話者に確かめる (話者の番にする)。`replies` に、考えたこと (`thinking`) と変えたこと (`change`) を足します
- 聴衆役の感想は、読みを取り込むときにスレッドになり、Claude の番から始まります。読み終えたら受信箱が開き、先頭の 1 行「聴衆役から n 件」で、話者がまとめて「Claude に渡す」(依頼文をコピー) か「見送る」(そのままにした で閉じる) を選びます。「中身を見る」で 1 件ずつ読めます。目を通した印はブラウザの手元にだけ持ち、feedback.yaml の形と `ball`・`closed` の値は変えません
- 良かった点は、済んだ件として残します。次に読んでもらうと、Claude の番のまま残っていた聴衆役の感想は「読み直した」で閉じます。話者の番の件は残ります
- 読みの面は、読んでもらうこととアンケートだけにします。指摘の一覧は受信箱にあります

## 5. 聴衆役のアンケート

項目は、聴衆を知る 7 つの問い (slide:ology p.35) を裏返したものと、うまくいったかの見分け方 (p.269) から作っています。調査は `research/audience-survey.md` にあります。

| 群 | 項目 |
|---|---|
| 届いたか | 得に来たものを得られた / 自分の悩みに触れていた / 新しい見方を得た |
| 分かったか | 話の筋を最後まで追えた / 画面はひと目で分かった |
| 動くか | 主張に納得した / 明日やってみようと思うことがある |
| 総合 | 同じ立場の人に勧めたい |

記事は、同じ意図の 8 項目を記事の言葉に置き換えます。発表の「画面はひと目で分かった」は、記事では「冒頭で読み進めたくなった」です。記事の読み手は、画面ではなく冒頭で離れるかどうかが決まるからです (writing-note Phase 3「フックを見つける」)。

| 群 | 項目 (記事) |
|---|---|
| 届いたか | 読みに来た目的を果たせた / 自分の悩みに触れていた / 新しい見方を得た |
| 分かったか | 最後まで迷わずに読めた / 冒頭で読み進めたくなった |
| 動くか | 主張に納得した / 読み終えて、やってみようと思うことがある |
| 総合 | 同じ立場の人に勧めたい |

ペルソナは「人」と「場」に分けます。人 (どんな人か・悩み・知っていること・引っかかりやすい点・話し手を知っているか) は `personas/` のプリセットで、発表でも記事でも使い回します。場 (なぜここに来たか) は `readers.yaml` に、作品ごとに書きます。

## 6. 画面の言葉

画面の言葉は、`ユーザーの問題解決とプロダクトの成功を導く エンジニアのためのドキュメントライティング` に沿って書きます。

- 知識の呪いを避ける。書き手 (Claude) が本や実装で覚えた言葉 (「種」「関門」「中核メッセージ」「状態」「粗密」「未対応」) を、そのまま画面に出さない。本を読んでいない人が、読んですぐ分かる言葉にする
- ボタンは、押すと何が起こるかを動詞で言う (「最初から再生」「読んでもらう」「依頼文をコピー」)。造語を作らず、一般的な Web サービスで同じ操作を呼ぶ言葉を選ぶ (「完成にする」「下書きに戻す」「追加」「送信」「キャンセル」)。用語は「作品・発表・記事」「シーン・コマ」「指摘・感想・返信」「あなた宛て・Claude 宛て・解決済み」に揃える
- 数には、何の数かを付ける (「あなた宛ての指摘 11 件」)。「残り」「未対応」のような、主語の無い言葉を使わない
- 絵コンテの単位は、シーンとコマで呼ぶ。「場面」は使わない。実装の言葉 (状態・トーク) は出さない
- 最初に読まれる所に、いちばん大事なことを置く。段階の冒頭に「やること」、その下に「なぜやるのか」、欄ごとに「何を書くか」と「例」を出す
- 例は、話者の過去の作品から引けるものは引く。作品に無い例は、ただの「例」として書く
- 本の考え方を言い換えたときは、出典を添える
- 文字は、shadcn/ui の既定より一回り大きくする (根の大きさを 112.5%)

## 7. 技術

- UI は shadcn/ui をそのまま使う (Tailwind v4)。studio は管理画面なので、hidoko のデザインシステムには乗らない。画面の系統は 1 つにする
- 絵コンテの読み書きは `packages/stage/node/storyboard.mjs` が持つ。話すこと (`replaceNotes`)、シーンの情報 (`replaceSceneMeta`)、並び (`moveScene`) を、Markdown のまま書き換える
- 指摘は `threads.mjs`、聴衆役の読みは `readers.mjs` が持つ。YAML は、人が読めて AI も直せるように、文書のまま開いてコメントと並びを保って書き戻す
- 聴衆役は `claude -p` の単発の依頼で、答えを JSON で受け取る。リポジトリの文脈 (CLAUDE.md) を拾わないよう、一時ディレクトリで起動する
- 発表の絵と再生は、サイト全体の開発サーバ (`apps/slides/site-server.mjs`) を使う。studio が中で立てる。トークは起動時に拾うので、トークを足したら studio を起動し直す
- studio は `startSite` に `<HOKUCHI_PRIVATE>/talks/` を足して渡し、非公開のトークも読む。そこのトークは非公開として扱い、開発サーバの一覧には非公開の印付きで出る。`bun run dev` とサイトの組み立て (`apps/slides/build.mjs`) は、`talks/` だけを読む (ADR-0041)
- 画面と Claude への依頼文に出すトークの場所は、リポジトリの中なら相対パス、外なら絶対パスにする
- 作品の面と場所は URL のハッシュに持つ (`/works/<key>#koma/<シーン>`・`/works/<key>#draft/<段落>`)。agentation のメモが場所ごとに分かれる
- 原稿の読み書きは `draft.mjs` が持つ。本文を空行で段落に分け (コードの囲みは 1 つにまとめる)、段落の位置で書き換える。保存のときは、画面が読んだときの段落と今の段落が同じかを確かめ、違えば保存しない (Claude Code が同時に直したときに上書きしないため)
- 構成は `<原稿>/outline.yaml` に、見出しごとに `title`・`point` (伝えること)・`grain` (密 / 粗)・`budget` (字) を並べる。原稿の実際の字数は、見出し (##) で区切った地の文の字数 (空白を除く)
- 聴衆役の読みは `readers.mjs` が発表と記事の両方を持つ。記事のアンケートの項目と依頼文は、記事用に置き換える (5 章)
- note に貼る本文は `tools/notes/src/paste.mjs` の `toPasteText` を使う
- 原稿の検査は `tools/notes/src/lint.mjs` の `lintDraft` をそのまま使う。検査結果の `at` (本文の抜粋) を含む段落に寄せ、寄せられないものは記事全体に出す

## 8. まだ無いもの

- 流れの面で、シーンを削る・章をまたいで動かす・骨組みの案を比べる (段階 5 の「案を出して絞る」)
- 段階 2 で描く聴衆と、読み手 (readers.yaml) をつなぐこと。読み手を画面で選ぶこと
- 公開の面の中身 (公開の可否・OGP・リハーサルと当日の振り返り)。声の録音と、動画の書き出し。音声はリポジトリの外に置く
- 記事の読み手の「なぜ読みに来たか」を、画面で書くこと。いまは選んだペルソナだけで読む
- 構成の案を AI に出してもらうこと (骨組みの案を比べる)。いまは話者と Claude Code が outline.yaml を書く
- 作品を公開するときに、置き場からリポジトリへ移す手順
- 一覧が長くなり、下書きが埋もれたときの畳み方 (年で畳むなど。ADR-0043 の見直しの条件)
- ごみ箱を空にする操作と、ごみ箱から戻す操作。いまは `<HOKUCHI_PRIVATE>/trash/` から手で戻す (ADR-0044 の見直しの条件)
- 聴衆役の読みに、人に見せた反応と当日の反応を並べること
