# studio の設計

studio は、発表資料と note の記事を、AI と一緒に企画から公開・振り返りまで作るローカルの制作アプリです。CMS に近いものですが、作ったものを管理するより、作る過程を支えることを主にします。この文書は生きた設計書で、試しながら書き換えます。根拠は `research/` にあり、決定の経緯は ADR-0036・0039・0040 にあります。

## 1. 考え方

3 つの調査 (slide:ology、note の本、note 公式の記事 10 本) は、媒体が違っても同じことを言っていました。

- 何を言うかが、どう言うかより先で、比重も大きい
- 書く・作る前に、相手と一言を決める。相手は属性ではなく、名前のある 1 人として描く
- 量を出してから捨てる。最初の案を採らない
- 構成ができるまで、本文やスライドに入らない
- 最後に決めるのは人。AI と機械は、量を出す・抜けを指摘する・数えて検査する側に回る

studio は、この順序を画面の並びにします。もう 1 つ、使いながら決めたことがあります。

- 画面は、話者が読む・決める・書くものだけを出す。Claude が実装を合わせるための情報 (絵の作り方・動きの役割・検査) は、話者の画面に出さない
- AI との対話は、画面に置かない。話者は画面に指摘を書き、Claude Code はファイルを読んで直す。接点はファイルにある (ADR-0038・0040)
- 1 つの面でする仕事は 1 つにする。読み方の違う仕事を、同じ面に同居させない

## 2. 扱うもの

| もの | 中身 | 置き場 |
|---|---|---|
| 作品 | 発表 1 本、または記事 1 本。企画・絵コンテ・指摘・聴衆役の読みを持つ | 企画シートは `~/Hobby/hokuchi-private/works/<id>/brief.yaml`。`talk` に、紐づくトークの slug を書く |
| 絵コンテ | 章 → シーン → コマ。シーンは「伝えること」と「かける時間」、コマは絵と「話すこと」を持つ | `talks/<トーク>/storyboard.md` |
| 指摘 | 1 件の指摘と、その往復 (スレッド)。話者・聴衆役・Claude のどれが書いたものも同じ形 | `talks/<トーク>/feedback.yaml` |
| 聴衆役の読み | 読み手が 1 回読んだ結果。アンケート 8 項目・自由記述 2 つ・コマへの感想 | `talks/<トーク>/reads/<番号>.yaml` |
| ペルソナ | 聴衆役の「人」。発表でも記事でも使い回すプリセット | `personas/<id>.yaml` |
| 読み手 | この発表を読んでもらうペルソナと、その「場」(なぜここに来たか) | `talks/<トーク>/readers.yaml` |
| ネタ | 作品になる前の種 | `~/Hobby/hokuchi-private/seeds/` |

話者の頭の中にあるのは「KomeKaigi の発表」1 つです。置き場が 2 か所 (企画は公開リポジトリの外、絵コンテは中) に分かれているのは実装の都合なので、画面では 1 つの作品として見せます。

## 3. 画面

```
ホーム ──→ 作品 ┬ 企画   場・聴衆・聞き終えたあと・伝えたいこと (段階 1〜4)
               ├ 流れ   発表全体を見渡して、順序と時間を決める
               ├ コマ   絵コンテを読んで、話すことを直し、指摘を書く
               ├ 読み   聴衆役に読んでもらい、指摘に答える
               └ 公開   通して見る。公開・振り返り (これから)
```

作品の画面の上には、「伝えたいこと」と「聴衆」を出し続けます。slide:ology がメッセージマップを常に表示させ、聴衆のプロフィールを資料の冒頭に置くのと同じ考えです (p.36-37, p.39)。聴衆は名前を押すと、どんな人か・悩み・なぜここにいるかが開きます。右端には「Claude に渡す指摘 n 件」が出ます。

各面で、話者がすることを 1 つに絞ります。

| 面 | 読む | 決める | 書く |
|---|---|---|---|
| ホーム | 作っているものと、次にやること | どれを開くか | ネタ |
| 企画 | 自分が前に書いたこと | 伝えたいこと (この内容で確定する) | 段階ごとの欄 |
| 流れ | 発表全体 (場面のカードと時間の帯) | 順序と、場面ごとの時間 | 場面の「伝えること」、時間 |
| コマ | 絵と話すこと (上から通して) | このコマはこれでいいか | 話すこと、コマへの指摘 |
| 読み | アンケートの結果と、あなたが答える指摘 | 指摘にどう答えるか | 返事 |

### ホーム

「作っているもの」「ネタ帳」「公開したもの」の 3 つです。作品のカードは、いまの様子と「次にやること」を言います。次にやることは、企画が残っていれば企画、絵コンテがあれば、答える指摘 → 読んでもらう → コマを読む、の順で決めます。作っている途中の発表は、「公開したもの」には出しません。

### 企画 (段階 1〜4)

左に段階、右にその段階の欄です。★ は、人が「この内容で確定する」を押して進む段階です。

| 段階 | 発表 | 記事 | 根拠 |
|---|---|---|---|
| 1. 場と素材を集める / 書きたいことを書き出す | 素材・場 (イベント・持ち時間・会場・公開するか) | 出来事・素材・種類 | slide:ology p.32, 39 / けんすう |
| 2. 聴衆を描く / 読者を決める | プロフィールシート: 名前のある聴衆と 7 つの問い | 読者 1 人と、その悩み | slide:ology p.35-37 / 本 p.126-132 |
| 3. 聞き終えたあと / 読み終えたあとを決める | 行動への呼びかけ、聴衆との関係 | 読後感 | slide:ology p.34-35 / 本 p.636 |
| 4. 伝えたいことを 1 文にする ★ | 中核メッセージを 1 文 | 芯を 1 文 | 鈴木・佐伯・本 p.161 |

AI に頼めること (1 文の案を出す、反論を挙げる、など) は、欄の下に小さく置きます。案や意見が出るだけで、欄は書き換わりません。

### 流れ

slide:ology の「ポストイットを壁に貼って並べ替える」(p.48) とメッセージマップ (p.39) に当たる面です。

- 上の帯は、場面ごとの時間を 1 本に並べたものです。章ごとに濃さを変え、持ち時間を超える所に線を引きます。どの章が厚いかと、収まるかが分かります
- カード 1 枚がシーン 1 つです。最初のコマの絵・名前・伝えること・コマの数・時間を出します。伝えることと時間は、その場で直せます
- 時間は、話すことの字数から見積もります (1 分 300 字)。話者が時間を書くと、それを使います (絵コンテの `粗密:` に入ります)。決めた時間と話すことの量が 15 秒以上ずれると、カードに出します
- カードは、章の中で前後に動かせます。章をまたぐ移動、削る、骨組みの案を比べる、はまだありません

### コマ

絵コンテ用紙と同じ、縦の並びです。1 行が 1 コマで、左に絵、真ん中に話すこと、右の余白にそのコマへの指摘を置きます。

- 左のレールは目次です。あなたが答える指摘があるシーンに、数を出します
- 話すことは、その場で直して欄の外を押すと、絵コンテに保存されます
- 絵を押すと、その絵に変わる動きを大きく再生します。← → で前後のコマ、Esc で閉じます
- 絵の作り方 (絵コンテの「画面の説明」) は Claude への指示なので、既定では出しません。絵がまだ無いコマと、レールの下の切り替えを入れたときだけ出します
- 右の余白は、あなたが答える件・あなたが書いた件・聴衆役の感想 (詰めて表示)・済んだ件 (畳む) の順です。「このコマに指摘を書く」は何度でも押せます。話す内容でも、スライドの見た目でも、同じ所に書きます

studio という道具そのものへの意見は、右下の agentation で書きます (ADR-0032)。

### 読み

slide:ology の「同僚に見せて、要点を押さえているかを評価してもらう」(p.54) に当たる面です。

- 「読んでもらう」を押すと、読み手がいまの絵コンテを読みます。読み手は毎回まっさらで、渡すのはペルソナ・場・絵コンテの画面と話すことだけです。数分かかります。自動では読ませません
- アンケートは 8 項目で、5 段階と理由 1 行です。行を選ぶと、その項目に付けた理由が読めます。最初は、いちばん点の低い項目を開いておきます。2 回目からは、前回との差を出します
- 「いちばん伝えたかったことは何だと思ったか」を、話者の「伝えたいこと」と並べます
- その下に「あなたが答える指摘」の一覧があります。答えるか、閉じるかを、ここで済ませられます

画面には「聴衆役の読み」と明記します。AI が演じる聴衆で、本物の聴衆ではありません。

## 4. 指摘のスレッド

1 件の指摘と、その往復を 1 本にします。見るのは 2 つだけです。

| 項目 | 値 | 意味 |
|---|---|---|
| `ball` | 話者 / Claude / none | いま誰が動く番か |
| `closed` | 直した / そのままにした / 良かった点 / 読み直した | 済んだ件の終わり方 |

画面の言葉は、`ball: 話者` が「あなたが答える」、`ball: Claude` が「Claude が直す」です。

- 話者ができるのは 3 つです。書く (Claude の番になる)、答える (Claude の番になる)、閉じる (「これでいい」は直した、「直さなくていい」はそのままにした)。状態は選びません
- Claude ができるのも 3 つです。直して閉じる、直さずに閉じる、話者に確かめる (話者の番にする)。`replies` に、考えたこと (`thinking`) と変えたこと (`change`) を足します
- 聴衆役の感想は、読みを取り込むときにスレッドになり、Claude の番から始まります。良かった点は、済んだ件として残します。次に読んでもらうと、Claude の番のまま残っていた聴衆役の感想は「読み直した」で閉じます。話者の番の件は残ります
- Claude へは、上の帯の「Claude に渡す指摘 n 件」から渡します。依頼文は「feedback.yaml に Claude の番の指摘が n 件ある。読んで直して」という短い文で、ターミナルの Claude Code に貼ります

## 5. 聴衆役のアンケート

項目は、聴衆を知る 7 つの問い (slide:ology p.35) を裏返したものと、うまくいったかの見分け方 (p.269) から作っています。調査は `research/audience-survey.md` にあります。

| 群 | 項目 |
|---|---|
| 届いたか | 得に来たものを得られた / 自分の悩みに触れていた / 新しい見方を得た |
| 分かったか | 話の筋を最後まで追えた / 画面はひと目で分かった |
| 動くか | 主張に納得した / 明日やってみようと思うことがある |
| 総合 | 同じ立場の人に勧めたい |

ペルソナは「人」と「場」に分けます。人 (どんな人か・悩み・知っていること・引っかかりやすい点・話し手を知っているか) は `personas/` のプリセットで、発表でも記事でも使い回します。場 (なぜここに来たか) は `readers.yaml` に、作品ごとに書きます。

## 6. 画面の言葉

画面の言葉は、`ユーザーの問題解決とプロダクトの成功を導く エンジニアのためのドキュメントライティング` に沿って書きます。

- 知識の呪いを避ける。書き手 (Claude) が本や実装で覚えた言葉 (「種」「関門」「中核メッセージ」「状態」「粗密」「未対応」) を、そのまま画面に出さない。本を読んでいない人が、読んですぐ分かる言葉にする
- ボタンは、押すと何が起こるかを動詞で言う (「最初から通して見る」「読んでもらう」「依頼文をコピー」)
- 数には、何の数かを付ける (「あなたが答える指摘 11 件」)。「残り」「未対応」のような、主語の無い言葉を使わない
- 絵コンテの単位は、シーン (場面) とコマで呼ぶ。実装の言葉 (状態) は出さない
- 最初に読まれる所に、いちばん大事なことを置く。段階の冒頭に「やること」、その下に「なぜやるのか」、欄ごとに「何を書くか」と「例」を出す
- 例は、話者の過去の作品から引けるものは引く。作品に無い例は、ただの「例」として書く
- 本の考え方を言い換えたときは、出典を添える
- 文字は、shadcn/ui の既定より一回り大きくする (根の大きさを 112.5%)

## 7. 技術

- UI は shadcn/ui をそのまま使う (Tailwind v4)。studio は管理画面なので、hidoko のデザインシステムには乗らない。画面の系統は 1 つにする
- 絵コンテの読み書きは `packages/stage/node/storyboard.mjs` が持つ。話すこと (`replaceNotes`)、シーンの情報 (`replaceSceneMeta`)、並び (`moveScene`) を、Markdown のまま書き換える
- 指摘は `threads.mjs`、聴衆役の読みは `readers.mjs` が持つ。YAML は、人が読めて AI も直せるように、文書のまま開いてコメントと並びを保って書き戻す
- 聴衆役は `claude -p` の単発の依頼で、答えを JSON で受け取る。リポジトリの文脈 (CLAUDE.md) を拾わないよう、一時ディレクトリで起動する
- 発表の絵と再生は、サイト全体の開発サーバ (`apps/slides/site-server.mjs`) を使う。studio が中で立てる。トークは起動時に拾うので、トークを足したら studio を起動し直す
- 作品のタブと場所は URL のハッシュに持つ (`/works/<id>#koma/<シーン>`)。agentation のメモが場所ごとに分かれる

## 8. まだ無いもの

- 流れの面で、シーンを削る・章をまたいで動かす・骨組みの案を比べる (段階 5 の「案を出して絞る」)
- 段階 2 で描く聴衆と、読み手 (readers.yaml) をつなぐこと。読み手を画面で選ぶこと
- 公開の面の中身 (公開の可否・OGP・リハーサルと当日の振り返り)。声の録音と、動画の書き出し。音声はリポジトリの外に置く
- 記事 (note) の、構成から先の面。コマを段落に置き換えて、同じ流れに乗せる
- 公開済みの記事の改稿の手順
- 作品を公開するときに、置き場からリポジトリへ移す手順
- 聴衆役の読みに、人に見せた反応と当日の反応を並べること
