## 結論

「つぎはぎ感」の正体は、画面の見た目より、骨組みの不在です。作品の画面は、上の帯 2 段に 15 種の要素を詰め、面ごとに別の左レールを持ち、指摘の入口と数字が 3 か所に散っています。発表と記事は同じタブの名前を使いながら、読み手の選び方・原稿の作り方・公開の面の型が別物です。

作り直すなら、次の 3 つを先に決めると、残りはついてきます。

1. 作品の画面の骨組みを 1 つにする。上の帯は 1 行（戻る・タイトル・状態・メニュー）、左レールに「芯・工程・受け渡し」をまとめ、面の中身は右に広く取る。企画の 4 段階もレールに吸収し、ナビを 1 層にする
2. 指摘の導線を 1 本にする。書く場所は余白（コマ・段落）だけ、裁く場所は「あなた宛て」の受信箱だけ、渡す場所はレールの「Claude に渡す」だけ。数字は「あなた宛て n / Claude 宛て m」の 1 組に揃える
3. 発表と記事の作法を揃える。読み手は両方で画面から選ぶ、原稿は slug を聞かずにタイトルから作る、公開の面は「確かめる → 出す → 取り込みを頼む」の同じ型にする

## 1. 画面ごとの棚卸し

### 1.1 ホーム [01][02][03][80]

迷う・手数が多い

- 絞り込みが 3 組（種類・進み具合・公開範囲）あり、「すべて (55)」が 3 回並びます。55 件のうち 52 件が公開済みの記事なので、話者が毎日見たいのは「作りかけ 3 件」だけです。絞り込みは「すべて / 発表 / 記事」1 組で足ります
- カードが 3 種類あります（下書きの作品・企画の無い発表・完成の表紙）。1 行目に文字のカード 3 枚、2 行目から表紙のカードが並び、同じ一覧に見えません [01]
- 完成した非公開の発表（社内勉強会）は、表紙の絵が来るまで空白のカードです [01]。開いた直後に何が無いのか分かりません
- ネタ帳が最上段に固定で、ネタが 0 件でも入力欄 2 つとボタンが場所を取ります。毎日開く画面の最初の 1 画面の 1/4 がネタ帳です
- 改稿中の記事のカードが「伝えたいことは未定」「次にやること: 聴衆役に読んでもらう」と出ます [80]。公開済みの記事の改稿に企画の芯は無いので、改稿の文脈では空欄の指摘が的外れです

言葉・配置

- 「サイトを開く」は本番のスライドのサイトだけを開きます。記事の一覧も並ぶ画面で「サイト」が何を指すかが曖昧です
- 画面の下に、置き場の絶対パスを常に出しています [03]。初回だけ知れば足りる情報です
- 右下に agentation のボタンが常にあります。道具への意見を書く入口が、作品の画面と同じ重さで出ています

### 1.2 作品の画面の上の帯（発表・記事で共通）[10][25][30][50][61]

ここが「つぎはぎ」のいちばん濃い場所です。

- 1 段目に 9 要素（ホーム・種類・進み具合・公開範囲・タイトル・イベント・日付・持ち時間・保存状態）、右にタブ 5 つと操作 2 つ。2 段目に「伝えたいこと」「聴衆 6 人のチップ」「Claude に渡す指摘 45 件」。合計 15 種類の要素が 2 行に詰まっています
- 1440 幅でタイトルが「AIに任せられるのは、磨いて…」に切れ、1280 幅では「AIに任」の 3 文字になります [25]。いま開いている作品の名前が読めません
- タブが帯の右端に寄り、ナビとしての存在感が薄い。企画タブの中だけ左に段階の目次（1〜4）が出るので、ナビが 2 層（上の帯のタブ + 左の段階）になります。流れ・コマの面に移ると左レールの中身がシーンの目次に変わり、「段階」は見えなくなります
- 数字が 2 種類あります。「読み」タブのバッジは「あなた宛て 11 件」、2 段目の右端は「Claude に渡す指摘 45 件」。同じ「指摘」の数が、別の意味で、別の場所に、説明なく出ています [10]
- 2 段目の高さが作品によって変わります。記事で原稿が無いときは「伝えたいこと 未定」だけで、右の「Claude に渡す」が消えて帯が細くなります [50][54]
- 状態の操作が作品ごとに違う場所・違う形で出ます。下書きは「完成にする」+「削除」、完成は「下書きに戻す」+「公開の手順」（情報アイコン）、改稿中は「改稿をやめる」だけ。公開済みは何も出ません。「公開の手順」は押すと説明文の吹き出しが開くだけで、操作ではありません [31]
- 「削除」「改稿をやめる」の吹き出しに、ごみ箱の絶対パスが 3 行分出ます [24][69]。確かめる文の中で、パスは読まれません
- 保存状態（保存中…／保存済み）がタイトルの横に小さく出ますが、コマ・原稿の面では各欄の下に「未保存です。欄の外を押すと保存します」と別の方式で出ます。保存の知らせ方が 2 通りです

### 1.3 企画（段階 1〜4）[10][11][12][13][14][50][51]

- 段階の目次が 4 行だけで、左レール 260px の大半が空です。レールの価値に対して幅が広すぎます
- 各段階の冒頭に「企画 n / 4」「見出し」「やること」「なぜやるのか（出典つき）」が毎回出ます。2 回目からは読まないので、折りたためる方が本文に早く着きます
- 聴衆のチップを押すと、どんな人か・悩み・なぜ・引っかかりが吹き出しで読めます [14]。良い作りですが、企画の段階 2 で書いたペルソナ（brief.yaml の personas）と、読み手（readers.yaml）が別物で、帯のチップは readers.yaml の方です。段階 2 で「高橋さん」を書いても、読み手に自動では入りません（design.md「まだ無いもの」）
- 記事の企画では、聴衆のチップが出ません。段階 2 の「誰に届けたいですか」は帯に反映されず、帯は「伝えたいこと 未定」の 1 項目になります [50]
- 「確定する」の後に「2026-10-12 に確定済み。書き換えたら、もう一度確定してください」と出ますが、ほかの段階には確定が無いので、段階 4 だけ作法が違います。何が「確定」で変わるか（帯に出る）は本文で言っているものの、確定しなくても帯には出ます（brief.fields.oneLiner を読むため）
- 「Claude に頼む」が欄の下に小さく並びます [13]。案が出た後の「この案を使う」で欄が書き換わるのは良い流れです。ただ、押した結果が候補カードとして同じ場所に積まれるので、2 回押すと前回の案が消えます（candidates は task ごとに 1 組）

### 1.4 流れ [15][36]

- 初めて開くと、絵が「絵はまだありません」になります [15]。裏で撮影中なのに、絵が存在しないのと同じ言葉です。数十秒後に差し替わるまで、話者は「絵が無い」と読みます
- 上の帯の「時間は話すことの字数から見積もっています（1 分 300 字）。カードの時間は書き換えられます」が常時出ます。説明文が常駐しています
- カードの並べ替えは、ホバーで出る「< >」の 2 つのボタンです。壁のポストイットを動かす操作としては手数が多く、章をまたげません
- 時間の帯のラベルが「0. はじめに」「1. 実験の背景」と章の名前で、持ち時間の線だけ赤。良い作りです

### 1.5 コマ [16][17][18][19][33]

- 右の余白（360px）に、各コマの「コマに指摘を追加」と、各シーンの「シーンに指摘を追加」が 2 行ずつ出ます。98 コマなら 130 個の同じボタンが並びます。指摘の無いコマでは、余白の 360px がほぼ空です
- 指摘のカードは、その行の高さを押し広げます。シーンの見出しの行に指摘を 1 件書くと、見出しとコマの間に 180px ほどの空白が入ります [33]。原稿の面も同じで、段落 1 に指摘を 1 件書くと、段落 1 の下に空白ができます [67]
- 話すことの欄は、欄の外を押すまで保存されません。「未保存です」の警告が欄の下に出る方式で、企画の自動保存（600ms）と違います
- 左レールの「絵の作り方を表示」は、Claude 向けの指示です。既定で隠しているのは正しいものの、絵が無いコマでは勝手に出ます [40]
- 再生の重ね画面 [17] は良い作りです。「← 前のコマ」「次のコマ →」「もう一度再生」「閉じる（Esc）」と、押すと何が起こるかが分かります

### 1.6 読み（発表）[20][21][35]

- 1 画面に 3 つの仕事があります。読んでもらう（ボタン）、アンケートを読む（表）、あなた宛ての指摘を裁く（一覧）。「あなた宛て 11 件へ ↓」のジャンプボタンがあること自体が、1 画面に 2 つの仕事がある印です
- 「Claude に渡す指摘 45 件」が、帯の右端と「あなた宛ての指摘」の見出しの右の 2 か所に出ます [21]
- 読み手が未設定の発表では「AI が演じる聴衆 0 人が…読んだ結果です」と出て、「読んでもらう」が押せません [35]。押せない理由（読み手を選んでいない）と、選ぶ手段（readers.yaml を手で書く）が画面にありません。記事には読み手を選ぶ UI があります [57]
- 「Claude 宛て 45 件と解決済み 0 件を表示」の行が、見出しなしの文のボタンです。畳まれた中身が何かは分かりますが、押せるように見えません

### 1.7 公開（発表）[22][31]

- 「通しで再生」のカード 1 枚と「公開の設定・OGP の確認・振り返りは準備中です。いまは Claude Code に公開を頼んでください」の 1 行です。公開の面なのに公開の操作が無く、公開の頼み方は帯の「公開の手順」（完成のときだけ出る）に別置きです
- 「最初から再生」「発表者ビュー」は良い言葉です

### 1.8 記事の企画 → 構成 → 原稿 [50]〜[58]

- 構成・原稿・読み・公開のどのタブを押しても、原稿が無ければ「原稿を作成」の画面になります [54]。タブの名前と中身が一致しません
- 「原稿を作成」で slug を聞きます。「半角の英小文字・数字・ハイフン」「原稿のフォルダ名と、公開後のアーカイブの名前になります」と、実装の都合を話者に説明しています。発表では絵コンテを Claude に頼むだけで、slug は出ません。原稿の置き場の名前は、タイトルから Claude か studio が決められます
- 原稿が 0 字の時点で、記事全体の検査に「要修正 地の文が 1 段落もない」と赤丸が出ます [56]。書き始める前に赤です
- 「本文はまだありません。下の『段落を追加』から書き始めるか、Claude Code に下書きを頼んでください」の案内の下に、すぐ入力欄が開いています。案内の「下の『段落を追加』」が指すボタンは、すでに入力欄に変わっています
- 構成の空の状態は「構成はまだありません」+ 説明 3 行 + 「見出しを追加」です [55]。改稿では「原稿の見出しから作成」が先に出ます [62]。押すと、既定の予算（60 字・150 字）で作られ、その瞬間に「予算より 68 字多い」「粗なのに 314 字あります」の赤い警告が 2 つ出ます [63]。話者がまだ何も決めていないのに、赤です
- 構成のカードの「密 / 粗」「予算 / 実際」は、writing-note の言葉です。design.md 6 章が「粗密」を画面に出さないと決めているのに、「粗なのに」「密が本文の n%」と出ています

### 1.9 読み（記事）[57][64][65]

- 読み手を選ぶ UI は 12 人のチェックボックスで、「この 0 人に決める」が無効のまま出ます [57]。読み手の候補が 12 人並ぶのは記事だけで、発表には無いので、同じ「読み」タブの第一印象が媒体で違います
- 見出しは「聴衆役の読み」、本文は「AI が演じる読み手 2 人が」、左の見出しは「読み手」。1 画面に「聴衆役」「読み手」が混ざっています。発表の面では「聴衆役」「聴衆」です

### 1.10 公開（記事）[58][66]

- タイトル・タグ・見出し画像・note に貼る・公開したら、の 5 枚のカードで、作業の順に並んでいます。発表の公開の面と型が違いますが、こちらの型（確かめる項目を上から順に）の方が良いです
- 公開前の原稿で「0 個。3〜5 個にしてください」「見出し画像はまだありません」が橙で出ます [58]。公開の面を初めて開いた時点で警告が 2 つです。これは「まだ」なので、警告ではなく「未設定」の表示で足ります
- 「公開したら」の依頼文に、原稿の絶対パスとごみ箱の相対パスが入ります。話者が読むより Claude に渡す文なので、本文を見せる必要が薄いです

### 1.11 公開済みの記事 → 改稿 [60][61][69][70]

- 読む画面は帯が「ホーム / タイトル（薄い字） / note で開く / 改稿する」だけで、作品の画面と別の骨組みです。種類・状態・公開日が帯に無く、作品の画面と同じ場所に同じものが出ません
- 「改稿する」を押すと、原稿タブで開きます。帯は「下書き 公開」の 2 バッジと「改稿をやめる」になります [61]。この状態の名前が画面に無いので、「下書き」と「公開」が並ぶ理由を、話者が推測します
- 改稿中に企画タブを開くと、段階 1 から空欄です [70]。公開済みの記事の企画シートは無いので、改稿の工程に企画は要りません。しかし先頭のタブが企画で、ホームのカードも「伝えたいことは未定」と言います
- 「改稿をやめる」の吹き出しの赤いボタンも「改稿をやめる」で、確かめる前と後が同じ言葉です。確かめる文に「原稿を、ごみ箱（絶対パス）に移します」が入ります [69]

### 1.12 作品に紐づかない発表 [40]

- 公開済みの発表（Dev's Garden）は `/talks/<slug>` の別画面で、帯に状態バッジも企画タブもありません。同じ「発表」なのに、作品の画面と骨組みが違います。公開済みの記事の読む画面も入れると、「発表 1 本・記事 1 本」の見え方が 4 通りあります（作品・紐づかない発表・公開済みの記事・改稿中）

### 1.13 指摘・読み・Claude の受け渡し（横断）[18][23][33][34][67][68]

- 指摘を書く入口は良いです。「コマに指摘を追加」→ その場に欄 → Enter で送信、の 2 手です [18]
- 書いた指摘は「あなた・Claude 宛て」のカードになり、「追記する」「取り下げる」が出ます [33]。あなた宛てのカードは「返信する」「解決する」「見送る」、解決済みは「未解決に戻す」、聴衆役の Claude 宛ては「追記する」「見送る」。スレッド 1 件に対する動詞が 6 種類あります
- 「Claude に渡す指摘 n 件」の吹き出しの依頼文に、`ball`・`replies`・`thinking`・`change`・`closed` の実装語が並びます [23]。記事では原稿の絶対パスが 2 回入ります [68]。話者が読む文ではなく、Claude に渡す文なので、画面に全文を見せる必要がありません。ボタンを押したらコピーされて「貼ってください」と出るだけで足ります（memory「往復 UI は手数最小で」）
- 「読んでもらう」の後、聴衆役の感想がスレッドになって Claude の番から始まります。話者が読む前に Claude に渡る設計なので、「45 件」が話者の判断なしに積まれます。数字が大きいほど、話者には「自分の仕事」に見えます

## 2. 横断で見えたこと（つぎはぎの正体）

| 症状 | どこに出るか | 根本 |
|---|---|---|
| どこにいるか分からない | 帯のタブ・企画の段階・コマの目次が 3 つのナビ | 「工程」を表す場所が決まっていない。タブは並列で、段階の順序を表していない |
| 同じ数字が 2 つある | 読みタブのバッジ 11 と帯の 45 | 「あなた宛て」と「Claude 宛て」を別の部品が別の場所に出している |
| 作品ごとに帯が違う | 下書き・完成・公開・改稿中・紐づかない発表で、帯の右の中身が 5 通り | 状態ごとに操作を継ぎ足した。「状態のメニュー」という 1 つの場所が無い |
| 媒体で作法が違う | 読み手の選択・原稿の作成・公開の面・帯のチップ | 記事の面を後から足したときに、発表の面の型に合わせた部分と合わせなかった部分がある |
| 実装の言葉が漏れる | slug・ball・絶対パス・粗密・予算・「絵の作り方」 | 画面の言葉の原則（design.md 6 章）が、後から足した面に効いていない |
| 空の状態が赤い | 原稿 0 字の要修正・構成作成直後の赤 2 つ・公開の橙 2 つ | 「まだ」と「間違い」を同じ色で出している |
| 余白が本文を動かす | コマ・原稿の右余白 | 指摘のカードを行の中に置いているので、行の高さが指摘で決まる |
| かっこよくない | 全画面 | shadcn 既定の管理画面の系統で、ブランド（夜の焚き火・ember・暖灰）の気配が無い。design.md 7 章は「hidoko のデザインシステムには乗らない」と決めているが、vision.md（10/19）は studio も手触りのあるものにすると言っている |

## 3. 理想の情報設計

```
└──────────────┴───────────────────────────────────────────────────────────────┘
```

上の帯は 1 行だけです。戻る・タイトル（省略しない）・状態 1 語・「⋯」メニュー。「⋯」に、完成にする／下書きに戻す／削除／改稿をやめる／公開の手順、のうち、その状態で押せるものだけを入れます。タブも操作も帯から外れるので、1280 幅でもタイトルが読めます。

左レールは 4 段です。上から、芯（伝えたいことと聴衆。企画の段階 4 と 2 の結果）、工程（面の並びと、各面の状態）、受け渡し（あなた宛て・Claude へ）、場（イベント・日付・残り日数）。レールが「いまどこで、次は何か」を常に言うので、面の中に「次にやること」の案内が要らなくなります。

工程の並びは、発表も記事も 5 つです。企画は 4 段階を子として畳み、企画を開いているときだけ展開します。流れ／構成、コマ／原稿は媒体で名前が変わりますが、位置と役目は同じです。各項目に、その面の 1 つの数字を添えます（流れは合計時間、構成は字数、読みはあなた宛ての件数）。

面の中は、面ごとの仕事に集中します。コマと原稿の目次（シーン・見出し）は面の中の左列として残します。レール（工程）と目次（面の中）の 2 列になりますが、役目が違うので色と幅で分けます。レールは暗い背景（ブランドの夜の闇）、目次は面と同じ明るさ、のように。

### 3.2 発表と記事で、共通にする部分と変える部分

| | 共通 | 媒体で変える |
|---|---|---|
| 骨組み | 帯 1 行・左レール・面 | — |
| 企画 | 4 段階、確定の作法、Claude に頼む | 欄の中身（いまのまま） |
| 下書きの全体（流れ／構成） | 上の帯（合計と上限）、カードの並べ替え、カードの「伝えること」 | 発表は時間、記事は字数。発表は章・時間、記事は見出し・密か粗か |
| 下書きの 1 つ（コマ／原稿） | 左に目次、真ん中に読む対象、右に指摘。その場で直す | 発表は絵+話すこと、記事は本文。記事は検査を右に添える |
| 読み | 読み手を選ぶ → 読んでもらう → アンケート。両方とも画面で読み手を選ぶ | アンケートの項目（いまのまま） |
| 公開 | 「確かめる項目を上から順に並べ、最後に依頼文をコピー」の型 | 発表: 通し再生・OGP・公開の可否・公開の依頼文。記事: タイトル・タグ・見出し画像・貼る・取り込みの依頼文 |
| 指摘 | 余白に書く、受信箱で裁く、レールから渡す | 位置の持ち方（シーン+コマ／段落）だけ |

原稿の作成は、slug を聞かずに作ります。企画のタイトルから Claude か studio がローマ字の名前を決め、話者には見せません（直したいときは「⋯」の中）。発表の「Claude Code に絵コンテを頼む」と並ぶ操作として、「Claude Code に下書きを頼む」の依頼文のコピーを同じ場所（企画の最後）に置きます。

読み手は、企画の段階 2 で描いた聴衆（発表）・読者（記事）から「この人を読み手にする」で選べるようにし、personas/ のプリセットからも足せるようにします。両方とも読みの面の先頭で選びます。段階 2 とつながると、帯の芯の「聴衆」と読み手が同じ人になります。

### 3.3 ナビゲーション

- ホーム → 作品の画面 → 面、の 2 階層だけにします。`/talks/<slug>` と `/notes/<dir>` の別画面は、作品の画面の見た目違いとして吸収します。企画シートの無い公開済みの発表・記事は、企画の面に「企画シートはありません（公開済み）」と出し、ほかの面は読むだけにします
- 公開済みの記事は、作品の画面の「原稿」の面で note 風に読めます（いまの NoteView の本文を、原稿の面の読むだけの状態として出す）。「改稿する」は「⋯」か原稿の面の上に置き、押すと同じ面が直せる状態になります。画面が変わらないので、「下書き 公開」の 2 バッジの謎が消えます
- URL は `/works/<id>#<面>/<場所>` のまま使えます

### 3.4 作品の状態の見せ方

話者の頭にある区分は「できたか」「出したか」の 2 軸（ADR-0045）ですが、画面では 1 語に畳みます。下書き・完成・公開・改稿中、の 4 語です。社内向けは「完成（社内）」のように添えます。データは 2 軸のまま持ち、見せ方だけ 1 語にします。

状態の操作は「⋯」メニューの 1 か所です。押せるものだけを出し、危険なもの（削除・改稿をやめる）は確かめる文を 1 文（「下書きを削除します。ごみ箱に移すので戻せます」）にして、パスは出しません。パスは「⋯」の「置き場を開く」で Finder から見られれば足ります。

ホームのカードは 1 種類にします。表紙（あれば）+ 種類 + 状態 1 語 + タイトル + 1 行（下書きなら次にやること、公開済みなら日付とイベント）。表紙が無い下書きは、芯の 1 文を表紙の代わりに大きく出します。

### 3.5 指摘・読み・Claude への受け渡しの導線

```
書く        余白（コマ・段落・シーン・記事全体）で、その場に欄。Enter で送る   ← いまのまま
裁く        レールの「あなた宛て n」を押すと、右から受信箱が開く。どの面からでも開ける
            1 件ごとに「返信・解決・見送る」の 3 つ。押すと次の件に進む
渡す        レールの「Claude へ m」を押すと、依頼文がコピーされ「ターミナルに貼ってください」と出る。1 手
読んでもらう 読みの面の先頭。読み手を選ぶ → 読んでもらう → アンケート
```

- 「あなた宛て」と「Claude へ」の数字は、レールの 1 か所にだけ出します。面のタブのバッジと帯の右端は無くします
- 受信箱は面を離れずに開くパネルにします。読みの面の下半分にあった「あなた宛ての指摘」の一覧は、受信箱に移します。読みの面は読んでもらうこととアンケートだけになり、1 面 1 仕事になります
- 余白の指摘カードは、行の高さを変えないようにします。カードを行の右に絶対配置して、重なるときだけ下にずらす（Google ドキュメントのコメントの作法）。指摘の無い行には、ホバーしたときだけ「指摘を書く」を出します。ボタンの常駐（130 個）をやめます
- 依頼文は短くします。「`<場所>/feedback.yaml` に Claude の番の指摘が m 件あります。crafting-presentation（writing-note）skill の Phase 8 に従って直してください」の 1〜2 文です。ball・replies の作法は skill 側に書き、画面には出しません
- スレッドの動詞は 3 つに絞ります。返信・解決・見送る。「追記する」は返信に、「取り下げる」は自分が書いた件の見送るに、「未解決に戻す」は解決済みのカードの「戻す」に畳みます
- 聴衆役の感想は、読んでもらった直後に話者が一度ざっと見てから Claude に渡す形にします（受信箱に「聴衆役から 45 件。Claude に渡す / 見送る」の 1 行を置き、まとめて渡す）。話者の判断を経ずに 45 件が積まれるのを避けます

### 3.6 言葉

- 聴衆役（AI が演じる聴衆）で統一します。「読み手」「読者」は、企画の段階 2 の「読者を決める」だけに残します
- 「指摘を書く」で統一します。「コマに指摘を追加」「シーンに指摘を追加」「段落に指摘を追加」「記事全体に指摘を追加」の 4 語は、余白の位置で分かります
- 実装語を外します。slug（出さない）、絵の作り方（「Claude への絵の指示」）、粗密・密・粗（「厚く書く / 短く通る」）、予算（「目安の字数」）、要修正（「直す」）、ball・replies（出さない）、絶対パス（出さない）
- 「まだ」と「間違い」を分けます。原稿 0 字・タグ 0 個・見出し画像なし・絵の撮影中は、灰色の「未設定」「撮影中」です。赤や橙は、話者が決めた値と食い違ったときだけです

### 3.7 ホーム

```
┌──────────────────────────────────────────────────────────────┐
│ hokuchi studio                       [ネタを書き留める…  ↵]  + 作成 │
├──────────────────────────────────────────────────────────────┤
│ いま                                                          │
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐           │
│ │ 発表 下書き     │ │ 記事 改稿中    │ │ 発表 完成（社内）│           │
│ │ AIに任せられる… │ │ LINE API…     │ │ 会員サイト…    │           │
│ │ あなた宛て 11   │ │ 読んでもらう    │ │ 公開の手順     │           │
│ │ あと 12 日      │ │              │ │              │           │
│ └──────────────┘ └──────────────┘ └──────────────┘           │
│ ネタ 3 件 ▸                                                   │

```

上が「いま」（下書き・完成・改稿中）、下が「積み上げ」（公開済み）です。vision.md の「ネタ → 芯 → … → 積み上げる」の両端をホームの上下にします。ネタは帯の 1 行の入力欄で書き留め、ネタの一覧は「いま」の下に畳みます。絞り込みは「すべて / 発表 / 記事」と検索だけです。積み上げは月で区切ると、「今月は何本出したか」が見えて、蓄積の実感になります。

### 3.8 かっこよさ（体験）

studio は話者だけが触る道具なので、ブランドをそのまま載せるのではなく、ブランドの気配を持たせます。

- 左レールを夜の闇（`#0a0907` 系の暖灰）にし、進行中の面と「あなた宛て」の数字だけ ember（`#f47d3a`）で灯す。面は暖かい白（`#f5f1e6`）。冷たいグレーを使わない
- 文字は本文を大きく、説明を小さく。「なぜやるのか」「出典」は折りたたみ、初めての人だけ開く
- 表紙の絵を主役にする。ホームの「いま」のカードと、作品の画面の帯の左端に表紙を小さく置く
- 常駐の説明文（「時間は話すことの字数から…」「本文をコピーして、note のエディタに貼ります」）を、ホバーの補足か「?」に移す

design.md 7 章の「hidoko のデザインシステムには乗らない。画面の系統は 1 つにする」は、shadcn を部品の土台にしたまま、色と字の系統をブランドに寄せる、という形で両立できます。決めるときは ADR を 1 本書くのが良いと思います。

## 4. 作り直しの優先順位

いちばん効くものから並べます。1 と 2 で「迷わない」が手に入り、3 で「発表と記事が同じ流れに乗る」が手に入ります。

1. 骨組みを 1 つにする（3.1・3.4）。帯 1 行、左レール（芯・工程・受け渡し・場）、「⋯」メニュー、状態 1 語。企画の段階をレールに吸収し、`/talks` と `/notes` の別画面を作品の画面に吸収する。ここで色と字の系統（3.8）も決める。見た目の変化がいちばん大きく、話者の「つぎはぎ感」に直接効く
2. 指摘の導線を 1 本にする（3.5）。数字をレールの 1 か所に、受信箱をパネルに、依頼文を 1 手のコピーに。余白のカードが行を押し広げないようにする。毎日の往復の手数が減るので、速さに効く
3. 発表と記事の作法を揃える（3.2）。読み手を両方で画面から選ぶ、段階 2 の聴衆と読み手をつなぐ、slug をやめる、公開の面を同じ型にする、改稿中は企画を飛ばす。質と蓄積に効く
4. 言葉と空の状態を総点検する（3.6）。実装語を外し、動詞を 3 つに絞り、「まだ」を灰色にする。1〜3 の実装の中で一緒にやるのが安いが、独立した点検として最後にもう一度回す（memory「文言を足したら Gemini も使って総点検」）
5. ホームを「いま / 積み上げ」にする（3.7）。ネタの入口を帯に、絞り込みを 1 組に、カードを 1 種類に。毎日最初に見る画面だが、作品の画面より滞在が短いので、作品の画面の後で良い
6. 流れ・構成の並べ替えをドラッグにし、章をまたげるようにする。design.md「まだ無いもの」の中で、いまの UI の手数がいちばん多い所

## 6. 確かめていないこと

- 「読んでもらう」「Claude に頼む」「タイトルの案を出す」は押していません。実行中の表示と、結果が画面に入る瞬間は見ていません

- ドラッグや細かいホバーの挙動は、静止画では見ていません
