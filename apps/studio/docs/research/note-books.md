## 1. 『はじめての note 副業』

本の結論は、書く前の準備が最も重要だということです (p.644)。誰に・何のために・どのゴールで書くかの 3 点です。型・タイトル・見直しは、慣れれば自然にできる側に置かれています。収益化に特化した部分 (ジャンル選び・有料記事の作り方) は、ここでは扱いません。

### 書き始める前に決めること

- 相手を先に決める。書きたいことではなく、読者が知りたいことから逆算する (p.109, 114)
- テーマの 3 つの軸: 自分の体験があるか、誰かの悩みに関係するか、興味を持ち続けられるか (p.118-125)
- 読者は属性ではなく悩みで絞り、1 人に絞る (p.126, 130)。候補は過去の自分・相談してきた人・他人の記事の読者
- 過去の自分を想定するなら: いつ頃の自分か、どんな悩みがあったか、どんな言葉があれば救われたか (p.131)
- 習熟度の段階で、どの段階の人に書くかを決める (p.132)
- 悩みの拾い方: 読者の発言の観察、検索キーワード、身近な人との会話、過去の自分、人気記事の導入文 (p.127-128)
- 1 記事 1 テーマ。何を伝えたいかを書く前に 1 つ決める (p.161-162, 176)
- 記事のゴール (共感・フォロー・他記事への誘導) を書く前に決める (p.636)

### 構成の型

- 基本の型: 結論 → ストーリー → スイッチ (気づき・視点の切り替え) → ノウハウ (→ 誘導) (p.160, 167-171)
- 体験談の型: 体験 → 感情 → 気づき → 今。気づきは 1 つに絞る (p.276-278)
- 構成の良し悪しは「構造」(冒頭の結論、ストーリーと主張の交互、1 記事 1 テーマ、最後のまとめか問い) と「配慮」(改行と余白、短い文、平易な言葉) で見る (p.175-178)
- 読まれない文章の典型: 感情だけのポエム、出来事を並べた日記、改行のない長文、主語が多すぎる文、論点が飛ぶ文 (p.174)

### タイトル・導入・締め・タグ

- タイトルは「軸 + ベネフィット」。ベネフィットは読者の未来の変化 (p.214-218)
- 左側にキーワードと強い言葉を置く。スマホで切れるので長すぎない (p.199-202)
- 引っかかり: 意外性・ズレ感・心の声 (p.208-210)
- タイトルは本文を書き終えてから付ける (p.213)
- 見出しの並びは中身をチラ見せする形に (p.222-223)
- 見出し画像は凝らなくてよいが必ず入れる (p.203, 348)
- 締めに関連記事への誘導を本文の中に入れる (p.610)。シリーズ化と次回予告 (p.607-608)
- タグは 5〜6 個。ジャンル・読者層・お題企画 (p.356, 599-605)

### 記事チェックリスト (ワーク 4、p.634)

書く前: 目的 / 読者 (1 人) / 読者の悩み / 悩みの解決につながる内容か / 自分にしか書けない要素 (経験・失敗・気づき) / 記事のゴール (読者にどう思ってほしいか、どう動いてほしいか)

書いている最中: 結論が数秒で伝わるか / ストーリーは具体的か / 気づき (スイッチ) があるか / ノウハウが伝わるか / 見出しは流し読みでも気になるか / 自分の他の記事を紹介しているか

公開前 (タイトル): 読者目線で魅力的か / 引っかかりがあるか / 検索されそうな語が入っているか

公開前 (表現): 文末の語調 / 箇条書きにできる所 / 文字種のバランスと表記揺れ / 専門用語や横文字の多さ / 曖昧語で終わっていないか

公開前 (見た目): 改行は 3〜5 行以内か / 太字は一番伝えたい所だけか / スマホで崩れていないか / 長文に区切りや画像があるか

### 続けるための運用

- ネタ帳: 気づいたらすぐメモし、なぜそう感じたかを深掘りし、自分のジャンルにつなげる (p.251-253)。お題: 最近モヤっとしたこと、人に聞かれたこと、説明したこと、語りたくなった話題 (p.227)
- ネタの視点: 過去の悩み、誰かの悩み × 自分の経験、視点をずらす (真逆・裏側・極端) (p.228-248)
- 公開後: タグのランキングで相性を見る (p.602)、マガジンで読んでほしい記事を先頭に (p.564)、シリーズにまとめる (p.607)
- 過去記事を体系的に見直す手順は、本にはない

## 2. note 公式のまとめと紹介記事

note 編集部のまとめは、悩みを「書くテーマを見つけたい」「伝わる文章を書きたい」「続けたい」の 3 つに分け、各 3 本を紹介しています。

| 記事 | 要点 |
|---|---|
| 鈴木洋平「売れるコンテンツのつくり方」 | 企画・取材・執筆・編集・分析の 5 段。企画はタイトルで考える。伝えたいことを一言に集約し、読後感を設計する。公開前に仮説を立て、シェアの量と質で検証する |
| 謎部えむ「書くこと講座 (1)」 | 面白さはテーマと内容でほぼ決まる。自分で発見したなら書く価値がある。字数を気にしない。まず自分の内側を見る |
| 佐伯要「誰のために、何を、どう書くか」 | 視る → 訊く → 何を書くか → どう書くか。何を書くかは、何を書かないかを決めること。Web では冒頭に山場を置く |
| 村井弦「それなりに整った文章を書くコツ」 | 構成づくりが作業の約 8 割。構成ができるまで書かない。構成は箇条書きのメモで十分。一番面白い所を冒頭に固定する。自分で「よく書けた」と思えるかで判定する |
| けんすう「読まれる文章のコツ」 | 内容 (情報・日記・主張) と表現を分ける。段落は 80〜150 字。読者の頭に浮かぶ疑問を順に潰す。過剰な表現を避ける (本人いわく感覚値) |
| 竹村俊助「読みやすい文章はデザインが優れている」 | 漢字をひらく。4〜5 行以内で改行する (しすぎるとポエムっぽい)。印象的な一文を 1 ページに 1 つ |
| 白水梨恵「サクッと書けるブログの書き方三箇条」 | 短文でよいので定期的に更新する。見出しはその節の一言要約。身近な誰か一人に手紙を書くつもりで |
| まよ「書きたいことが分からなくなってしまった」 | 受け身の時間ばかりで余白がないと書けない。ふと感じたことをメモし、下書きに貯める |
| さとくま「毎日書くには、毎日書かないこと」 | 書ける日に書き溜め、予約投稿する。書けない日は休むと伝える。勢いで書いた質の低い記事は出さない |

### 横断して共通する原則

1. 何を書くかが、どう書くかより先で比重も大きい (謎部・佐伯・けんすう・鈴木)
2. 冒頭に一番面白いものを置く (村井・佐伯・鈴木)
3. 一言に集約し、捨てる判断をする (鈴木・佐伯・白水)
4. 構成を先に作る (村井・白水・鈴木)
5. 読み手を具体的に置く (佐伯・白水・けんすう)
6. 続けることが前提 (謎部・白水・さとくま・まよ)
7. 具体 (エピソードと数字) で納得させる (鈴木・けんすう)

### 食い違う点

- 長さ: 謎部は字数を気にしない / 白水は種類ごとの目安を示す
- 読者意識: 謎部はまず自分の内側 / 佐伯・白水・けんすうは読者が起点
- 構造: けんすうは見出しの入れ子を避ける / 白水は見出しで区切る
- 何を書くか: けんすうは情報が読まれやすい / 謎部・まよは自分の発見や日々の感覚でよい
- 品質の判定者: 村井は自分の「よく書けた」 / 鈴木は公開後のシェアの量と質

## 3. 人の関門と、AI・機械の支援

人が決めること: 何に気づいたか・何を書くか、読み手は誰か、伝えたい一言と読後感、何を捨てるか、冒頭に置く一番面白い所、「よく書けた」という納得、公開後の反応の解釈。5 本の記事が判断の主体を書き手に置いています。AI が代わりに決めると、記事の根拠そのものが崩れます。

機械が検査できること: 段落の字数、改行の間隔、漢字の比率とひらく候補、文末の統一、誇張語、リンクの数、卑下表現、見出しが一言要約か、タイトルの文字数。

AI が問い返しで支援できること: 一言が言えているかの確認、材料の列挙と捨てる候補、冒頭候補の比較、読者が抱きそうな疑問の列挙、タイトル案 (判断は人)。

## 4. 提案: 制作アプリへの落とし込み

- 企画の欄: 種メモ / 種類 (情報・日記・主張) / 読み手 (1 人と、その悩み) / 一言 / 読後感・ゴール / 仮タイトル / 材料 (使う・捨てる) / 冒頭 / 構成メモ / 公開前の仮説
- 段階: 種 → 企画 → 材料と取捨 → 構成 (冒頭を固定してから箇条書き) → 執筆 → 見直し → 公開 → 検証
- 関門: 一言の確定、冒頭の確定、「よく書けた」の自己判定。人がボタンを押して通る
- 見直し: 機械の検査と、人のチェック (冒頭は一番面白いか、本質を削りすぎていないか、印象に残る一文、締めの後味、タイトル、よく書けたか) に分ける
- 公開後: 仮説と実績を並べる。シェアの言葉を貼り、「へー」型と「たしかに」型に分ける
- ネタ帳を記事とは別に持つ。欄は出来事・なぜそう感じたか・どの悩みにつながるか・切り口
- 過去記事の改善は、本にも記事にも体系的な手順がない。書き手の方針で設計する
