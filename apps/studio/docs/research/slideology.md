# slide:ology 読み直し — 発表資料を新しく作るとき、何をどの順に決めるか

2026-10-09 に、studio の設計の根拠として全 12 章を読み直した記録です。頁番号は日本語版のものです。本の主張には頁を付け、解釈や提案は「提案:」で区別します。

## 結論

本が示す順序は「聴衆を知る → 紙で量を出す → 絞って捨てる → 構成 → ビジュアル体系を一度で決める → 1 枚ずつ作る → リハーサルで削る」です。本の章立ては作成手順と同じ順です (p.15)。p.32 の準備時間の表が工程表にあたります。

## 1. 作り始める前に決めること

冒頭の問い (p.34): 聴衆はどんな人々か / 何を求めているか / どうアプローチすべきか / 自分の情報は彼らの生活にどう役立つか / プレゼン後にどんな行動を取ってほしいか。何より大切なのは行動への呼びかけです。聴衆との関係を、自分が彼らの「ヒーロー」になるのか「応援団長」になるのかで考えます。どちらも、自分のためではなく他人のために力を尽くす役です (p.36)。

聴衆を知る 7 つの問い (p.35)。

1. どんな人々か (属性から入り、最後は個人レベルで理解する)
2. なぜここにいるのか (自分から来たのか、来させられたのか)
3. 彼らを悩ませているのは何か
4. 彼らの問題をどう解決するか (聴衆が得るもの)
5. 彼らに何をしてほしいのか (「だから何？」に答える)
6. どんな反発を受けるか
7. 最適なアプローチは何か (会場のレイアウトから終了後の資料まで)

プロフィールシート (p.36-37): 典型的な聴衆の画像に名前を付け、7 問の答えを書き込みます。投影はせず、資料の冒頭に置いて話す相手を意識し続けます。聴衆が多様なら複数枚作ります。

そのほか前もって決めること。

- 状況分析 (p.39): 会場・聴衆・伝えるべきメッセージ・呼びかける行動を決めてから、物語を作る
- 重要度 (p.32): 準備時間は重要度に比例する。1 時間の発表で 36〜90 時間
- 色の 3 つの問い (p.146)、会場の明るさと背景 (p.152)、媒体の選択 (p.260-261)

本には「中核メッセージを 1 文で書け」という明示の工程はありません。メッセージはメッセージマップ (p.39) と、アイデアを選ぶ基準 (p.47) として出てきます。1 文に固定する工程は、本の外 (note の書き方記事など) から補うことになります。

## 2. アイデア出しから構成までの工程

| 工程 | 入力 → 出力 | 判断基準 | 頁 |
|---|---|---|---|
| リサーチ (6〜20 時間) | 素材を集める | 時間を惜しまない | p.32 |
| 聴衆のニーズマップ (1 時間) | 7 問 → プロフィールシート | 個人レベルで描けているか | p.35-37 |
| 発散 (PC を離れ、紙で) | 抽象語 → ワードマップ・大量の案 | 質より量。最初の案を採らない。良い案は 4〜5 案目以降 | p.46-47 |
| 付箋 (2 時間) | 案 → 1 枚 1 案のカード | 油性ペンで書ききれない案は複雑すぎる | p.48 |
| まとめる (1 時間) | カード → メッセージマップ (大テーマの行 × トピック) | 作業中ずっと表示して更新する | p.39 |
| スケッチ | コンセプト → 複数のラフ | メッセージに焦点が合うか | p.52-53, 58-60 |
| 助言 (1 時間) | スケッチ → 指摘 | 1〜2 人の同僚に要点を評価してもらう | p.54-55 |
| 絞り込み | 候補 → 1 案 | 1 案を残して捨てる。楽な方法に飛びつかない | p.60 |
| 構成・絵コンテ (2 時間) | 1 案 → 順序 | 直線的な絵コンテでもよい | p.32, 48 |
| 作成 (20〜60 時間) → リハーサル (3 時間) | | | p.32 |

## 3. 1 枚 (1 場面) の基準

- 3 秒ルール (p.160)。看板のように一瞬で読ませる
- 75 語以上は「ドキュメント」、50 語前後は「テロップ」(p.27。英語の語数で、日本語への換算は未検証)
- 1 枚に 1 つのアイデア (p.256)
- 情報の層は 4 つ以上重ねない。要点はメイン 1 つとサブ 2 つまで (p.117)
- 読む順は Z 字 (p.116)。取り除いても影響の小さい所、分割すべき所を問う (p.126)
- 書体は 2 つまで (p.163)。基調講演では 28pt 未満を使わない (p.172)
- 箇条書きは見出しとして書き、言い回しを揃える (p.170-171)
- 話している項目より先は隠す (p.203)
- タイトルの位置を固定するなど、一貫性を保つ (p.135, 227)

ダイアグラムは、伝えたい関係を 6 つの型 (フロー・構造・クラスタ・放射・ピクトグラム・データ) に照らして選びます (p.65)。図の中心に誰を置くかまで決めます (p.80)。データは、データそのものではなく意味を伝えます (p.84)。持ち帰ってほしいことが強調する所を決めます (p.88-89)。アニメーションは理解を助けるときだけ使い (p.200)、役割は 5 つ (関係性の変化・画面の演出・オブジェクトの変化・連続性・強調) です (p.205)。不適切なアニメーション 8 項目に当たるものは削ります (p.220)。

## 4. 発表全体に効く原則

- 聴衆は読むと聞くを同時にできない (p.26)
- メッセージ・ビジュアルストーリー・デリバリーは 3 本脚の椅子で、それぞれに検証がある (p.30-31)
- スライドデザインの失敗の多くは、スタイルではなく基本構成が原因 (p.109)
- スライド依存から抜け出す (第 11 章)。3 つの R (Reduce・Record・Repeat、p.241)、時間を短くする (p.246)、プロジェクターなしでも話せるか (p.250)
- スライドと配布物は別物。Web 向けの資料は話し手なしで通じる形にする (p.43, 86, 258)
- 巻末の 5 原則 (p.273-281): 聴衆こそが王様 / アイデアを広め、人を動かす / 伝えたいことをわかりやすく / デコレーションではなくデザインを / スライドと聴衆と健全な関係を築く

## 5. 人の関門と、AI・機械の支援

人が決めること: 7 問の答え (特に「何をしてほしいか」「反発」)、聴衆との関係、1 案を残して捨てる判断、データで強調する意味、図の中心に置く人物、キーワードだけで話せるか (リハーサル)。

提案: AI は発散の量を増やす (p.47)、7 問の抜けを指摘する、反発の予測で壁打ちする、同僚役として講評する (p.54。本が想定するのは人の同僚なので補助)、関係を図の型・動きの役割に照らして提案する。

提案: 機械は、1 枚の文字数、書体の数と最小サイズ、タイトル位置の一貫性、円グラフの項目数、グレースケールでのコントラスト、動きの役割の有無、ノートの順と表示順の一致を検査できる。

## 6. 提案: 制作アプリの段階

| 段階 | 主な欄 | 関門 |
|---|---|---|
| 企画 | 重要度・持ち時間・会場・媒体 | |
| 聴衆 | プロフィールシート (複数可。名前・画像・7 問)、関係、行動への呼びかけ | 問 5 を人が書くまで進めない |
| 発散 | アイデアカード (1 枚 1 案)、ワードマップ | 採用前に 5 案以上 |
| メッセージマップ | 行 = 大テーマ、セル = トピック | 以降も常に画面に出す |
| スケッチ | コンセプトごとの複数案、採否と却下理由 | 採用は 1 案 |
| 絵コンテ | 場面ごとに「伝えること 1 行」・型・強調点・表示順・ノート | 1 場面 1 アイデア |
| ビジュアル体系 | 背景・配色・書体・グリッド・画像の様式 | 一度決めたら固定 |
| 作成・検査 | 機械の検査と、不適切な動き 8 項目 | |
| リハーサル | 3 つの R、停電テスト | 人の自己申告 |
| 配布物 | スライドとは別の文書 | |

本は検証から作り直しに戻る反復を描いています (p.30-31)。段階は一方通行にせず、どこへでも戻れる設計が本に忠実です。
