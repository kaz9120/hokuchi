バグ報告のために画面をキャプチャして、「ここ」と矢印を引いて、Slack に貼る。ハンズオン記事を書くために、操作手順をスクショに撮って、注釈をふって、note や Zenn に並べる。

ソフトウェアエンジニアなら、この作業を週に何度もやっていると思います。

私もそうです。そして、ずっと地味なストレスを感じていました。

## Mac のスクショ体験が、意外としんどい

Windows を使っていた頃は、標準のツールでそこそこ快適にこなせていました。Mac に移ってから、同じことをやろうとすると妙に手数が増える。

スクショを撮る。プレビューで開く。切り取る。注釈を足す。コピーする。ツールを行き来するたびに、流れが途切れます。

CleanShot X のようなネイティブアプリを入れれば解決する場面もあります。でも、私が欲しかったのは「環境を選ばず、ブラウザを開くだけで使える」手軽さでした。インストールが必要な時点で、別のマシンでは使えません。

そしてもう一つ。私はスクショをローカルに保存したくない。撮って、加工して、クリップボードに乗せて、Slack なり GitHub なりに貼ったら、それで終わり。画像ファイルがデスクトップに溜まっていくのは、それだけで小さなストレスです。

## snapcrop を作った

この不便を解決するために、snapcrop というブラウザツールを作りました。

[![](assets/1782023635-LFUjh6xaIKZQCm5Nkp12o8bG.png)](https://snapcrop.y-kaz.com/)
*https://snapcrop.y-kaz.com/*

アカウント登録は不要です。画像がサーバーに送信されることもありません。開いた瞬間から使えます。

できることは絞っています。

- ブラウザ上でスクリーンショットを撮る
- 画像を切り取る（16:9 などアスペクト比の指定もできる）
- 矢印、テキスト、矩形、マーカー、モザイクで注釈を入れる
- Cmd+C でクリップボードにコピーする

これだけです。

画像を保存する機能はあえて重視していません。スクショは「通過する」ものだと思っています。撮って、加工して、相手に届いたら、役目を終える。

## 「伝わるスクショ」は、道具の問題だった

snapcrop を自分で使い込むうちに、気づいたことがあります。

スクショは、適当に貼ればいいものではありません。バグ報告で「ここが壊れている」と矢印1本引いてあるだけで、受け取る側の理解速度がまるで変わります。ハンズオン記事で手順ごとのスクショが同じサイズで並んでいると、読む側のストレスが減ります。

丁寧にスクショを作りたいという気持ちは、多くの人が持っているはずです。でも、ツールが不便だとその気持ちに蓋をしてしまう。面倒だから、とりあえず撮ったまま貼る。

これは意志の問題ではなく、道具の摩擦の問題でした。

snapcrop は、その摩擦を限りなく小さくすることで、「丁寧に伝える」の敷居を下げたいと思って作っています。

## なんでもできる方向には進まない

snapcrop は画像編集アプリではありません。Figma や Photoshop の代わりにはなりませんし、なるつもりもありません。

目指しているのは、「説明のための図解を、摩擦なく作れるツール」です。なんでもできるようになると、むしろ価値が下がると考えています。機能を足すかどうかの判断基準は「これがあると、説明がもっと伝わるか」の一点だけです。

今は1枚ずつの注釈の体験を磨いている段階ですが、いずれはハンズオン資料のように、シリーズを通して一貫した見た目で図解を並べられる体験も作りたいと考えています。

## 使ってみてください

<https://snapcrop.y-kaz.com/>

ブラウザで開いて、Cmd+V で画像を貼るか、画面キャプチャボタンを押すだけです。

普段のスクショ作業が少しでも楽になったら嬉しいです。
