# ADR-0003: デフォルトテーマは BRAND.md と hidoko tokens.css から導出する

- ステータス: 承認
- 日付: 2026-07-04
- スコープ: presentation

## 文脈

スキーマの Foundation 層（テーマトークン）はスロット制で、色・書体・グリッドを名前付きスロットに固定する（ADR-0001）。ではデフォルトテーマの中身、とくに色と書体の実値を何から決めるか。hokuchi には既にブランド定義（`BRAND.md`）と、その実装であるデザインシステム（`hidoko/packages/ui/src/tokens.css`）がある。テーマをここから導くか、スライド専用に新規設計するかを決める必要があった。

## 選択肢

1. **テーマを独自に新規設計** — スライドという媒体に最適な配色・書体をゼロから設計する。媒体特性（大会場・投影）に合わせ込める自由度はある。しかしブランドの指紋色や書体と乖離すれば、資料がブランドから浮く。BRAND.md §6.5 の「基準色をアクセントに統一する」という既存の約束を二重に定義し直すことになり、片方を直すたびにもう片方とズレる
2. **BRAND.md と tokens.css から導出** — 既にあるブランド判断とトークンをスライドのスロットに写す。ブランドとの一貫性が自動的に保て、色や書体の更新はデザインシステム側の変更に追従できる。slide:ology の配色論とブランドの指紋色が構造的に噛み合うかは確認が要る

## 決定

2 を採用する。ember-400（`#f47d3a`、ブランドの指紋色）を highlight スロット（強調専用の 1 色）に置く。core には補助色（moon/moss/smoke）を、neutral には ink 段階色を bg/surface/line/muted/text の役割名付きスロットとして割り当てる。書体は LINE Seed JP（和文）+ Inter（欧文）のスタックを display / body 両スロットに写し、階層はウェイトで分ける（BRAND.md の分担は和文/欧文であり、display/body ではない）。背景はダークを標準とする。BRAND.md §6.5 の「冒頭スライドにキャッチコピー」「自己紹介スライドは毎回更新」は opener テンプレートの仕様に落とす。デザインシステムを複数リポジトリからどう共有するかは、hokuchi のスコープ外として別途検討する。

## 根拠

ember-400 を highlight スロットに置くと、slide:ology のハイライトカラー（強調専用の 1 色、p.156）と、BRAND.md §6.2 の「基準色はブランドを象徴する接点に使う」がそのまま一致します。強調に使う唯一の色という役割が、両者で同じ形をしています。ここが噛み合うことが、独自設計ではなく導出を選ぶ決め手です。core／neutral／書体も、既にデザインシステムに段階色（ink 0〜900）と補助色が定義済みで、スロットへの写像は素直に済みます。確信度は高。ダーク標準は slide:ology の「dark=フォーマル/大会場」（p.152）に沿いますが、配布用途では light が要るため、背景の既定値だけは確信度中です。

## 見直しの条件

次のいずれかで再訪します。(1) `tokens.css` の色・書体・段階が更新され、テーマがブランドから乖離したとき。テーマはトークンの写像であり、単一ソースは tokens.css 側にあるので、乖離は追従で解消する。(2) 実デッキが配布資料（light 背景）中心の運用になり、ダーク標準が実態に合わなくなったとき。(3) スライドのテーマを hokuchi 以外のリポジトリからも共有したい要求が具体化したとき。スコープ外に置いた「複数リポジトリでのデザインシステム共有」を、そこで正式に検討する。

## 影響

- デフォルトテーマは tokens.css を単一ソースとする。テーマ側で色値を直接持たず、トークンへの参照として定義する
- opener テンプレートは BRAND.md §6.5 を仕様に含む。キャッチコピー枠と自己紹介スライドの更新を前提にする
- neutral を単なる 3 色配列から bg/surface/line/muted/text の役割名付きスロットへ広げる。この役割名は spike のレンダラが実際に使った面・枠・補助テキストの区分（spike/NOTES.md §1.3）に対応する
