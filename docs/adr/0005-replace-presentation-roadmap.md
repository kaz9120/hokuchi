# ADR-0005: skill は presentation-roadmap を置き換える新規とする

- ステータス: 承認
- 日付: 2026-07-04
- スコープ: presentation

## 文脈

このスキーマの書き手は Claude で、スキルが人間との対話から聴衆・メッセージを深掘りし YAML を生成する（ADR-0001）。hokuchi には既に presentation-roadmap スキルがあり、slide:ology を土台にコンテンツ設計から Marp プロットを生成する。新しいスキルを、この既存スキルとどう関係づけるかを決める必要があった。

## 選択肢

1. **前工程として合流** — presentation-roadmap を残し、その出力（Marp プロット）を新スキーマ生成の前段に置く。既存スキルの資産（コンテンツ設計の対話フロー）を活かせる。しかし旧スキルの出口は Markdown/Marp であり、新スキーマは Markdown という文書メタファーを捨てる設計（ADR-0001）なので、接続点で Marp から YAML への変換という二重管理が生じる。旧スキルの前提（Marp で表現する）と新スキーマの前提が正面衝突する
2. **置き換え** — 新スキルを新規に作成し、旧 presentation-roadmap との互換は考慮しない

## 決定

2 を採用する。skill は既存の presentation-roadmap スキルを置き換える新規作成とし、旧スキルとの互換は考慮しない。

## 根拠

旧 presentation-roadmap の到達点は Marp プロットであり、その前提は「スライドを Markdown で表現する」ことです。新スキーマはその前提そのものを課題の根本と見て捨てました（ADR-0001、design.md §1）。合流させると、旧スキルの Marp 出力を新スキーマの YAML に橋渡しする変換層が要り、二つの表現形式を並行して保守することになります。コンテンツ設計の対話（聴衆・メッセージの深掘り）は新スキルにも要りますが、それは slide:ology の思想として引き継げばよく、Marp を出力する実装を引き継ぐ必要はない。互換を捨てるほうが変更しやすい、という判断です。確信度は高（design.md §7 末尾、2026-07-04 決定）。

## 見直しの条件

次のいずれかで再訪します。(1) 旧 presentation-roadmap の利用者や既存の Marp 資産が実際に残っており、置き換えによる移行コストが問題として現れたとき。移行パスを別途用意するか検討する。(2) Marp プロットという中間成果が、新スキーマ生成の前段として独立に有用だと判明したとき。合流案を再評価する。

## 影響

- 新スキルは新規作成として設計する。コンテンツ設計の対話は slide:ology の原則として引き継ぎ、Marp 出力の実装は引き継がない
- 旧 presentation-roadmap は置き換え対象。段階的な廃止か併存放置かは、上記の移行コストの観測に応じて決める
