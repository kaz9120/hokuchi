# ADR-0006: image 要素は生成プロンプトを画像仕様として保持する

- ステータス: 承認
- 日付: 2026-07-04
- スコープ: presentation

## 文脈

image 要素は写真を扱う（第 8 章）。ここで、実画像がまだ無い段階のスライドをどう表すかという問題がある。書き手は Claude で、生成の時点では最終画像を持たないことが多い。画像そのものは外部の生成 AI や素材から後で用意する。このとき image 要素に何を持たせ、「どんな画像であるべきか」という意図をどこに残すかを決める必要があった。

## 選択肢

1. **src のみ（画像は完全に外部管理）** — image は画像ファイルへの参照だけを持つ。スキーマは単純になる。しかし画像がまだ無い段階では src が空で、そのスライドが「何の画像を意図していたか」がスキーマから失われる。意図は書き手の頭か別のメモに退避し、スライドの意味の一部（配置・視線・被写体、design.md §4）が宙に浮く
2. **prompt を仕様として併記** — image は src と別に prompt（画像生成 AI 向けプロンプト）を持つ。プロンプト自体が「どんな画像であるべきか」の仕様として YAML に残る。src が無ければ prompt がプレースホルダとして描画される。運用では人間が任意の生成 AI で出力した画像を src に置いて差し替える

## 決定

2 を採用する。image 要素は src と prompt を持つ。prompt は画像生成 AI 向けのプロンプトであり、同時に「この位置にどんな画像が来るべきか」の仕様として YAML に残り続ける。src が省略されていれば、レンダラは prompt を使ってプレースホルダを描画する。src が置かれれば実画像に差し替わる。

## 根拠

プロンプトを仕様として YAML に残すと、実画像が無い段階でもスライドの意図が失われません。被写体や視線（subject / gaze）といった配置の意味は、実画像の有無と独立に宣言できます。spike ではこのプレースホルダ描画を実装し、prompt からプレースホルダ（面・コーナー枠・プロンプト文）を生成できることを確認済みです（spike/NOTES.md §1.3）。特定の画像生成 AI をスキーマに固定しない点も利点で、人間はどの生成 AI で出力してもよく、成果物を src に置くだけで差し替わります。生成手段への依存を抽象化できています。確信度は高。

## 見直しの条件

次のいずれかで再訪します。(1) 画像生成が API 統合で自動化され、prompt から src を機械的に生成する運用になったとき。prompt と src の関係（生成トリガーや再生成の扱い）を仕様として定義し直す。(2) prompt を更新したのに src が古いままになる、といった両者の同期ずれが実運用の痛点として現れたとき。どちらを真とするか、あるいは src に生成元 prompt を紐づけるかを決める。

## 影響

- レンダラは src 欠落時に prompt からプレースホルダを描画する責務を負う（spike で実装済み）
- prompt は image 要素の一級フィールド。画像がまだ無いスライドも、意図を保ったままレビュー・レンダリングできる
