# ADR-0008: spike が残した痛点に SPEC 確定へ向けて回答する

- ステータス: 承認
- 日付: 2026-07-04
- スコープ: presentation

## 文脈

spike の痛点のうち構造の根幹（スロット制・emphasis・タイプスケール）は ADR-0007 で決めた。残る痛点（spike/NOTES.md §2.4〜2.6・2.8・2.9）と、スクリーンショットの目視レビューで見つかった品質問題（日本語改行・主役要素の存在感）に、SPEC.md を書き始める前に答えを出す必要があった。7 つの小さな決定を 1 本にまとめる。個別に選択肢を並べるほどの分岐がないものは、決定と根拠のみ記す。

## 決定

1. **グリッドは行数を明示する。** `theme.grid` に `rows`（既定 6）を追加する。`col-4` が列だけ決めて行数が宙に浮く状態（NOTES §2.4）を解消する
2. **舞台からあふれる主役は縮小し、lint が報告する。** stage_margin の帯に収まらない diagram/chart は、はみ出しでもエラーでもなく縮小して収める。縮小が発生したことは linter が情報として報告する。逆に主役要素は舞台領域を十分に使う（目安として高さの 85% 以上）ようスケールする。spike スライド 5 の「小さく漂うダイアグラム」の再発を防ぐ
3. **chart のデータは インライン形を正準とする。** `data: { x: [...], series: [{label, values}] }` を正準形とし、外部ソース (`source: file.csv`) は描画前に正準形へ解決される入力糖衣とする。design.md と spike で食い違っていた 2 形式（NOTES §2.5)の関係を定義する
4. **チャート注釈のアンカーは x の値で指し、照合失敗は lint エラーにする。** annotations の `at` は x 配列の値との完全一致で解決する。表記ゆれで黙って壊れる問題（NOTES §2.5）は、解決できない `at` を linter がエラーとして検出することで防ぐ。位置で指したい場合のために `at_index` も許す
5. **軸の共有はデッキ層の `scales` で宣言する。** デッキに名前付きスケール（例: `revenue: { y: { min: 0, max: 80 } }`）を定義し、chart が `scale: revenue` で参照する。連続する chart スライドが共有スケール無しで軸レンジが食い違う場合、axis-lock lint が警告する（NOTES §2.6）
6. **role は舞台の枠を、layout は舞台上の配置を支配する。** レターボックスの有無・バンパー扱い（ロゴ許可）・ヘッダフッタは role が決め、layout は舞台の内側の配置だけを決める。layout から枠は変更できない。1 つの視覚属性を両者が触る二重支配（NOTES §2.8）を分担で断つ
7. **diagram の edges は構造化形を正準とする。** `{from, to, label?}` を正準形とし、`"a -> b"` の文字列は読み込み時に正準形へ展開される糖衣とする。存在しないノード id への参照は linter がエラーとして検出する（NOTES §2.9）

追加で、スキーマ外だがレンダラの必須要件を 1 つ決める。

8. **日本語の改行は文節単位で行う。** statement / quote のような大きなテキストは、BudouX 相当の文節分割と行バランスで折り返す。行末 1 文字だけの孤立（spike スライド 4「向き合／う」、スライド 9「書いてみ／ませんか」）を許さない。書き手が `text` に明示的な改行を入れた場合はそれを優先する

## 根拠

いずれも spike の実装記録（NOTES.md §2）と私自身のスクリーンショット目視レビューで観測された具体的な問題への回答であり、机上の一般論からの追加仕様ではありません。方針は一貫して「書き手の宣言は意味に限る。曖昧さは黙って通さず、正準形への正規化と lint 検出で受け止める」です。糖衣（edges の文字列形・chart の外部ソース）を残すのは書き味のため、正準形を定義するのは検証可能性のためで、ADR-0001 の構図と同じです。確信度は高。85% という主役スケールの目安値だけは見た目の経験則であり、確信度は低〜中です。

## 見直しの条件

SPEC.md に基づく本実装で実デッキを 3 本作り、(1) 縮小の lint 情報が大半のスライドで出る（= 舞台と主役のサイズ観がずれている）、(2) `at` の値一致がチャート実務で使いにくく `at_index` ばかり使われる、(3) 文節改行が日本語以外のデッキで邪魔になる、のいずれかが観測されたら該当項目を再訪します。

## 影響

- SPEC.md と JSON Schema はこの 7 + 1 項を仕様として明文化する
- linter のルールに annotation-anchor（`at` 解決失敗）、edge-ref（ノード id 参照切れ）、shrink-report（主役の縮小発生）が加わる
- レンダラは BudouX 相当の文節改行を実装要件として負う
