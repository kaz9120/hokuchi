# ADR-0017: link の OGP 自動解決と post の SPA 実埋め込み

- ステータス: 承認
- 日付: 2026-07-09
- スコープ: tools/slides

## 文脈

ADR-0016 の serve 注釈レビュー (2026-07-09) で、紹介系 2 要素の「本物らしさ」が足りないと指摘された。

1. link は OGP 画像を手動でダウンロードして `image:` に渡す運用だが、指定しなければテキストだけのカードになる。レビューは「OGP の表示はしてほしい。OGP / QR / URL がセットで出るくらいが良い」。ADR-0016 は OGP 取得の自動化を「手運用が痛くなってから」としており、その条件が初回レビューで即座に満たされた
2. post は自前描画のカードだが、レビューは「実際のポストの埋め込みにしたい。web アプリとして実装している強みを出したい」

どちらも外部ネットワークに触れる機能であり、「出力は自己完結」(ADR-0010/0012 の一貫した方針) と「発表会場のネットワークに依存しない」という制約の内側で設計する必要がある。

## 選択肢

**OGP の取得タイミング。** A 案: CLI ヘルパー (`hokuchi ogp <url>`) を手で叩く — 手運用が残り、指摘の解消にならない。B 案: render 時に自動取得し、デッキの `assets/ogp/` へキャッシュする — 初回だけネットワークを使い、以後はオフラインで再現する。C 案: 表示時 (SPA) に取得する — 会場のネットワークに命運を預けることになり不可。B 案を採る。

**post の埋め込み方。** A 案: カードのまま — 指摘の解消にならない。B 案: SPA では常に X の埋め込みに置き換える — オフラインで空白になり、shot (PNG) も撮れない。C 案: 漸進的強化 — 静的出力はカード、SPA は `source` がある post に限り実埋め込みを試み、失敗したらカードがそのまま残る。C 案を採る。

## 決定

1. link 要素は、`title` / `description` / `image` が未指定のとき、render 時に URL の OGP メタデータを取得して補完する。取得した画像とメタデータはデッキの `assets/ogp/` に URL ハッシュ名でキャッシュし、存在すれば再取得しない (オフライン再レンダリングと final 凍結に耐える)。手書きの指定は常にフェッチ結果より優先する。取得失敗は render を止めず、従来のテキストカードに落ちて lint 相当の警告を出す
2. link カードは OGP 画像 + タイトル + URL (ドメインだけでなく全体を折り返し表示) + QR を標準の構成とする
3. post 要素は、静的出力 (shot / handout) ではカード描画のまま。SPA 出力では `source` URL を持つ post に限り、X の oEmbed (blockquote + widgets.js) をカードに重ねて描画を試みる。スクリプトが読めない・ポストが消えている場合はカードがそのまま見える (フォールバックではなく初期表示がカード)
4. ネットワークを使うのはこの 2 箇所 (render 時の OGP、SPA 表示時の widgets.js) だけとし、どちらも失敗が出力を壊さないことを不変条件とする

## 根拠

確信度は OGP が高、post 埋め込みが中。OGP はビルド時取得 + コミット可能なキャッシュなので自己完結の方針と矛盾しない。post は X の widget 仕様変更に振り回されるリスクがあるが、カードが常に下敷きにあるため壊れても発表は成立する。

## 見直しの条件

- X の oEmbed / widgets.js が不安定化・有料化したら、SPA 埋め込みを外してカードのみへ戻す (スキーマは変わらない)
- OGP キャッシュが肥大したら、画像の最大サイズ・形式の制約を足す

## 影響

- レンダラに OGP 取得 (render 時、キャッシュ付き) と link カードの再構成、SPA の post 埋め込みを追加
- SPEC §6.8 / §6.9 の描画記述を改訂
- 要素選択ガイドの link の行 (「OGP 画像はローカルパスで渡す」) を自動解決前提に改訂
- deck スキーマは変わらない (0.3.0 のまま)
