# ADR-0021: note アーカイブの index.md は note のエディタにそのまま貼れる Markdown にする

- ステータス: 承認
- 日付: 2026-09-08
- スコープ: リポジトリ全体 / tools/notes

## 文脈

ADR-0019 は、埋め込みカードを `:::embed{service="..." url="..."}` ディレクティブで残すと決めた。理由は「素の URL に潰すと種別が失われる」だった。取り込んだ 45 本に埋め込みは 135 件あり、`index.md` に出てくる Markdown 外の記法はこの `:::embed` と、目次の `:::toc` (6 件) の 2 つである。リンクと画像は最初から Markdown の範囲に収まっている。

ADR-0020 で執筆の順序が「hokuchi で書いてから note に貼る」に変わり、`index.md` に新しい要求が生まれた。原稿 (`drafts/`) と公開後のアーカイブを同じ形にし、front matter を除いた本文を note のエディタにそのまま貼れるようにしたい。note のエディタは URL を 1 行貼るとカードに変えるので、埋め込みの自然な書き方は URL だけの行である。ディレクティブでも引用ブロックでも、貼る前に手で戻す作業が要る。

そして、ディレクティブを選んだ理由そのものが弱い。ADR-0019 は同時に「復元の責任は `source.json` が負い、`index.md` は読めるかを優先してよい」とも決めている。原本が別にある以上、`index.md` から種別やポスト本文が消えても情報の欠落にはならない。落ちたことに気づく手段は `verify` が担っていて、これは `source.json` と突き合わせるので、記法を変えても効き目は残せる。

## 選択肢

**埋め込みの表現。** A 案: `:::embed` ディレクティブのまま — 種別と URL とテキストが構造として残るが、Markdown ではなく、note に貼る前に手で戻す必要がある。B 案: 引用ブロックの 1 行目にリンク、続く行にポスト本文やタイトルを置く — CommonMark で書け、埋め込み先が消えても中身が残る。ただし note に貼ると引用として入り、カードにならない。C 案: URL だけの 1 行 — note に貼るとそのままカードになり、原稿と同じ形になる。ポスト本文やタイトルは `index.md` から消えるが、`source.json` の `embedded_contents` がスナップショットごと持っている。C 案を採る。ADR-0019 が C 案を「これまでの失敗の再来」と退けたのは、失敗の本体が「落ちたことに気づけない」ことだったからで、`verify` がある今は当てはまらない。

**埋め込みと素の URL の見分け方。** URL だけの段落は埋め込み以外にもあり得る。A 案: `index.md` に印を足す — 独自記法に戻る。B 案: `verify` は原本の `data-src` を知っているので、URL だけの行のうち原本の埋め込み URL と一致するものだけを埋め込みとして扱う。B 案を採る。`lint` は原本を持たないが、URL だけの段落を地の文から外すだけでよい。

**ラベルが URL そのもののリンク。** 原本の `<a href="u">u</a>` を `<u>` の自動リンクにしていた。note に貼ると `<` `>` が文字として残るので、素の URL に変える。GitHub では GFM の自動リンクで、CommonMark の範囲では文字のままになるが、貼れることを優先する。

**目次。** note が見出しから自動生成する部品で、記事の内容ではない。貼るときにも要らないので出さない。未知のタグは `<!-- unknown: tag -->` に続けてテキストを置き、`verify` が warn を出す。

**画像。** note のエディタに貼って試したところ、見出しや強調は Markdown として解釈されるが、画像行 `![alt](path)` が 1 つでも混ざると本文全体が素のテキストになる。A 案: 原稿から画像行をやめ、位置を示す文字列だけ書く — 貼れるが、プレビューで画像が見えず、公開後のアーカイブ (`verify` が画像の並びと実体を検査する) と形が揃わない。B 案: ファイルは `![alt](assets/…)` のままにし、貼るときに `hokuchi-note paste` が画像行とキャプションを Markdown の意味を持たない 1 行 (`（画像 n/N: ファイル名 ｜ キャプション: …）`) に置き換えてクリップボードに入れる。ローカルの画像はどのみち note 側で入れるしかないので、置き換えた行が入れる位置の印になる。B 案を採る。

**GFM への依存。** `index.md` が Markdown 処理系に期待するのは、素の URL の自動リンクだけである。表・取り消し線・タスクリスト・アラート・脚注は使わない。

## 決定

`index.md` の本文は、画像を除けば note のエディタにそのまま貼れる形にする。埋め込みは URL だけの 1 行で表し、ポスト本文や記事タイトルは書かない。ラベルが URL そのもののリンクも素の URL にする。目次は出さない。画像は `![alt](assets/…)` のまま置き、貼るときは `hokuchi-note paste` が位置を示す 1 行に置き換える。

```markdown
年間20回以上、勉強会やカンファレンスで登壇する。

https://x.com/kyamamoto9120/status/589357152663248896

https://kaitou.connpass.com/event/379977/
```

`verify` は原本の `data-src` の列と、URL だけの行のうち原本の埋め込み URL に一致するものの列を突き合わせる。数・順序・URL の欠落を error にする点は変わらない。

## 根拠

確信度は中。原本と検査が別にあるので、`index.md` の表現は「読めるか」「貼れるか」で決めてよく、note の原稿と同じ形にするほうが執筆から公開までの往復が減る。埋め込み先が消えたときの中身は `source.json` にあり、読みたければそこを見ればよい。

確信度を下げる前提が 2 つある。エスケープ (`\-` や `\*`) を貼ったときの扱いは未検証で、含む記事は 45 本中 2 本ある。貼れなければ `paste` が外すか、エスケープの規則を見直す。もう 1 つ、原稿での埋め込みを URL 1 行で書く運用はまだ実例がない。

## 見直しの条件

- note のエディタの貼り付けの挙動が変わり、画像行があっても Markdown が通るようになったとき (`paste` の画像の置き換えをやめる)、または見出しや強調が通らなくなったとき (`paste` が note の記法に変換する)
- 自分の本文に、埋め込みと同じ URL だけの段落が現れ、`verify` が取り違えたとき
- `index.md` を読む場所が GitHub 以外に増え、素の URL がリンクにならず不便になったとき

## 影響

- ADR-0019 の「埋め込みの表現」の決定をこの ADR で置き換える。2 層構成・取得元・画像・`verify` の方針はそのまま生きる
- `tools/notes` の `markdown.mjs` (埋め込み・自動リンク・目次の出力)、`verify.mjs` (埋め込みの認識と目次検査の撤去)、`lint.mjs` (URL だけの段落の除外)、テストと `docs/design.md` を直す
- `hokuchi-note paste` を追加する (`src/paste.mjs`)
- 45 本を `build` し直す。差分は埋め込み 135 件・目次 6 件・自動リンク 3 件の機械的な置き換えで、本文は変わらない
- writing-note skill に、原稿での埋め込みは URL を 1 行置くと書き足す
