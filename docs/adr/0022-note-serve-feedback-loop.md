# ADR-0022: note の原稿レビューは serve のフィードバックループで回す

- ステータス: 承認
- 日付: 2026-09-09
- スコープ: tools/notes

## 文脈

writing-note skill (ADR-0020) を初めて通した 2026-09-06 の記事で、Phase 4〜6 (書く・削る・検査) の往復が重かった。「この段落くどい」「ここは具体が欲しい」のような位置付きの指摘を、ターミナルで場所ごと言葉にして返していたからである。公開のときも、`paste` を別に叩く手間が残った。

スライド側には同じ問題への答えがある。ADR-0011 は `serve` で描画を配信し、ブラウザで付けたアノテーションを `annotations.md` に落として Claude が読む形にした。人は「アノテーション送った」と言うだけでよく、位置の特定は機械が担う。

## 選択肢

**どこまでアプリに寄せるか。** A 案: Phase 0〜7 全部をチャット + エディタの独立アプリにし、Claude API を組み込む — ターミナルが要らなくなるが、skill の手順をプロンプトへ移植し直し、原稿を git に戻す経路と API キーの管理が要る。B 案: Phase 4〜6 の往復だけをブラウザに寄せ、Claude Code (skill) は頭脳のまま — 芯・フック・骨組みの候補選び (Phase 2〜3) はターミナルの対話に残る。C 案: Claude Code の Artifact に原稿を公開し、コメントをセッションに送る — コードはほぼ要らないが、セッションが生きている前提で、hokuchi の外に置くことになる。いちばん重かったのは Phase 4〜6 なので B 案を採る。候補選びまで寄せるかは、使ってから決める。

**アノテーション UI。** A 案: ADR-0011 と同じく agentation を注入する — 要素をクリックして選ぶ道具で、文を選ぶ用途に合わない。React と esbuild が依存に入り、`tools/notes` の「依存ゼロ」が崩れる。B 案: 文を選ぶと「コメント」ボタンが出る最小の UI を自作する — ADR-0011 が撤退先として挙げていた形で、prose には選択範囲がそのまま位置になる。B 案を採る。

**フィードバックの置き場。** `<原稿dir>/feedback.md` に節ごと追記する。`annotations.md` と同じく Claude が読むファイルで、違いは「反映したら節を消す」運用にすること。原稿ディレクトリは公開後に消えるので記録にはならず、往復の受け渡し口に徹する。画面は未反映の節だけを見せ、「ターミナルに貼る」で依頼文ごとクリップボードに入れる。Claude への起点は、貼るか「フィードバック見て」と言うかのどちらでもよい。

**コメントの手数。** 最初の実装は「文を選ぶ → ボタン → ポップオーバー → 送る」の 3 手だった。試したところ多いと分かり、選んだ直後にその場へ入力欄を出して Enter で送る 1 手にした。

**描画。** 汎用の Markdown 処理系を足さず、原稿で使う記法 (`markdown.mjs` が出すもの) だけを HTML にする最小のレンダラを持つ。各ブロックに通し番号を付け、コメントの位置の手掛かりにする。

## 決定

`hokuchi-note serve <原稿dir>` を追加する。原稿を note 風に描画してブラウザで見せ、文を選んでコメントを付けると `feedback.md` に追記する。Claude は `feedback.md` を読んで原稿を直し、反映した節を消す。原稿が変われば画面が追従する (1.5 秒ごとの mtime 監視)。

画面には、lint の指摘 (クリックで該当段落へ)、未反映のフィードバック、全体へのコメント欄、「note に貼る本文をコピー」(`paste` と同じ本文をクリップボードへ)、`assets/` を Finder で開くボタンを置く。lint の指摘には `at` (該当箇所の抜粋) を持たせ、画面が段落を探す手掛かりにする。

## 根拠

確信度は中〜高。位置付きの指摘を機械が運ぶ形は ADR-0011 で効いており、prose では選択範囲がそのまま位置になるので、さらに素直に収まる。依存ゼロで書けたのは、対象の記法が有限だからである。

確信度を下げているのは、Phase 2〜3 の候補選びが残ることと、往復の起点が「Claude にフィードバック見てと言う」であることの 2 つ。後者は `feedback.md` の変化を Claude が自分で待つ形にもできるが、まず人が声をかける運用で始める。

## 見直しの条件

- 候補選び (芯・フック・骨組み) の往復が重いと分かったとき (画面に候補を並べて選ぶ機能を足すか、A 案へ寄せる)
- 「フィードバック見て」と言う手間が気になったとき (Claude 側で `feedback.md` を監視する)
- 原稿で使う記法が増え、最小レンダラでは追いつかなくなったとき (Markdown 処理系を依存に入れる)

## 影響

- `tools/notes` に `serve.mjs` `serve.html` `render.mjs` を足し、cli に `serve` を加える。依存は増えない
- `lint.mjs` の指摘に `at` を持たせる。CLI の出力は変わらない
- writing-note skill の Phase 5〜7 を、serve を立てて往復する手順に書き換える
