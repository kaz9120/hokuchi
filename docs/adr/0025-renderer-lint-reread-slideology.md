# ADR-0025: deck スキーマ 0.5.0 — レンダラと lint を slide:ology の読み直しに合わせる

- ステータス: 廃止 (→ ADR-0026)
- 日付: 2026-09-28
- スコープ: tools/slides

## 文脈

ADR-0024 で slide:ology を読み直した際、スキルの外にもズレが見つかった。話者の手直しのうち、スキルでは直せずレンダラ・スキーマが原因のものがある。

- 「左上のタイトルにできませんか」「タイトルと中央に大きなメッセージ」: statement-stage に上の見出しスロットが無い。前提を先に読ませる手段が、枚数を分けるか support (主役の下・muted) に入れるかしかない。本は親 (タイトル) を上に、子を下に置く (p.118)
- 「字が小さいし表にする価値を感じない」: table のセル・図のノード・出典は 24px (約 18pt) で描かれる。テーマ自身が `type.body.min_size_pt: 24` を宣言しているのに、それを下回るトークンがあり、検査もない。本は基調講演で 28pt 未満を使わない (p.172)
- 段階表示が描画されない: `bullets.reveal`・`diagram.reveal`・`build`・`connect` はスキーマが受け付けるが、レンダラに実装が無い。スキルは `reveal: sequential` を勧めていた。本で最も実務に効くのは「話していない項目は隠す」(p.203) と「詰め込まず分けてつなぐ」(p.210-212) である
- chart の `message` (必須) が画面に出ない。本の強調レイヤーは「データから得られる結論を記す」(p.92)
- 複数系列のチャートは系列ごとに色が変わり、凡例も無い。本は重要度の低い系列をグレーにし (p.95, p.97)、凡例ではなく直接ラベルを置く (p.94)
- composition の単一系列は常に円に導出される。本は円を「差が大きいとき」に限る (p.91)
- lint と SPEC の出典に誤りがある。`bullet-count` (5 項目超で warn) は本が「全て無視して」と退けた種類のルールである (p.170)。`slideument` の出典 p.164 は「文字数に公式なルールはない」と書いている。`one-idea` の出典 p.109 は 1 枚 1 アイデアを述べていない (明示は p.256)。closer の出典 p.37 は聴衆プロフィールシート、アニメーションの 5 役割は p.204 ではなく p.205、`show` の役割は「連続性」ではなく「画面の演出」
- 本の検査のうち機械で見られるものが lint に無い。「1 枚に 4 つ以上の情報のレイヤーを重ねない」(p.117)、「見出しは 1 行」「3 秒で読めるか」(p.160, p.164)、「箇条書きは言い回しを揃える」(p.171)

## 選択肢

**A 案: スキル側の回避策で済ませる。** 見出しが要るときは枚数を分ける、table を使わない、段階表示は同じスライドを複製して 1 項目ずつ足す、と書く。レンダラに触れない。ただし話者の指摘の一部 (字の小ささ、読む順序) はスキルでは消えない。複製スライドは id 管理と差分レビューを壊す。

**B 案: レンダラ・スキーマ・lint を本に合わせて直す。** 足りない語彙を足し、描画されない語彙を実装し、誤った lint を直す。構図の知識はレンダラが専有する原則 (ADR-0014) は保つ。書き手に渡すのは意味の語彙だけにする。

## 決定

B 案を採る。deck スキーマを 0.5.0 に、theme スキーマを 0.5.0 に上げる (いずれも後方互換)。

語彙の追加:
- statement-stage に任意スロット `headline` (heading、上) を足す。前提や問いを上に置き、主張を中央に大きく置く組み方を書けるようにする
- chart-stage で headline を省略したとき、`message` を見出しとして描く (p.92)
- chart に `emphasis` (強調する系列ラベルの配列) を足す。指定があれば、それ以外の系列は neutral 系の色に落とす (p.95, p.97)。複数系列は凡例ではなく直接ラベルで描く (p.94)
- composition の単一系列は、構成比の差が小さいときは円ではなく 100% 基準の横棒に導出する (p.91)。判定の閾値はレンダラの内部ポリシーとし、SPEC には原則だけを書く

描画の実装:
- SPA のプレゼンテーションで `bullets.reveal: one-by-one`、`diagram.reveal: sequential`、`build` (show / dim / emphasize) を実装する。キー送りはビルドのステップを進めてから次のスライドへ移る。静的出力 (shot・一覧モード・handout) は全ステップ表示後の姿を描く。`transform` は描画対象が定まるまで未実装のまま残し、SPEC に明記する
- `connect: push-*` を SPA の画面遷移として実装する。push で連なるスライド列では chapter・フッタ・ロゴを外す (p.212)

型の下限:
- テーマの本文系タイプスケール (node・attribution など、読ませる本文を運ぶトークン) を `type.body.min_size_pt` 以上に上げる。1px = 0.75pt で換算する (キャンバス 1280×720 を 16:9 の 960×540pt に対応させる)。chapter・フッタ・URL・軸の目盛は補助情報として除外する
- lint `min-type` (warn): 主役の縮小を含めた実効サイズが min_size_pt を下回る本文を報告する

lint:
- `bullet-count` を廃止し、`bullet-parallel` (warn) に置き換える。項目間で句点の有無、体言止めと文の混在が揃っていないものを報告する (p.171)
- `layers` (info): 1 枚の情報レイヤー (headline・主役・主役内の副テキスト (detail・edge label・annotation・description)・support) が 4 つ以上 (p.117)。chapter は常時の枠なので数えない
- `glance` (info): headline が 1 行に収まらない長さ、content の statement が 3 秒で読めない長さ (p.160, p.164)。閾値は字数の目安で、SPEC の未決事項に実測の要を残す
- `form-fallback` (info): 専用描画を持たない diagram form (step-row に落ちるもの) を使った
- `message-missing` (info): `deck.message` が無い (ADR-0024)
- SPEC と lint の出典を原文ページに合わせて直す。`slideument` の閾値は hokuchi の独自値であることを明記する (出典は p.26-27 の考え方、p.164 は「文字数に公式ルールはない」)

## 根拠

確信度は中〜高。

語彙の追加はどれも、話者の具体的な指摘と本のページの両方に対応する。構図の数値 (見出しの位置、系列の色、円と棒の閾値) はレンダラに閉じ、書き手に渡すのは意味 (これは前提だ、この系列が主役だ) だけなので、ADR-0014 と整合する。

段階表示と push は、スキーマがすでに受け付けていた語彙の実装であり、新しい設計判断は「静的出力は全ステップ後の姿」と「キー送りの順序」だけである。

確信度を下げているのは型の下限である。本文系トークンを上げると、ノードの多い図や行の多い表は縮小が増え、`min-type` の warn が出やすくなる。これは「文字を小さくしないと入らないなら文書化している」(p.172) という本の判定そのものだが、既存デッキで warn が増える。

## 見直しの条件

- `min-type` の warn が、話者が良しとしたスライドで頻発するとき (換算か下限の見直し)
- `glance` と `layers` の info が実感と合わない (出すべきところで出ない、出てほしくないところで出る) と分かったとき。合うと分かったら warn への昇格を検討する
- 段階表示を使ったデッキで、serve のアノテーションや一覧モードに支障が出たとき

## 影響

- `tools/slides/`: schema (deck / theme)、src (render・components・lint)、themes (scale)、SPEC (§2.3・§3・§4.1・§5.1・§6.5・§7・§9・§11・付録 A)、docs/design.md の出典
- `.claude/skills/crafting-presentation/`: 新しい語彙 (statement-stage の headline、chart の emphasis、段階表示) を ADR-0024 のスキルから使う
- mosh.yaml のロゴ (全スライド・右上) と content の背景画像は本の推奨 (p.137, p.145) と異なるが、MOSH のブランド要件に関わるため本 ADR では変えない
- 既存の talks/ のデッキは再描画すると見た目が変わる (本文系の文字サイズ)。`final/` は凍結済みなので影響しない
