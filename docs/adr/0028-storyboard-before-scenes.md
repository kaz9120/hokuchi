# ADR-0028: 登壇資料は絵コンテ (storyboard.md) で合意してからシーンを実装し、ノートの正本を絵コンテに置く

- ステータス: 承認
- 日付: 2026-10-07
- スコープ: リポジトリ全体 (.claude/skills/crafting-presentation) / tools/stage

## 文脈

ADR-0026 で、発表資料は意図宣言型 YAML ではなく、シーン×状態の React コードで書くことになった。crafting-presentation スキル (ADR-0024) は、Phase 4 で deck.yaml を書き、Phase 5 で聴衆役と話者に見せ、Phase 6 で削り、Phase 7 で描画する流れだった。YAML は書くのが安く、描画はレンダラが担っていたので、構成や言葉を直すたびに描画し直しても負担は小さかった。

コードで書くシーンは、1 つ作り込むのに手間がかかる。構成や言葉が固まる前に実装すると、話者の指摘のたびにシーンを作り直すことになる。2026-09 Dev's Garden では、完成までに 10 往復以上・アノテーション 100 件超の手直しがあり、その多くは「何を伝えるか」と「言葉」の指摘だった (ADR-0024)。

もう 1 つの問いとして、話すこと (ノート) をどこに置くかがある。ノートは発表者ビューと、公開サイトのノートを読むモードに出る。話者が直す頻度も高い。

slide:ology は、映画の絵コンテにはあらゆる場面転換が描かれ、プレゼンでも動きの使いどころを見極めて計画を練るべきだとしている (p.202)。

## 選択肢

**A 案: 構成を決めたらすぐシーンを実装し、実装した画面で話者のレビューを受ける。** 話者は実際の見た目で判断できる。構成や言葉の指摘が出るたびに、実装を作り直すことになる。

**B 案: 絵コンテ (Markdown) で、構成・言葉・見せ方・動きの役割・話すことを話者と合意してから実装する。ノートの正本は絵コンテに置き、ビルド時にシーンへ流し込む。** 実装の前に、構成と言葉の指摘を安く受けられる。聴衆役のレビューと削る工程も、絵コンテの上で回せる。絵コンテと実装の 2 か所を保つ必要があり、食い違いが起きうる。

**C 案: B 案と同じだが、ノートはシーンのコードに置く。** 実装を開けばノートも見える。話者がノートを直すには TSX を開くことになり、絵コンテとノートが二重になる。

## 決定

B 案を採る。

- 絵コンテ `talks/<slug>/storyboard.md` に、トークの情報 (中核メッセージ・聴衆・持ち時間・公開・テーマ・表記)、章、シーン (伝えること・前から受けるもの・見せ方・粗密)、状態 (画面・動きの役割・話すこと) を書く。形式はスキルの `references/storyboard.md` で定め、`tools/stage/storyboard.mjs` が読む
- スキルの Phase 4〜6 (完全版・聴衆役と話者のレビュー・削る) は絵コンテの上で行い、Phase 5 の承認を絵コンテに対して取る。シーンの実装は Phase 7 で、承認と削りを済ませてから行う
- ノートとシーンの名前の正本は絵コンテに置き、`virtual:talk` がビルド時にシーンへ流し込む。`check` は、シーンの抜け・状態の数・順序・空のノートを絵コンテと照合する
- 粗密 (ADR-0023) は、各シーンの `粗密:` に時間とあわせて書き、`wave.mjs` が絵コンテから読む
- 公開の可否を絵コンテ (`公開:`) と `talk.tsx` (`public`) に持たせる。サイトには `public: true` のトークだけを載せる

ADR-0024 の進め方 (理解が先・完全版から削る・文脈を持たない目で読む、Phase 0〜3) は引き継ぐ。deck.yaml を書く Phase 4、lint・render・shot・serve を回す Phase 7、スライド id 単位で反映する Phase 8 を置き換える。

## 根拠

- 構成と言葉の指摘を、実装より前に受けられる。実装の作り直しが減る (確信度: 中。新方式での実績がまだない)
- 話者が直す頻度の高いノートが Markdown にあるので、話者は TSX を開かずに直せる (確信度: 高)
- 絵コンテと実装の食い違いは、`check` の照合で機械的に見つけられる (確信度: 高)
- 状態ごとに動きの役割を宣言させることで、slide:ology の「役割を言えない動きは付けない」(p.205) を、実装の前に確かめられる (確信度: 中)

## 見直しの条件

- 絵コンテで合意した後も、実装を見た話者から構成の指摘が多く出るとき。絵コンテの文字だけでは見せ方が伝わっていない可能性がある。そのときは、絵コンテの段階でラフな静止画を添える方法を検討する
- 絵コンテと実装の二重管理の手間が、合意の早さの利益を上回ったとき

## 影響

- ADR-0024 のうち、Phase 4・7・8 の決定を置き換える。ADR-0024 のステータスに部分的な置き換えを記す
- crafting-presentation の SKILL.md 本体と references (storyboard.md・build-scenes.md を新設、element-guide.md と slide-design.md を書き直し、ほかを追従) と、scripts/wave.mjs・evals を改めた
- 旧方式の deck.yaml を持つ過去のトークは、そのまま残す
