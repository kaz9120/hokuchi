# ADR-0030: 発表資料は制作アプリ studio で、絵コンテのボードを見ながら Claude とチャットして作る

- ステータス: 承認
- 日付: 2026-10-07
- スコープ: リポジトリ全体 / apps/studio / .claude/skills/crafting-presentation

## 文脈

ADR-0028 で、発表資料は絵コンテ (storyboard.md) で話者と合意してから実装することになった。話者からは「絵コンテを Markdown で読むのではなく、システム化できないか。ローカルで動く Web アプリでチャットしながら、絵コンテを見てフィードバックし、スライドを作っていける体験にしたい」という要望があった。

これまでの往復は、ターミナルの Claude Code と、ブラウザの作業用サーバと、エディタの Markdown を行き来していた。どのシーンのどの状態について話しているかを、話者が毎回言葉で伝える必要もあった。

ローカルの Claude Code は、非対話モード (`claude -p`) でストリーム形式の入出力に対応し、1 つのプロセスで会話を続けられる。会話は session id で再開できる。話者がログインしている Claude Code をそのまま使える。

## 選択肢

**A 案: ボードとプレビューだけを作り、チャットはターミナルに残す。** 選んだ状態の文脈をコピーして、ターミナルに貼る導線を付ける。作るものは小さい。話者は画面を行き来し続ける。

**B 案: ボード・プレビュー・チャットを 1 つの画面にまとめる。** サーバがローカルの Claude Code を常駐させ、ストリームで会話する。選んだ状態の文脈をメッセージに自動で付ける。ファイルの変更を見張って、描画を撮り直す。

**C 案: Claude の API を直接呼ぶチャットを作る。** 会話の制御は自由になるが、API キーと課金が別に要り、Claude Code のスキル・権限・ツールを作り直すことになる。

## 決定

B 案を採る。`apps/studio` に、`bun run studio <talk>` で立ち上がるローカルの制作アプリを置く。

- 中央は絵コンテのボード。章 → シーン → 状態のカードに、実際の描画の縮小画像、画面の説明、動きの役割、話すことを並べる。話すことはその場で直せる (絵コンテの該当行を書き換える)
- 右はプレビュー。カードを選ぶと、その状態への遷移を再生する。テーマを切り替えて見比べられる
- 左は Claude とのチャット。選んだ状態の文脈 (`[選択: <scene> の状態 <n>「…」]`) をメッセージに付ける。Claude は crafting-presentation に従って絵コンテと実装を直し、`bun run check` で確かめる
- ファイルの変更を見張り、ボードを読み直し、描画を撮り直す。検査は画面から実行できる
- Claude Code に確認なしで許可するのは、ファイルの読み書きと、検査・型検査・粗密の確認だけにする

## 根拠

- 話者が見たいもの (絵コンテと描画) と、話す相手 (Claude) が同じ画面にあると、往復の手数が減る。選んだ状態が文脈として付くので、「どのページの話か」を説明しなくてよい (確信度: 中。実際の制作での手応えは未検証)
- Claude Code を使うので、スキル・CLAUDE.md・メモリ・権限の仕組みをそのまま使える (確信度: 高。2 往復の会話で動作を確かめた)
- 描画の撮り直しとボードの読み直しは、ファイルの変更から自動で起きる。Claude がどのファイルを直しても、画面は追従する (確信度: 高)

## 見直しの条件

- Claude Code の非対話モードの仕様が変わり、常駐やストリームでの会話ができなくなったとき
- 話者が、ターミナルで直接やりとりする方が速いと感じる場面が多いとき
- アノテーション (画面の要素に直接メモを付ける, ADR-0011) が必要になったとき。いまは状態の単位で文脈を付けるだけ

## 影響

- crafting-presentation の Phase 5〜8 で、絵コンテと実装を話者に見せる場所を studio にする。Markdown をそのまま渡す運用は、studio を使えないときの代替にする
- 絵コンテのパーサ (`packages/stage/node/storyboard.mjs`) に、行番号と、話すことの書き換えを足した
- 再生機は、親の窓からのメッセージ (`stage:goto`) で状態を移れるようにした
