# ADR-0034: slides.y-kaz.com 全体を開発サーバで見られるようにし、`bun run dev` の既定にする

- ステータス: 承認
- 日付: 2026-10-09
- スコープ: apps/slides / packages/stage

## 文脈

ADR-0027 では、発表後にトークのビルドを `final/` に凍結する前提だった。サイトは凍結済みの完成品を並べて一覧ページを付けたもので、開発中に確かめるのはトーク 1 本ずつだった。CLI がトーク単位で、サイトの組み立てが `apps/slides/build.mjs` で別立てなのは、この前提から来ている。

ADR-0029 で凍結をやめ、サイトはいつでもソースから作れるものになった。ただ、そのとき開発の体験はトーク単位のまま残り、サイト全体を開発サーバで見る選択肢は検討しなかった。

サイト全体をローカルで見るには、`bun run site` で全トークをビルドしてから `wrangler dev` で配信する必要があった。直すたびに組み立て直しになる。話者からは「サイトの方も `bun run dev` で確認して、agentation でフィードバックしたかった」「やや管理が面倒な構成になっている気がする」という声があった。

## 選択肢

**A 案: `site` と `wrangler dev` を 1 つのコマンドにまとめる。** 作りは小さい。直すたびに全トークのビルドが要るのは変わらず、agentation も使えない。

**B 案: サイト全体の開発サーバを作る。** トークごとに Vite を立て、`/<slug>/` の下にぶら下げる。トップページは組み立てと同じ関数で作る。保存すると即座に反映され、agentation も使える。

**C 案: トーク 1 本の作業用サーバのまま、トップページだけを別に出す。** トークの URL が本番と違い (`/` 直下)、トップページからの導線を確かめられない。

## 決定

B 案を採る。

- `bun run dev` をトーク無しで実行すると、`apps/slides/dev.mjs` がサイト全体の開発サーバを `http://localhost:5280/` に立てる。トークを指定すると、これまでどおりトーク 1 本の作業用サーバになる
- トークごとの Vite は middleware モードで、base を `/<slug>/` にする。HMR の WebSocket はサイトの http サーバに相乗りする
- トップページ・404 ページ・sitemap.xml の生成は `apps/slides/pages.mjs` に切り出し、組み立てと開発サーバで共有する
- 一覧のサムネイル (`og.png`) は、表紙をその場で撮る。トークのファイルが変わったら撮り直す
- 非公開のトークも、印を付けて一覧に出す。本番には載らない
- トップページと 404 ページも、サイト用の Vite に通して agentation を差し込む。HTML はリクエストのたびに作るので、こちらの HMR は切る
- `wrangler dev` は、公開の直前に組み立てたものを本番の配信と同じ形で確かめるときだけに使う

## 根拠

- トップページ・URL・404 を、本番と同じ形で、直しながら見られる。保存したシーンの変更が、ハッシュ (`#/<scene>/<step>`) を保ったまま反映されることを確かめた (確信度: 高)
- agentation は base に追従して差し込むので、サイト全体の開発サーバでも使える。コピーの見出しに `/<slug>/#/<scene>/<step>` が載り、トークと状態まで分かる (確信度: 高)
- フォントの切り出しと見た目の差分検査は、公開の関門として組み立て (`bun run site`) に残す。開発サーバは確かめるため、組み立ては公開するため、と役割を分ける (確信度: 中)

## 見直しの条件

- トークが増えて、起動時に全トークの Vite を立てるのが遅くなったとき。開いたトークだけを立てる遅延起動にする
- Vite の middleware モードで、複数のサーバが HMR の WebSocket を相乗りできなくなったとき

## 影響

- ルートの `bun run dev` の向き先を `apps/slides/dev.mjs` に変えた。トーク 1 本の作業用サーバは `packages/stage/cli.mjs dev` のまま
- agentation の差し込み (ADR-0032) を、base 付きの URL に対応させた
- CLAUDE.md・design.md・apps/slides/README.md・crafting-presentation の SKILL.md に、サイト全体の開発サーバを書き足した
