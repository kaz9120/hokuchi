# ADR-0035: studio を発信準備の入口にし、ホームの一覧から発表資料と note の原稿の編集画面に移る

- ステータス: 承認 (第 1 段: ホームと発表資料まで)
- 日付: 2026-10-09
- スコープ: リポジトリ全体 / apps/studio / apps/slides

## 文脈

発信の準備は、3 つの入口に分かれていた。

| 入口 | 対象 | 1 回に扱える数 | Claude とのやりとり |
|---|---|---|---|
| `bun run studio <talk>` (ADR-0030) | 発表資料 | 1 本 (起動時に固定) | 画面のチャット |
| `bun run dev` (ADR-0034) | サイト全体 | 全トーク | agentation でメモを付けて、ターミナルに貼る |
| `hokuchi-note serve <原稿>` (ADR-0022) | note の原稿 | 1 本 | 文を選んでコメントし、`feedback.md` を経由して、ターミナルで声をかける |

話者からは「studio でも、slug を指定しないで一覧画面から自由に個別の編集画面に遷移できるようになると、資料の準備がしやすそう」「note の記事の作成も似たような仕組みに寄せたい」「全部を統合的に扱える発信準備機能として整理したい」という要望があった。

## 選択肢

入口について。

**A 案: studio を発信準備の入口 1 つにまとめる。** 引数無しで開くとホームの一覧が出て、そこから各編集画面に移る。サイト全体の開発サーバも studio の中で立てる。

**B 案: 入口は分けたまま、それぞれに一覧を付ける。** 作りは小さい。立てるものを用途ごとに選ぶ手間が残る。

サイト全体の開発サーバとの関係について。

**C 案: studio に統合する。** 同じプロセスで 5280 にサイトを立て、プレビューと撮影もそこから描く。普段は studio だけを立てればよい。

**D 案: 別々のまま。** studio は制作、`bun run dev` は公開した姿の確認と役割を分ける。2 つ立てることになる。

note の原稿への指摘の道具について。

**E 案: 文を選んでコメントする。** `serve` の仕組みを引き継ぐ。文章では文の選択がそのまま位置になる (ADR-0022 の判断)。

**F 案: agentation に揃える。** スライドと同じ道具になる。段落の中の一文を指すのが苦手。

## 決定

A 案・C 案・E 案を採る (話者の選択)。段に分けて作る。

第 1 段 (この ADR で実装した)。

- `bun run studio` を引数無しで開くと、ホーム (`/`) に発表資料と note の原稿が並ぶ。発表資料を選ぶと、編集画面 (`/talks/<slug>`) に移る。トークを指定すると、その編集画面の URL も出す
- 編集画面の中身は、ADR-0030 の studio のまま。API はトークごと (`/api/talks/<slug>/…`) にし、画面への通知もトークごとに分ける
- 撮影・ファイルの監視・Claude の会話は、編集画面を初めて開いたときに立てる。会話はこれまでどおり、トークごとの session id で続きから再開する
- サイト全体の開発サーバは `apps/slides/site-server.mjs` に切り出し、`bun run dev` と studio の両方から使う。studio はトークごとの開発サーバ (5281) を持たなくなった

第 2 段 (次に作る)。

- note の原稿の編集画面 (`/notes/<slug>`)。`serve` の描画・lint・貼り付けに、チャットを足す。文を選んで付けたコメントは、`feedback.md` を経由せずにチャットへ届ける
- ホームから新しいトーク・新しい記事を始める。skill の Phase 0 の対話を、チャットで始める

## 根拠

- 入口が 1 つなら、「何を立てるか」「どのトークを指定するか」を考えずに始められる。一覧から別のトークに移るのも、立て直さずにできる (確信度: 高。ホームから編集画面に移り、縮小画像の撮影まで確かめた)
- トークの開発サーバをサイトと共有するので、プレビューは本番と同じ URL (`/<slug>/`) で描かれる。サイト全体の確認も、同じ studio の中で済む (確信度: 高)
- 第 2 段を分けたのは、発表資料の側で使ってみてから、原稿の画面に何を引き継ぐかを決めるため。`serve` は依存ゼロで動いているので、急いで寄せる理由もない (確信度: 中)

## 見直しの条件

- 起動時に全トークの Vite を立てるのが遅くなったとき。開いたトークだけを立てる遅延起動にする (ADR-0034 と同じ)
- 第 2 段で、原稿の画面を studio に寄せると `tools/notes` の依存ゼロが崩れるとき。描画と lint は `tools/notes` に残し、studio はそれを読むだけにする

## 影響

- ADR-0030 の studio は「トーク 1 本を起動時に固定する」から「ホームの一覧から選ぶ」に変わった。編集画面の構成と Claude の扱いは引き継ぐ
- `bun run studio` と `bun run dev` は同じポート (5280) を使うので、両方は立てられない
- CLAUDE.md・apps/studio/README.md・apps/slides/README.md・crafting-presentation の SKILL.md の起動方法を直した
