# ADR-0037: フィードバックの経緯をトークごとの feedback.yaml に残し、studio のボードでシーンごとに見せる

- ステータス: 承認 (経緯の形は → ADR-0040 でスレッドに置き換え)
- 日付: 2026-10-12
- スコープ: apps/studio / .claude/skills/crafting-presentation

## 文脈

KomeKaigi 2026 の絵コンテを、4 人の聴衆役に 3 周読ませて直した。指摘は 1 周で数十件あり、話者の指摘も重なった。話者には、会話の中で要約して伝えていた。話者からは次の要望があった。

- どのページへの指摘なのかが分からない。どんなフィードバックがあり、何を考えて、どう変えたのかの履歴が欲しい
- 経緯の確認まで含めて、全部のチェックを studio の画面の上でしたい

会話の要約だけだと、指摘とシーンの対応が消える。絵コンテ (storyboard.md) には「いまの姿」しか残らないので、なぜその言葉になったのかを話者が確かめられない。

## 選択肢

**A 案: git の履歴に任せる。** 追加の仕組みが要らない。差分から分かるのは「何が変わったか」だけで、誰のどの指摘から来たのか、見送った指摘は何かが残らない。構成を固めている間は、コミットの粒度も粗い。

**B 案: storyboard.md の中に、シーンごとの経緯を書く。** ファイルが 1 つで済む。絵コンテは話者と合意する設計図で、ノートの正本でもある (ADR-0028)。経緯が混ざると読みにくくなり、パーサとノートの流し込みにも手が入る。

**C 案: トークごとに feedback.yaml を置き、studio が読んでシーンの下に出す。** 絵コンテは「いまの姿」、feedback.yaml は「そこに至った経緯」と役割が分かれる。YAML は人が読めて、AI も直せる (ADR-0036 の企画シートと同じ理由)。ファイルが 1 つ増える。

## 決定

C 案を採る。`talks/<トーク>/feedback.yaml` に、1 件ごとに `scene` (絵コンテのシーン id。トーク全体の話は `"*"`)・`round`・`from`・`feedback` (指摘)・`thinking` (考えたこと)・`change` (変えたこと)・`status` (反映 / 見送り / 話者待ち) を書く。studio の絵コンテのボードは、シーンの下に「経緯」を折りたたんで出し、「話者待ち」だけに絞れるようにする。聴衆役の指摘も、話者の指摘も、記録との照合で分かったことも、同じ形で残す。

## 根拠

確信度は中。話者が欲しいのは「このページの言葉が、なぜこうなったか」で、単位はシーンである。シーン id は絵コンテ・実装・URL で共通の鍵なので、経緯もこの鍵に付ければ、どの画面からも引ける。見送った指摘と、話者の判断を待っている指摘が並ぶので、話者は「自分が決めること」だけを拾える。

確信度を下げているのは、書く手間である。いまは Claude が手で書く。指摘が多い周では、書き漏らしや、シーン id の取り違えが起きうる。シーンを消したときは、その経緯が「トーク全体の経緯」に落ちる。

## 見直しの条件

- 経緯を書く手間が、直す手間を上回ったとき。聴衆役の出力から機械で起こす形を検討する
- 話者が studio の画面から指摘を書き、状態を変えたくなったとき。読むだけの表示から、書ける表示にする
- 記事 (note) の制作でも同じ要望が出たとき。置き場と形を、発表と揃えて決め直す
