# ADR-0038: 絵コンテの画面を絵コンテだけにし、作品の段階の中に置く。AI との接点は画面ではなくファイルにする

- ステータス: 承認 (画面の構成と依頼文のボタンは → ADR-0040 で置き換え。AI との接点をファイルに置くことは継続)
- 日付: 2026-10-13
- スコープ: apps/studio

## 文脈

KomeKaigi 2026 の絵コンテを、studio を使いながら 2 日かけて作った。次のことが分かった。

- 発表資料の編集画面 (ADR-0030) は、左に絵コンテのボード、右にプレビューとチャットを置いている。読む・観る・話すの 3 つの仕事が 1 画面に同居し、右の 44% が常に取られる。フィードバックの経緯 (ADR-0037) を足すと、ボードがさらに縦に伸びた
- この 2 日間、studio のチャットは 1 度も使われなかった。やり取りはすべてターミナルの Claude Code で行い、studio は見る場所としてだけ働いた
- 状態を縦に積む並べ方では、シーンの中で絵がどう変わるかが読み取りにくい
- studio には入口が 2 つある。段階の画面を持つ「作品」(ADR-0036。段階 1〜4 まで) と、絵コンテの編集画面を持つ「トーク」(ADR-0030) である。KomeKaigi は両方に別々に存在し、つながっていない

話者の要望は次のとおり。全体を絵コンテの表示だけにしてよい。プレビューと AI との対話は、この画面から外す。フィードバックは各スライドに紐づく形で分かるようにする。AI へのフィードバックは全スライド分まとめてでよい。入口は統合したい。slide:ology の思想に合う、新しいスライドの作り方を体現した道具にしたい。声を入れて動画にする、Claude in Chrome に画面を操作させる、という先の可能性も視野に入れる。

## 選択肢

**画面の構成**

- A 案: いまの 2 カラムのまま、プレビューとチャットを折りたためるようにする。作りは小さい。主役が絵コンテだという構図は変わらず、折りたたみの操作が増える
- B 案: 絵コンテだけの画面にする。本物の絵コンテと同じ 4 段 (コマ・動きの指示・台詞・メモ) でコマを作り、状態を横に並べる。動きを見たいときだけ、その場で大きく再生する。通しで見るのは別窓の再生と発表者ビューに任せる

**AI との接点**

- A 案: studio のチャットを残す (常設か、サイドシート)。画面の中で完結する。この 2 日間は使われなかった
- B 案: 画面の操作を Claude in Chrome に任せ、ブラウザの操作で入力させる。絵コンテも経緯もファイルなので、書く仕事はファイルを直すほうが速くて確かである。ブラウザの操作が活きるのは、描画された画面を見て講評する側である
- C 案: 接点をファイルに置く。話者はコマに書き込み、書いたものは feedback.yaml に「未対応」で溜まる。拾うのは、ターミナルの Claude Code でも、あとから足すサイドシートでも、Claude in Chrome でもよい

**入口**

- A 案: 作品とトークを別のまま、互いにリンクだけ張る
- B 案: 作品を 1 本の流れにし、絵コンテの画面を作品の段階 6〜8 (構成を決める・スライドを作る・見直す) の画面にする

## 決定

画面は B 案、AI との接点は C 案、入口は B 案を採る。

- 発表資料の編集画面を、絵コンテだけの画面にする。状態を横に並べたコマにし、コマは上から絵・画面の説明と動きの役割・話すこと・フィードバックの 4 段で作る。表示は、コマだけを敷き詰める「通し」と、台詞まで出す「精読」を切り替える。コマを押すと、その遷移をその場で大きく再生する
- 常設のプレビューとチャットを外す。話者はコマにフィードバックを書き込み、feedback.yaml に「未対応」で入る (ADR-0037 の形に `state` と状態「未対応」を足す)。未対応の件は、まとめて Claude Code に渡す。渡し方の最初の形は、依頼文をコピーしてターミナルに貼ることにする
- 作品の企画シート (brief.yaml) に、トークの slug を持たせる。作品の段階 5〜8 から絵コンテの画面に移り、絵コンテの画面の上には、作品の「伝えたいこと」と「聴衆」を出し続ける (slide:ology p.36-37, p.39)
- 声の録音とリハーサルの記録、動画の書き出しは、あとの段で扱う。音声はリポジトリの外に置く

## 根拠

確信度は中。主役が絵コンテであることは、2 日間の使い方が示している。接点をファイルに置けば、どの AI のクライアントを使うかを、いま決めずに済む。画面の操作がすべてファイルの操作に対応していれば、Claude in Chrome をあとから足すのも難しくない。段階の画面 (ADR-0036) と絵コンテの画面は、slide:ology の制作プロセス (メッセージ → ビジュアルストーリー → デリバリーを巡る。p.31) の前半と後半に当たり、1 本の流れとして扱うのが本の考え方に合う。

確信度を下げている前提は 3 つある。状態が 5 つを超えるシーンは横に長くなり、読みにくくなるかもしれない。依頼文をターミナルに貼る渡し方は、手数が 1 つ多い。記事 (note) の側は、まだ同じ形にしていない。

## 見直しの条件

- 絵コンテの画面を見ながら AI と話したい場面が続いたとき。サイドシートを足す (studio のサーバ側の会話の仕組みは残してある)
- 横に並べたコマが読みにくいと分かったとき。折り返しの幅や、縦の並べ方を選べるようにする
- 記事 (note) の原稿でも同じ往復をしたくなったとき。コマを段落に置き換えて、同じ形にする

## 置き換えるもの

ADR-0030 の「絵コンテのボードを見ながら Claude とチャットして作る」のうち、チャットとプレビューを常設する部分を、この ADR で置き換える。絵コンテのボードで見る・話すことをその場で直す、という部分は引き継ぐ。
