# ADR-0039: 聴衆役の読みを studio の機能にする。ペルソナは「人」と「場」に分けてプリセットを持ち、アンケートで答えてもらう

- ステータス: 承認 (実装済み。読み手の選び方の画面は未実装)
- 日付: 2026-10-13
- スコープ: apps/studio / .claude/skills/crafting-presentation / .claude/skills/writing-note

## 文脈

KomeKaigi 2026 の絵コンテを、4 人の聴衆役 (AI が演じるペルソナ) に 3 周読ませて直した。話者は、事前に想定した聴衆からフィードバックがもらえる体験を良いと感じ、次のことを求めた。

- 直すたびに聴衆から感想をもらえる仕組みにしたい。note でも同じ仕組みを使いたい
- 毎回ペルソナを細かく設定するのは大変なので、プリセットを多く持ちたい。10 人、20 人と増やしてよい。話者のファン／話者を知らない人、技術がまったく分からない人、のような切り口も欲しい。コストを気にして縮こまった設計にしない
- 点数のような定量的な評価も欲しい。理解しやすく、やる気も出る。項目は多すぎず、ちゃんとしたフィードバックになるものを、資料と Web の調査から決める
- 場面へのピンポイントな感想を絵コンテの画面で見て、自分もコメントを入れ、それをもとに Claude Code に直してもらう

調査は `apps/studio/docs/research/audience-survey.md` にある。slide:ology に採点表は無い。材料は、聴衆を知る 7 つの問い (p.35)、制作プロセスの「検証」の項目 (p.31)、同僚に見せる助言の工程 (p.54)、うまくいったかの見分け方 (p.269) の 4 つである。これまでの 3 周では、「10 点満点で」とだけ聞いた点数は 6〜7 点から動かず、何が足りないのかを示さなかった。

## 選択肢

**ペルソナの持ち方**

- A 案: 作品ごとに毎回書く (いまの形)。その作品に合うが、手間がかかり、発表と記事で欄が違う
- B 案: 1 人を「人」と「場」に分ける。人 (どんな人か・悩み・知っていること・反発しやすい点) はプリセットとして使い回す。場 (なぜこの発表・記事を選んだか、どうなってほしいか) は作品ごとに 2〜3 行足す

**答えてもらい方**

- A 案: 自由な感想だけ (1 周目の形)。中身は濃いが、回をまたいで比べられない
- B 案: 総合の点数を 1 つ (2・3 周目の形)。比べられるが、どこが弱いかが分からない
- C 案: 項目を分けたアンケート (5 段階と理由 1 行) に、自由記述 2 つと、コマへの感想を足す

**読ませる時機**

- A 案: 絵コンテを直すたびに自動で読ませる
- B 案: 話者が「読んでもらう」を押したときに読ませる

## 決定

ペルソナは B 案、答えてもらい方は C 案、時機は B 案を採る。

- プリセットのペルソナ (人) をリポジトリに置く。一般的な人物像なので公開してよい。実在の人をもとにしたものは、リポジトリの外に置く。最初は KomeKaigi の 4 人を入れ、立場の幅 (経験の年数、技術への距離、話者を知っているか) を広げながら増やす。作品では、プリセットから読み手を選び、場の文脈を足す
- アンケートは 8 項目にする。届いたか (得に来たものを得られた／悩みに触れていた／新しい見方を得た)、分かったか (筋を追えた／画面はひと目で分かった)、動くか (主張に納得した／明日やってみようと思うことがある)、総合 (同じ立場の人に勧めたい)。5 段階で、項目ごとに理由を 1 行もらう。自由記述は「いちばん伝えたかったことは何だと思ったか」と「ここがこうなっていたら」の 2 つ。コマへの感想は、シーン id と状態の番号を付けて、種類 (分からない言葉／話が飛んだ／読み切れない／納得できない／良かった) と一緒にもらう
- 絵コンテの画面に「読んでもらう」を置く。読み手は毎回まっさらにし、絵コンテの画面と話すことだけを渡す (crafting-presentation の聴衆役と同じ)。回ごとの結果を残し、項目ごとの推移を見せる。コマへの感想は feedback.yaml に入り、コマの下に出る
- 集計では、「直せば済むこと」と「話者の材料や判断が要ること」を分けて出す
- 画面には「聴衆役の読み」と明記する。人に見せた反応や当日の反応も、同じ形で入れられるようにする

## 根拠

確信度は中。7 つの問いは聴衆を描くための欄なので、裏返すと聞き終えたあとの質問になる。ペルソナのシートがそのまま採点の基準になり、発表と記事で同じ形を使える。項目を分けるのは、口頭発表の評価表が内容・構成・聴衆との相互作用・デリバリーに分けて 5 段階で採点していること、カンファレンスの実務が「観点ごとに分ける・項目は少なく・持ち帰ったものを聞く」を勧めていることによる。自動にしないのは、1 周に数分かかり、言葉を 1 つ直すたびに走ると読む量が増えるためである。費用を理由に読み手を絞ることはしない。

確信度を下げている前提は 2 つある。聴衆役は本物の聴衆ではない。同じモデルが演じるので、4 人の指摘は 8 割がた重なった。点を上げることが目的になると、演じている側に合わせた資料になる。もう 1 つは、聴衆が自分の体験を答えるアンケートで、妥当性を確かめたものが見つかっていないことである。項目は、使いながら直す。

## 見直しの条件

- 項目の点が回をまたいで動かない、または直した実感と合わないとき。項目を入れ替える
- 当日の反応と、聴衆役の読みが大きく食い違ったとき。読ませ方 (渡すもの・ペルソナの書き方) を見直す
- 読み手を増やしても新しい指摘が出なくなったとき。立場の違いを広げる方向で、プリセットを足す
