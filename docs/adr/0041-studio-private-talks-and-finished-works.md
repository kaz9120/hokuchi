# ADR-0041: studio は公開リポジトリの外のトークも扱い、作品に「終わった」を持たせる

- ステータス: 承認 (作品の「終わった」は → ADR-0043 で置き換え)
- 日付: 2026-10-19
- スコープ: apps/studio / apps/slides (開発サーバ)

## 文脈

2026-10-19 の社内勉強会の発表は、社内向けなので `~/Hobby/hokuchi-private/talks/` に置いた (ADR-0029)。作ってみると、studio では次の 2 つが起きた。

- studio が読むトークは、リポジトリの `talks/` だけだった。社内向けのトークは企画シートの `talk` に紐づけられず、流れ・コマ・読みのタブも使えなかった。絵コンテの確認は Markdown のままになった
- 作品に終わりが無かった。企画シート (`works/*/brief.yaml`) は、発表日が過ぎても公開しても、ずっと「作っているもの」に並ぶ

話者の理想は、「サイトには載せないが、studio では管理できる」ことだった。

## 選択肢

**社内向けのトークの置き場**

- A 案: 社内向けのトークもリポジトリの `talks/` に置き、`.gitignore` で外す。置き場は 1 つで済むが、誤って追跡に入れると GitHub に出る。ADR-0029 の「リポジトリの外に置く」とも食い違う
- B 案: 置き場は外 (`<HOKUCHI_PRIVATE>/talks/`) のまま、studio が両方を読む。サイトの組み立て (`apps/slides/build.mjs`) は今までどおり `talks/` だけを読む

**作品の終わり**

- A 案: 発表日が過ぎたら、自動で終わったものに移す。手間は無いが、登壇後にノートを直す・公開するといった作業が残っていても移ってしまう
- B 案: 話者が「終わった」を押す。企画シートに `doneAt` (押した日時) を残す。押し直せば作っているものに戻る

## 決定

置き場は B 案、終わりは B 案を採る。

- studio は、`talks/` と `<HOKUCHI_PRIVATE>/talks/` の両方からトークを読む。外のトークも、企画シートの `talk` で作品に紐づけ、流れ・コマ・読みのタブで扱える。studio の中で立てるサイト全体の開発サーバ (5280) には、外のトークも非公開の印付きで出る
- サイトの組み立ては、`talks/` だけを読む。外のトークは、`public: true` と書いても載らない
- 作品の画面で「終わった」を押すと、企画シートに `doneAt` を書く。ホームでは「作っているもの」から外し、「終わったもの」に並べる。終わったもののカードには、公開か社内向けかと、発表日を出す。「終わった」を取り消せば、作っているものに戻る

## 根拠

- 社内向けの資料が公開リポジトリに入る道を、置き場の段階で断つ方が安全である。`.gitignore` は、ファイル名の付け方 1 つで外れる (確信度: 高)
- 登壇のあとにも、ノートの仕上げ (ADR-0033) や公開の作業が残る。作業が済んだかどうかは話者が知っているので、押してもらう方が実態に合う (確信度: 中)

## 見直しの条件

- 終わったものが増えて、ホームの一覧が長くなったとき。年ごとに畳む・検索するなどを考える
- 「終わった」を押し忘れて、作っているものが溜まり続けるとき。発表日を過ぎた作品に「終わりましたか」と促す

## 影響

- `apps/slides/site-server.mjs` の `startSite` が、読み込むトークの置き場を追加で受け取れるようにする。studio はここに `<HOKUCHI_PRIVATE>/talks/` を渡す。`bun run dev` は今までどおり `talks/` だけを読む
- 企画シートに `doneAt` を足す。`apps/studio/docs/design.md` のホームと作品の画面の記述を更新する
- 2026-10-19 の社内勉強会の作品に、トークを紐づけて終わったものにする
