# ADR-0042: 発表用の画面と公開用の画面を分け、公開用ではノートの代わりにテキストと PDF を渡す

- ステータス: 承認
- 日付: 2026-10-19
- スコープ: packages/stage / apps/slides / .claude/skills/crafting-presentation

## 文脈

再生機の画面は 1 つで、キーでモードを切り替えていた。ライブ再生・ノートを読むモード (`n`)・発表者ビュー (`p`)・一覧 (`o`)・全画面 (`f`) である。slides.y-kaz.com で公開したトークでも、すべて使えた。ADR-0027 は、話者なしで読む閲覧者のために、ノートを読むモードを用意すると決めていた。

話者から、次の指摘があった。

- 公開した資料の閲覧者に、発表者ビューやノートは要らない。資料が読めれば良い
- 一方で、資料を AI に取り込んで内容を読みたい読者もいる。口頭で補足した内容まで含めて、整理したテキストでコピーできると良い
- 社内向けの発表では、ファイルで共有するために PDF が必要になった (2026-10-19)。HTML と PDF の書き出しだけでも、まず喜ばれる
- 発表用の画面と公開用の画面を、はっきり分けたい

## 選択肢

**画面の分け方**

- A 案: 1 つの画面のまま、公開版ではキーの一部を隠す。作りは小さいが、何が誰向けかが曖昧なまま残る
- B 案: 発表用と公開用の 2 つの画面にする。どちらになるかは、ビルドの種類で決める。開発サーバと studio は発表用、サイトの組み立てと単一 HTML は公開用

**口頭の補足の渡し方**

- A 案: ノートを読むモードを残す (ADR-0027)。人は読めるが、AI に渡すには 1 状態ずつ写すことになる
- B 案: ノートを画面から外し、トーク全体を 1 つのテキストにまとめて渡す。画面に出た文字と話したことを、状態の順に並べる
- C 案: ノートを公開しない。AI に渡したい読者の要望に応えられない

**書き出し**

- A 案: テキストだけ
- B 案: テキストと PDF。PDF は 1 状態を 1 ページにする

## 決定

画面は B 案、補足は B 案、書き出しは B 案を採る。

- 発表用の画面は、今の再生機のままにする。ライブ再生・発表者ビュー・ノート・一覧・全画面を使う。開発サーバ (`bun run dev`)・studio・`single --present` がこの画面を出す
- 公開用の画面は、資料を読むことだけに絞る。ステージと、その下の細い帯を置く。帯には、前へ・位置・次へ・一覧・全画面・「テキストをコピー」・「PDF」を並べる。発表者ビューとノートは出さない。サイトの組み立て (`build`) と単一 HTML (`single`) がこの画面を出す
- テキストは、ビルドのときに作る。トークの情報 (演題・登壇者・イベント・日付・URL・概要) のあとに、シーンごとに「画面」と「話したこと」を状態の順に並べる。「画面」は、その状態で新しく出た文字だけにする (前の状態と同じ文字を繰り返さない)。ブランド枠の文字は入れない。Markdown にし、サイトでは `/<slug>/talk.md` に置く。「テキストをコピー」は、この全文をクリップボードに入れる
- PDF も、ビルドのときに作る。全状態の静止画を 1 状態 1 ページで並べる。サイトでは `/<slug>/<slug>.pdf` に置く。単一 HTML では、PDF をファイルの隣に書き出す
- ノートは、テキストの中で公開される。そのため、公開前にノートを公開物として仕上げる手順 (ADR-0033) は、そのまま残す

## 根拠

- 閲覧者は、発表者のための道具 (時計・次の状態・話すことの全文) を使わない。読む画面に要らない操作があると、どれが自分向けかを探させる (確信度: 中)
- AI に読ませる読者にとって、状態ごとに分かれたノートを集める手間が、いちばん大きい。1 つのテキストにまとめれば、そのまま貼れる (確信度: 中)
- 「画面」を新しく出た文字だけにするのは、同じ見出しや数字が状態の数だけ繰り返され、AI にも人にも読みにくくなるためである (確信度: 中)
- PDF は、ADR-0027 で「動きが失われる」としてやめた。ただし共有の手段としては、社内でもまだ必要とされている。主役は Web のまま、PDF を副産物として添える (確信度: 高)

## 見直しの条件

- ノートを人の目で読む閲覧者が多いと分かったとき。公開用の画面に、ノートを開く操作を戻す
- テキストの形が、AI に渡したときに誤読されやすいと分かったとき。「画面」と「話したこと」の書き方を見直す
- PDF のファイルサイズが大きすぎて、共有に困るとき

## 影響

- ADR-0027 の「話者なしで読む閲覧者のために、ノートを読むモードを用意する」を、この ADR で置き換える
- 再生機に、発表用と公開用の 2 つの画面を持たせる。どちらにするかは、ビルドのときに決める
- `build` と `single` が、テキストと PDF を書き出す。`single` に、発表用の画面を書き出す `--present` を足す
- `packages/stage/docs/design.md` の画面とキー操作の記述を、2 つの画面に分けて書き直す。crafting-presentation の公開の手順に、テキストと PDF を確かめることを足す
