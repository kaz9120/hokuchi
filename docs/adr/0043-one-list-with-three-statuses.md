# ADR-0043: studio のホームは、発表と記事を 1 つの一覧にし、下書き・非公開・公開の 3 つの状態で見せる

- ステータス: 承認
- 日付: 2026-10-19
- スコープ: apps/studio

## 文脈

ADR-0041 で、作品に「終わった」(`doneAt`) を持たせ、ホームに「終わったもの」を足した。実際の画面を見た話者の評価は、次のとおりだった。

- 「作っているもの」「終わったもの」「公開したもの」が別々に並び、同じ種類のものが 3 か所に分かれて見える。公開した発表は、「終わったもの」と「公開したもの」の両方に出る
- まずは、記事と発表資料を、下書きも含めて全部 1 つの一覧で扱いたい。カードは今の形でよい
- 状態は「下書き・非公開・公開」くらいでよい。非公開はリポジトリで管理しない。非公開から公開には変えられるが、公開から戻すことはできない
- 状態の管理は複雑にしたくない

## 選択肢

**状態の持ち方**

- A 案: 企画シートに 3 つの状態をすべて書く。画面のボタンで切り替える。書いた状態と実物 (サイトに載っているか・note に出ているか) がずれることがある
- B 案: 公開は実物から決める。サイトに載っている発表と、note のアーカイブにある記事が公開である。企画シートには、非公開にしたことだけを書く (`status: private`)。どちらでもなければ下書きである

**状態の移り方**

- A 案: どの状態にも行き来できる
- B 案: 下書き → 非公開 → 公開の一方通行にする。下書きから直接公開にもなる。戻す操作は置かない

## 決定

持ち方は B 案、移り方は B 案を採る。ADR-0041 の `doneAt` と「終わったもの」は、これで置き換える。

- ホームの一覧は 1 つにする。企画シートのある作品と、企画シートの無い公開物 (アーカイブの note の記事・サイトに載っている発表) を同じ一覧に並べる。企画シートが公開物に紐づいていれば、1 枚にまとめる
- カードに、状態 (下書き・非公開・公開) と種類 (発表・記事) を出す。カードの形は今のものを使う。下書きは「次にやること」を言うカード、公開は表紙の絵のあるカードである
- 並びは、下書きを上に、そのあとに非公開と公開を日付の新しい順に置く。種類と状態で絞り込み、タイトルで探せるようにする
- 作品の画面で「非公開で終える」を押すと、企画シートに `status: private` を書く。非公開のトークは、リポジトリの外 (`<HOKUCHI_PRIVATE>/talks/`) に置く
- 非公開から公開にするときは、トークをリポジトリの `talks/` に移し、`public: true` にしてデプロイする。手作業とデプロイの確認が要るので、画面には「Claude Code に頼む」案内だけを置く。公開すると、状態は実物から公開になる
- 公開から戻す操作は置かない。一度サイトや note に出たものは、リポジトリの履歴や検索に残るためである

## 根拠

- 公開かどうかを実物から決めれば、書いた状態と実物がずれない。人が覚えておく状態は「非公開にした」の 1 つだけになる (確信度: 高)
- 一方通行にすると、ボタンは 1 つで済む。戻せないことは、話者が決めたルールそのものである (確信度: 高)
- 「終わった」は、話者の頭の中の区分 (下書き・非公開・公開) と合っていなかった。区分を話者の言葉に揃える (確信度: 中)

## 見直しの条件

- 一覧が長くなり、下書きが埋もれるとき。下書きだけを上に固定する・年で畳むなどを考える
- 非公開の作品を、あとから下書きに戻したい場面が繰り返し出るとき

## 影響

- ADR-0041 の「作品に終わりを持たせる」(`doneAt` と「終わったもの」) を置き換える。外のトークを studio で扱う部分は、そのまま残す
- ADR-0040 のホームの 3 区分 (作っているもの・ネタ帳・公開したもの) のうち、作っているものと公開したものを 1 つの一覧にする。ネタ帳は残す
- `apps/studio/docs/design.md` のホームと作品の画面の記述を書き直す
