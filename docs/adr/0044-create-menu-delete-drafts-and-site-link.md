# ADR-0044: 作成は 1 つのボタンにまとめ、下書きは削除できるようにし、「サイトを開く」は本番を開く

- ステータス: 承認
- 日付: 2026-10-19
- スコープ: apps/studio

## 文脈

ADR-0043 で作り直したホームを見た話者から、3 つの指摘があった。

- 「発表を作成」と「記事を作成」が横に並び、記事の方だけがプライマリーの見た目になっている。2 つに優劣は無く、並んでいると押し間違えそう
- 下書きを削除できない。下書きのうちは、消したいことがありそう
- 「サイトを開く」で、非公開のスライドも見えている。サーバに上がっていないかが気になる

3 つ目は、実際には上がっていない。「サイトを開く」が開くのは studio の中で立てたローカルの開発サーバで、ADR-0034 で非公開のトークにも印を付けて一覧に出すと決めていた。公開の組み立てが読むのは `talks/` の `public: true` だけである。それでも、話者に「上がっているかも」と思わせる時点で、画面として失敗している。

## 選択肢

**作成のボタン**

- A 案: 2 つのボタンを同じ見た目 (どちらも枠線) にする。優劣は消えるが、押し間違いは残る
- B 案: 「作成」のボタン 1 つにし、押すと「発表」「記事」を選ぶメニューを開く。一般的な Web サービスの新規作成と同じ形

**下書きの削除**

- A 案: 企画シートと、紐づくファイルを消す。戻せない
- B 案: 企画シートと、リポジトリの外に置いた紐づくトークを、`<HOKUCHI_PRIVATE>/trash/` に移す。リポジトリの中のファイル (公開予定のトーク・記事の原稿) には触らず、消すなら Claude Code に頼むよう案内する

**「サイトを開く」**

- A 案: ローカルの開発サーバの一覧から、非公開のトークを外す
- B 案: 本番 (`https://slides.y-kaz.com/`) を開く。ローカルの開発サーバは、作品の画面のプレビューと `bun run dev` で使う

## 決定

作成は B 案、削除は B 案、「サイトを開く」は B 案を採る。

- ホームの右上は「作成」のボタン 1 つにする。押すと「発表」「記事」を選ぶ
- 削除できるのは下書きだけにする。非公開と公開は削除できない (ADR-0043 の一方通行と揃える)。削除は確認を挟み、企画シートとリポジトリの外のトークを `<HOKUCHI_PRIVATE>/trash/<日時>-<id>/` に移す。リポジトリの中のファイルが紐づいているときは、それは残すことと、消すなら Claude Code に頼むことを確認の中で伝える
- ホームの「サイトを開く」は、本番のサイトを開く。サイトに載っているものだけが見える

## 根拠

- 新規作成をメニューにまとめる形は、多くの Web サービスで見慣れている。種類を選ぶ一手が増えるが、押し間違いが無くなる (確信度: 高)
- 削除をごみ箱への移動にすれば、間違って消しても戻せる。リポジトリの中のファイルは git の操作が要るので、画面からは触らない (確信度: 高)
- 「サイトを開く」は、話者にとって「世の中から見えている姿」を見る操作である。ローカルの一覧を見せると、公開と非公開の境目が分からなくなる (確信度: 中)

## 見直しの条件

- ごみ箱が溜まって困るとき。空にする操作を足す
- 公開前のサイト全体を、studio から頻繁に確かめたくなったとき。ローカルの開発サーバを開く操作を、別の名前で足す

## 影響

- ADR-0034 のローカルの開発サーバの一覧はそのまま残す (`bun run dev` で使う)。studio のホームからは開かない
- `apps/studio/docs/design.md` のホームと作品の画面の記述を更新する
