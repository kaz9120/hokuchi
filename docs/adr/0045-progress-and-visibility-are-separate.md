# ADR-0045: 作品の状態を、進み具合 (下書き・完成) と公開範囲 (非公開・公開) の 2 つの軸に分ける

- ステータス: 承認
- 日付: 2026-10-19
- スコープ: apps/studio

## 文脈

ADR-0043 で、作品の状態を「下書き・非公開・公開」の 1 本にした。下書きの作品の画面には「非公開にする」のボタンを置いた。使ってみた話者の評価は、次のとおりだった。

> 下書きから正式版にするときに「非公開にする」というボタンなのは違和感かもしれません。多分、下書き → 正式版 と 非公開 → 公開 の状態しかないですよね。二つの状態を混ぜて管理している印象がありました。

下書きの作品も、まだどこにも出していないので非公開である。「非公開にする」は、すでに非公開のものを非公開にする操作に読める。押したときに起きていたのは「作り終えた」ことの記録で、公開範囲は何も変わっていなかった。

## 選択肢

- A 案: 1 本の状態のまま、ボタンの言葉だけ変える (「完成にする」など)。押すと状態が「非公開」になり、言葉と状態の名前が食い違う
- B 案: 2 つの軸に分ける。進み具合は「下書き → 完成」で、話者が決める。公開範囲は「非公開 → 公開」で、実物から決める (ADR-0043 と同じ)

## 決定

B 案を採る。

- 進み具合: 下書きと完成の 2 つ。作品の画面の「完成にする」で完成になり、企画シートに `finishedAt` (押した日時) を書く。「下書きに戻す」で戻せる。完成しても、編集は今までどおりできる
- 公開範囲: 非公開と公開の 2 つ。公開は実物から決める (サイトに載る発表、note のアーカイブにある記事)。それ以外は非公開。公開から非公開には戻せない (ADR-0043)。非公開の作品は、リポジトリの外に置く (ADR-0041)
- 公開した作品は、完成として扱う。「下書きに戻す」は出さない
- 削除できるのは、下書きだけにする (ADR-0044)
- ホームのカードと作品の画面には、2 つの軸をそれぞれのバッジで出す。絞り込みも、進み具合 (すべて・下書き・完成) と公開範囲 (すべて・非公開・公開) に分ける
- 作品の画面の右上には、進み具合の操作 (下書き: 「完成にする」と「削除」、完成: 「下書きに戻す」) と、公開範囲の操作 (完成した非公開の作品: 「公開の手順」) を置く
- ADR-0043 の企画シートの `status: private` は使わない。いま `status: private` を持つ作品は無い

## 根拠

- 話者の頭の中にある区分は、「できたか」と「出したか」の 2 つだった。画面の状態を、その区分に揃える (確信度: 高)
- 2 つの軸のうち、話者が書き込むのは進み具合だけである。公開範囲は実物から決まるので、ずれない。覚えておく状態の数は、ADR-0043 と変わらない (確信度: 高)
- 進み具合は戻せる方が自然である。登壇の直前に直す、記事を改稿するといった場面がある。戻せないのは、世の中に出したもの (公開) だけである (確信度: 中)

## 見直しの条件

- 完成と公開のあいだに、別の段階 (レビュー待ち・予約公開など) が要るようになったとき
- 「完成」の言葉が、話者の使う言葉 (「正式版」など) と合わないと分かったとき

## 影響

- ADR-0043 の状態の持ち方 (3 つの状態と `status: private`) を、この ADR で置き換える。1 つの一覧・並び・カードの形は、そのまま残す
- `apps/studio/docs/design.md` の作品の状態とホームの記述を書き直す
