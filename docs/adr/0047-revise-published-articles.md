# ADR-0047: 公開済みの記事は、原稿に写して原稿タブで直し、note を更新してから取り込み直す

- ステータス: 承認
- 日付: 2026-10-19
- スコープ: apps/studio / tools/notes

## 文脈

ADR-0046 で、記事の原稿を `<HOKUCHI_PRIVATE>/notes/<slug>/` に置き、studio の原稿タブで直せるようにした。公開済みの記事を開くと、読むだけの画面 (NoteView) になり、「改稿する」は押せないままだった。話者は、公開済みの記事も原稿タブで直したいと考えている (2026-10-19)。

公開済みの記事の `index.md` は、note の原本 (`source.json`) から作る生成物である (ADR-0019)。ここを直しても note の記事は変わらず、次の `sync` で上書きされる。

## 選択肢

- A 案: アーカイブの `index.md` を、studio から直接直せるようにする。ADR-0019 の「生成物は手で直さない」と食い違い、note との食い違いが残る
- B 案: 「改稿する」で、公開済みの本文を原稿に写す。原稿タブで直し、note に貼り直して更新する。`sync` で取り込み直すと、アーカイブが新しい本文になる

## 決定

B 案を採る。

- 公開済みの記事の画面の「改稿する」で、アーカイブの `index.md` (frontmatter と本文) と `assets/` を `<HOKUCHI_PRIVATE>/notes/<slug>/` に写す。企画シートが無ければ作り、`note` に slug を書いて紐づける。写したら、原稿タブで開く
- 原稿タブ・読み・指摘は、下書きと同じものを使う。原稿には、どの記事の改稿かを frontmatter (`revises: <アーカイブのディレクトリ名>`) で残す
- 直したら、公開タブで note に貼る形でコピーし、話者が note の記事を更新する。そのあと `sync` で取り込み直すよう、Claude Code に頼む。取り込みが済んだら、原稿は trash に移す
- 改稿中の記事も、公開範囲は公開のままである (実物から決まる)。進み具合は、改稿の原稿があるあいだは下書きとして見せる

## 根拠

- 原本を note に置いたままにすれば、アーカイブと note が食い違わない。ADR-0019 の 2 層をそのまま使える (確信度: 高)
- 改稿も下書きと同じ原稿タブで扱えば、読み・指摘の仕組みが公開済みの記事にも効く。話者が覚える使い方も増えない (確信度: 高)

## 見直しの条件

- note の API で記事を更新できるようになり、貼り直しの手間を省けるとき
- 改稿の途中で、同じ記事を `sync` で取り込むことが多く、原稿とアーカイブが食い違うとき

## 影響

- NoteView の「改稿する」を有効にする
- ADR-0045 の「公開したものは完成として扱う」に、例外を 1 つ足す。改稿の原稿があるあいだは、進み具合を下書きとして見せる
