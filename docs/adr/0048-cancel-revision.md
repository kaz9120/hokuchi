# ADR-0048: 公開済みの記事の改稿は、画面からやめられるようにする

- ステータス: 承認
- 日付: 2026-10-19
- スコープ: apps/studio

## 文脈

ADR-0047 で、公開済みの記事を原稿に写して直せるようにした。改稿を終える道は、note の記事を更新して `sync` で取り込み直す 1 つだけだった。話者が既存の記事を改稿して聴衆役に読んでもらったあと、「完成の状態に戻すにはどうしたら良いか」と聞いた。note を更新せずに、直したものを捨てたい場面がある。話者は「まさに必要な機能」と言った (2026-10-19)。

## 選択肢

- A 案: 改稿をやめるときも、Claude Code に原稿の片付けを頼む。画面の操作は増えないが、話者が自分で終えられない
- B 案: 作品の画面に「改稿をやめる」を置く。改稿の原稿だけを trash に移し、企画シートとアーカイブは残す

## 決定

B 案を採る。改稿中の記事の作品の画面の右上に「改稿をやめる」を置く。確認を挟み、改稿の原稿を `<HOKUCHI_PRIVATE>/trash/<日時>-revise-<slug>/` に移す。企画シート・note の記事・アーカイブは変えない。原稿が無くなると、進み具合は完成 (公開) に戻る。

## 根拠

- 始めた操作 (改稿する) は、同じ画面でやめられる方が迷わない (確信度: 高)
- 原稿は消さずに trash に移すので、間違えても戻せる。企画シートを残せば、指摘や読みの記録の紐づけも残る (確信度: 中)

## 見直しの条件

- 改稿をやめたあと、同じ記事を改稿し直すときに、前の改稿の原稿を引き継ぎたくなったとき

## 影響

- `apps/studio/docs/design.md` の改稿の節に、やめ方を足した
