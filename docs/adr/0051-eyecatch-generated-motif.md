# ADR-0051: note の見出し画像の下地は、nano banana に描かせたモチーフを、作り直した暗い紙に置いて作る

- ステータス: 提案
- 日付: 2026-10-29
- スコープ: tools/eyecatch / skills

## 文脈

note の見出し画像は Unsplash から記事に合いそうな写真を選び、hidoko の note-ogp でタイトル・号数・日付を入れて作っていた。写真は記事ごとに選ぶ手間がかかり、連載として並べたときの統一感も出しにくい。

話者は写真を手描きの絵本のような絵に描き直す画像生成のプロンプトを見て、その画風で見出し画像の下地を作りたいと考えた (2026-10-28)。使う画像生成は nano banana で、Antigravity CLI (`agy`) の `image-generator` から呼べることを確かめた。

試作で次のことが分かった。

- 明るい紙に描かせると、note-ogp はタイトルの領域が明るいと判断し、ハロ (黒縁の白文字) を付ける。暗い紙なら、ハロもスクリムも付かないオフ白の文字になる。話者は暗い紙を選んだ
- 位置を言葉や数値で指定しても、モチーフは画面の中ほどに寄る。並べたときに動きが出ない
- 紙の色が 1 枚ごとにぶれる (6 枚で `#2a251f`〜`#413933`)。並べると、位置のずれより目立つ
- 頼んでいない枠線・窓・人物が足されることがある

## 選択肢

- A 案: 生成のまま使う。プロンプトで位置と紙の色を指定し、外れたら作り直す。道具は要らないが、位置と紙の色は揃わない
- B 案: hokuchi に CLI を置く。モチーフを正方形の中央に描かせ、切り出して、作り直した紙の指定位置に置く。位置と紙の色は確実に揃う。位置は人が決める
- C 案: note-ogp が切り出したモチーフを配置する。タイトルの位置と一緒に決められ、重なりを避けられる。note-ogp の設計を変えることになる

## 決定

B 案を採る。`tools/eyecatch` に CLI `hokuchi-eyecatch` を置く。`prompt` と `generate` は場面と季節の光だけを差し込む固定のプロンプトで、モチーフを暗い紙の正方形の中央に描かせる。`place` は生成画像からモチーフを切り出し、紙の色を揃え、インクの量で大きさを揃えて、1280×670 の作り直した紙の指定位置に置く。`sheet` は見出し画像を 3 列に並べた見本を作る。タイトル・号数・日付はこれまでどおり note-ogp で入れる。モチーフの選び方は writing-note skill の `references/eyecatch.md` に書く。

## 根拠

- 生成に位置を指定すると、指定が増えて絵の質がばらつく。描かせるのはモチーフだけにして、位置は決定的な処理で決める方が、絵の質と位置の両方を保てる (確信度: 高。6 枚で確かめた)
- 紙を作り直してモチーフだけを載せれば、境目は出ず、紙の色も 1 つに揃う (確信度: 中。等倍の目視で確かめたが、粒は乱数で作っているので生成画像の紙より少しデジタルのノイズに近い)
- note-ogp の「H1 静けさ」は空いている面へタイトルを自動で置くので、位置と組みを組にして選ばなくてもよい (確信度: 中。話者の運用の見立て)
- C 案は全記事を作り直す中で、note-ogp に移す価値があるかを見てから決めればよい (確信度: 中)

## 見直しの条件

- タイトルとモチーフが重なり、note-ogp の組みで避けきれない回が続いたとき (C 案を再訪する)
- nano banana が位置の指定を守るようになり、切り出しが要らなくなったとき
- `agy` が保存先の指定を聞くようになったとき、または `image-generator` が無くなったとき (`generate` を直す)

## 影響

- ルートの bun ワークスペースに `tools/eyecatch` を加えた。依存は sharp。`bun run eyecatch` と `bun run test:eyecatch` を足した
- `tools/eyecatch/docs/design.md` を生きた設計書として置いた
- writing-note skill の Phase 7 の見出し画像の手順を、この CLI を使う形に書き換えた
- 色は `BRAND.md` と hidoko の `tokens.css` から取る。紙の色だけは生成画像の実測に合わせた `#2c2721` で、トークンの段階には無い
