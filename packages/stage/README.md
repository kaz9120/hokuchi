# packages/stage

発表資料をシーン×状態の React コードで書くためのフレームワークです。再生機・部品・テーマと、トーク単位の CLI を持ちます。シーンの書き方は crafting-presentation skill の `references/build-scenes.md` にあります。

## 考え方

発表は 1 枚ずつのスナップショットの連続ではなく、シーンが移り変わる映画として作ります (slide:ology p.212)。

- シーンは 1 つの画面空間です。中の要素は役者として状態をまたいで生き続け、クリックごとに移動・変形・強調されます。シーンが変わるときは画面が横にパンし、ブランド枠はパンの外に置きます
- 動きは関係性の変化・画面の演出・オブジェクトの変化・連続性・強調の 5 つの役割のどれかを果たすときだけ付けます (p.205)
- フレームワークが持つのは再生と部品だけです。どこに何を置くか、どんな図にするかは、シーンを書く側が毎回決めます。部品は出発点で、使う義務はありません。表現の上限を語彙で決めないためです
- 状態遷移で起きる崩れ (見出しの重なり・縮む箱の中の歪み・折り返しの飛び) は、部品が吸収します。シーンの側で対処しません
- 色はテーマのトークンで書きます。テーマを差し替えても構図が崩れないためです。和文は Web フォントに固定します。閲覧環境で字幅が変わると、手で置いた構図が崩れるためです
- 立ち上がりが鋭い緩急は「速い」と感じられるので使いません

## 見せ方と配信

- 動きは閲覧者が体験して初めて届くので、配信の主役は Web です。各トークを `https://slides.y-kaz.com/<slug>/` に置きます。PDF は副産物として添えるだけです
- 画面は登壇する話者のための発表用 (ノート・発表者ビューつき) と、資料を読む人のための公開用の 2 つです。公開用には AI に読ませる人のためのテキスト全文 (`talk.md`) と PDF を付けます
- OGP 画像は表紙の静止画そのものにします。表紙と OGP で構図を 2 つ持たないためです
- 公開済みの資料を凍結しません。公開のたびに全トークを最新のフレームワークでビルドし、前回と見た目が変わった状態があれば止まります
- 公開用のビルドには、全状態に出てくる文字だけを切り出したフォントを同梱します。会場がオフラインでも字形が変わりません
- agentation は開発サーバのライブ再生にだけ出します。PolyForm Shield のコードを公開物に同梱しないためです

## CLI

```sh
bun run dev                    # サイト全体の開発サーバ (http://localhost:5280/)
bun run dev <talk>             # トーク 1 本の作業用サーバ。<talk> は名前の先頭だけでもよい
bun run check <talk>           # 全状態の静止画と検査 → out/check.md
bun run check <talk> --motion  # 遷移のコマ撮りも出す → out/motion/
bun run build <talk>           # 公開用 → out/build/
bun run single <talk>          # 1 つの HTML と PDF (公開用の画面。--present で発表用)
bun run typecheck
```

`check` は、文字の箱の重なり・ステージからのはみ出し・18px 未満の文字を機械で探し、絵コンテとの食い違いを照合します。線と文字の重なり、構図の釣り合い、動きの自然さは、静止画とコマ撮りを目で見て確かめます。

開発サーバでは、`?theme=<名前>` でテーマを差し替え、`?public` で公開用の画面を確かめられます。URL のハッシュ `#/<scene-id>/<step>` で状態を直接開けます。
