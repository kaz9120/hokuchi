# tools/notes

note.com の記事を取り込んでアーカイブし、原稿の文体を検査し、note に貼る形を作る CLI です。依存はありません。

`tools/notes` で一度 `npm link` すると `hokuchi-note` で使えます。無ければリポジトリのルートから `node tools/notes/cli.mjs <サブコマンド>` で同じように動きます。テストは `npm test` (変換規則の回帰とアーカイブ全体の検査) です。

| コマンド | すること | ネットワーク |
|---|---|---|
| `sync` | 一覧取得 → 記事取得 → 画像取得 → build → verify → index | 使う |
| `build [dir...]` | `source.json` から `index.md` を作り直す | 使わない |
| `verify [dir...]` | 取り込みの忠実さを検査する。欠落があれば終了コード 1 | 使わない |
| `lint [原稿...]` | 原稿の文体を検査する。引数を省くと公開済み記事全部 | 使わない |
| `paste <原稿>` | 原稿を note に貼れる形にしてクリップボードへ。`--stdout` で標準出力 | 使わない |
| `index` | `articles/note/README.md` を作り直す | 使わない |

## アーカイブ

```
articles/note/
  slugs.json            note key → slug。ディレクトリ名の唯一の真実
  <公開日>-<slug>/
    source.json         原本。note API の不変フィールドを凍結したもの
    index.md            読む用。source.json から生成する
    assets/             見出し画像と本文画像
```

- 真実は `source.json`・`assets/`・`slugs.json` です。`index.md` と `README.md` は生成物なので、手で直しません。直したいときは変換規則を直して `build` を回します。変換規則を変えても、原本があるので記事は失われません
- `index.md` に、`source.json` に無い情報を足しません
- `index.md` の本文は note のエディタにそのまま貼れる Markdown にします。埋め込みは URL だけの 1 行で、貼るとカードになります
- 記事を足したら `sync` を回します。`slugs.json` に無い記事は key のままのディレクトリに作られるので、slug を足して再実行すると引っ越します

## 検査の考え方

- `verify` は取り込みが忠実かを見ます。パーサを通さず原本の HTML を直接数えます。パーサと検査が同じ勘違いをして、揃って通ることを避けるためです。要素があるかだけでなく、順序・出現回数・リンクのラベルと URL の組まで見ます
- `lint` は文章が研ぎ澄まされているかを見ます。閾値は公開済み記事の実測から引き、公開済みが error を出さず、warn が改善の余地として出る位置に置きます。公開済みが error を出すなら、閾値の方が間違っています。記事が増えたら測り直します
- 濃いかどうか、フックが効いているかは lint では測れません。人が読んで決めます

## note に貼る

note のエディタは Markdown を貼ると見出しや強調を解釈します。ただ、画像行 `![alt](path)` が 1 つでも混ざると、本文全体が素のテキストとして入ります (実測)。そこで `paste` は画像行を「（画像 2/5: ファイル名 ｜ キャプション: …）」の 1 行に置き換えます。note 側でこの行を消し、その位置に画像を入れます。原稿の側は `![alt](assets/…)` のままにします。

公開前の原稿は `~/Hobby/hokuchi-private/notes/<slug>/` に置き、studio の記事の画面で直します。公開済みの記事は studio の「改稿する」で原稿に写して直し、note を更新したら `sync` で取り込み直します。
