# layout-engine spike 実装ノート (ADR-0014)

> 2026-07-08: 検証を終え、本実装を `src/render.mjs` に移植済み。このディレクトリは
> 検証記録として凍結する。§2 の持ち越し事項も本実装に反映した (measure は
> `measureXxx(el, ctx, avail)` の形で制約を受け取る)。

捨てる前提の試作。measure/compose 2 パスレイアウトを diagram-stage (flow.cycle) と
chart-stage (trend) の 2 枚だけで貫通させ、構図の before/after を検証した。
カード・チャートの視覚言語 (色・線・タイポ) は現行 render.mjs から流用し、
差分が構図だけになるようにしてある。

使い方は `node build.mjs` → `node ../../cli.mjs shot out/before` / `shot out/after`。

## 1. spike で決めた導出ルール (本実装のインプット)

数値はすべてレンダラ内部の実装詳細。スキーマ・テーマ・SPEC には出さない (ADR-0014)。

### 縦予算

- 外周マージンは 96×64 のみ。レターボックス (旧 `stage_margin`) という概念を持たない。
  余白は compose が配分した結果として現れる
- before の主役の箱 1088×288 (3.78:1) が、after では 1088×508 まで回復する

### compose

- headline の帯は `heading × 1.3`、headline と主役の間は 40px
- 主役の箱は fitAspect: 中身が申告した理想アスペクトで最大内接
- 使い残した高さは上:下 = 45:55 (光学中心)。今回の 2 枚は中身が高さを
  使い切るのでほぼ効いていない。statement など背の低い中身で効く想定

### measure — 中身の申告値

- flow.cycle: 箱の理想アスペクト 1.1 (カードが横長なぶん、わずかに横広が釣り合う)。
  環はカード寸法を引いた内接楕円とし、小さい方の半径を基準に大きい方の超過を
  15% までに制限 → ほぼ正円になり、ノードは正多角形の頂点に載る。
  before の rx/ry ≈ 5.09 が after では 1.0〜1.15 に収まる
- trend チャート: プロット領域の理想 2:1。軸ラベルの pad (l84 r60 t26 b64) は
  定数なので、pad 込みの箱アスペクトに換算してから申告する。
  before のプロット 944×198 (4.78:1) が after では 836×418 (2.0:1) になる

### チャート注釈の置き場所

ラベルは折れ線が空けている側に置く。隣の点が高い側は線が上へ逃げるので下が空く。
右下 (読み方向) を優先、次に左下、両方塞がっていれば上。固定オフセット (旧: 常に右下)
だと下降トレンドの右側でラベルが線を横切る。

## 2. 気付き・本実装への持ち越し

- アスペクト交渉と縦予算の回復だけで、2 枚とも構図の印象が大きく変わる。
  コンポーネント自体 (カード・線・注釈の描き方) は流用でも効果が出た。
  構図とコンポーネントは独立に改善できる
- fitAspect は「理想値ぴったり」しか実装していない。min/max の許容幅
  (例: trend は 1.6〜2.4 まで許して幅を使い切る) は本実装で検討
- measure が CANVAS/MARGIN を知っている箇所がある (trend の箱換算)。
  本実装では「制約を渡されてから答える」形に直す (measure(constraints) → 申告)
- 光学中心 45:55 は今回未検証。statement-stage / quote-stage で確かめる
- ブランド枠は content グループのみ流用した簡易版。本実装では現行の
  brandFrame をそのまま使う
- cycle の環に沿う弧エッジ (ringArcEdge) は正円に近づくとより自然に見える。
  歩行ロジックは現行のまま流用できた
